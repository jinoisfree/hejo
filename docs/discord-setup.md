# 디스코드 연결 방법

hejo의 방을 휴대폰(안드로이드 포함)에서 디스코드로 보고 쓸 수 있게 연결하는 순서다.
hejo가 원본이고 디스코드는 보조 창이다. 동작 계약은 [gate/README.md](../gate/README.md#디스코드-보조-창)를 따른다.

연결하면 디스코드 서버에 hejo 방마다 포럼 채널이 하나씩 만들어진다. 앱이 배치를 보내면 사이드바 섹션별 분류에서 방을 찾을 수 있다.
포럼 글 하나가 hejo 스레드 하나다. **채널은 손으로 만들지 않는다.** 손으로 만든 채널은 hejo 방과
이어지지 않고, hejo가 같은 이름의 채널을 따로 만든다.

## 준비물

- hejo 서버가 설치된 Mac(Hermes가 도는 Mac)과 디스코드 기능이 있는 hejo 앱
- 디스코드 계정

## 1. 디스코드 서버 만들기

1. 디스코드 왼쪽 세로줄의 **＋(서버 추가하기)** → **직접 만들기** → **나와 친구들을 위한 서버**.
2. 이름을 정하고 **만들기**.

## 2. 커뮤니티 켜기

포럼 채널은 커뮤니티 서버에서만 만들 수 있다.

1. 서버 이름 옆 **∨** → **서버 설정** → **커뮤니티 활성화** → **시작하기**.
2. 필수 항목(이메일 인증 등, 미디어 콘텐츠 필터)을 체크하고, 규칙·업데이트 채널은 기본값으로 **완료**.

## 3. 봇 만들기

1. <https://discord.com/developers/applications> 에서 **New Application** → 이름(예: `hejo`) → **Create**.
   디스코드의 "입력 중" 표시는 이 이름으로 나온다.
2. 왼쪽 **Bot** 메뉴:
   - **Message Content Intent**를 켜고 **Save Changes**.
   - **Reset Token** → 나온 토큰을 복사해 둔다. 복사한 뒤 Reset Token을 다시 누르면 앞의 토큰은 무효가 된다.
     토큰은 채팅·문서에 붙여 넣지 않는다.

## 4. 봇을 서버에 초대

1. 같은 페이지 왼쪽 **OAuth2** → **URL Generator**.
2. **SCOPES**에서 `bot`만 체크.
3. **봇 권한**에서 아래 10개만 체크한다. 관리자와 음성 권한은 체크하지 않는다.

   | 일반 권한 | 채팅 권한 |
   |---|---|
   | 채널 관리 | 메시지 보내기 |
   | 웹후크 관리 | 공개 스레드 만들기 |
   | 채널 보기 | 스레드에서 메시지 보내기 |
   | | 스레드 관리 |
   | | 링크 임베드 |
   | | 파일 첨부 |
   | | 메시지 기록 보기 |

4. 맨 아래 생성된 주소를 복사해 새 탭에서 열고, 1에서 만든 서버를 골라 **승인**.
   서버 멤버 목록에 봇이 보이면 된다.

## 5. 서버 Mac에 토큰 넣기

서버 Mac 터미널(zsh)에서 아래 한 줄을 그대로 실행한다. `새 토큰 붙여넣고 Enter:`가 뜨면 토큰을
붙여 넣고 Enter를 누른다(화면에 보이지 않는 것이 정상). 기존 줄이 있으면 바꾸고, 길이와 점 개수만 보여 준다.

```zsh
read -rs "T?새 토큰 붙여넣고 Enter: " && sed -i '' '/^DISCORD_BOT_TOKEN=/d' ~/.hermes/.env && printf 'DISCORD_BOT_TOKEN=%s\n' "$T" >> ~/.hermes/.env && echo " 저장됨 (길이 ${#T}, 점 $(tr -cd . <<< "$T" | wc -c | tr -d ' ')개)" && unset T
```

봇 토큰은 보통 **길이 70 안팎, 점 2개**다. 점이 없거나 길이가 30 안팎이면 Client Secret 같은 다른 값을
복사한 것이니 3부터 다시 한다.

**디스코드 허용 값은 넣지 않는다.** `DISCORD_ALLOWED_USERS`·`DISCORD_ALLOWED_ROLES`·허용 채널·홈 채널,
`GATEWAY_ALLOW_ALL_USERS` 같은 값이 있으면 Hermes가 디스코드 글을 직접 받게 되고, hejo는 그 글을 기록하지
않고 앱에 "Hermes 디스코드 허용이 열려 있음"을 알린다(닫힘 운영). 확인은 값을 보이지 않게 이름만 본다.

```zsh
grep -E '^(DISCORD_|GATEWAY_ALLOW)' ~/.hermes/.env | cut -d= -f1
```

`DISCORD_BOT_TOKEN` 한 줄만 나와야 한다.

## 6. 디스코드 의존성 설치와 재시작

Hermes 공식 방법으로 discord.py를 설치하고 게이트웨이를 재시작한다.

```zsh
hermes pm install --extra discord
hermes gateway restart
```

재시작하면 진행 중이던 대화 하나가 끊길 수 있다. 게이트웨이 로그에 `discord connected`가 보이면 된다.
`Improper token has been passed`가 보이면 토큰이 틀린 것이다 — 3에서 새 토큰을 받아 5부터 다시 한다.

## 7. 짝짓기와 켜기

**재시작 직후 몇 분은 기다린다.** 봇이 처음 접속하면 Hermes가 디스코드에 슬래시 명령을 등록하는데,
그동안 짝짓기·켜기를 하면 채널 만들기가 디스코드 속도 제한에 걸려 실패할 수 있다. 게이트웨이 로그에
`Safely reconciled … slash command(s)` 또는 `Skipping Discord slash command sync`가 보인 뒤 진행한다.

1. hejo 앱 **설정 → 연결과 동기화 → 디스코드**. 상태가 "연결 안 됨"이어야 한다
   ("Hermes 디스코드 허용이 열려 있음"이면 5의 허용 값을 지운다).
2. **연결 코드 받기** → 코드 복사(10분 유효).
3. 디스코드 서버의 `#일반` 채널에 코드만 보낸다. 봇이 "연결됐어요"라고 답하고 앱 상태가 **연결됨**이 된다.
4. 앱에서 **디스코드 연결 켜기**를 체크한다.
5. 앱이 배치를 보내기 전에는 `hejo` 분류에 포럼 채널이 생긴다. 앱 배치가 도착하면 섹션별 분류로 옮겨지고, 고정하지 않은 1:1 방은 앱의 DM 묶음 분류에 모인다. 분류에 50개가 차면 넘치는 방은 자리가 있는 동안 `hejo`에 배치된다.

디스코드 속도 제한에 걸리면 문이 대기한 뒤 다시 시도한다. 채널이 하나도 생기지 않고 앱 상태가 "채널 권한 문제"로 남으면, 4의 권한을 확인한 뒤 `hermes gateway restart`로 다시 시도한다.

## 쓰는 법

- **새 질문:** 그 방 채널에서 새 포스트를 만든다. 디스코드 포럼은 새 포스트에 제목이 필수다.
  hejo는 제목과 본문을 합쳐 한 글로 받으므로 짧은 질문은 제목에 쓰면 된다.
- **이어서 말하기:** 포스트 안에서 답글을 쓴다. 제목이 필요 없다.
- hejo 앱에서 쓴 글과 직원 답은 같은 방 채널의 포스트로 보인다(직원 이름으로 표시).
- 섹션 이름과 순서를 바꾸거나 방을 옮기면 디스코드에도 반영된다. 채널은 분류 안에서 이름순으로 보인다. 섹션을 삭제하면 대응 분류는 채널이 비었을 때 정리된다.
- 방 이름을 바꾸면 채널 이름도 바뀌고, 보관하면 채널이 `hejo 보관` 분류로 옮겨진다.
- `#일반` 같은 방 채널이 아닌 곳에 쓴 글은 hejo에 올라가지 않고 안내만 받는다.
- 서버가 꺼져 있던 동안 디스코드에 쓴 글은 나중에 들여오지 않는다.

## 끊기

- 잠시 끄기: 앱에서 **디스코드 연결 켜기**를 끈다.
- 연결 해제: 앱에서 **연결 해제**. 디스코드 채널은 그대로 남는다.
- 봇 자체를 끄기: `~/.hermes/.env`에서 `DISCORD_BOT_TOKEN` 줄을 지우고 `hermes gateway restart`.
