## 문제
처리할 일 칸이 대화 창 밖 왼쪽에 대화 창 색을 불투명하게 칠한 판으로 붙는다. 대화 창 나머지는 반투명 유리라 칸만 검게 떨어져 보이고, 방 목록과 채팅 사이 흐름도 끊긴다(사장 스크린샷, 0.2.5).

## 목표
칸이 대화 창 안에서 **방 목록 | 할 일 | 채팅 | (웹 칸)** 순서로 열리고, 방 목록과 같은 바탕 결로 보인다.

## 범위
- 안: 칸 위치, 창 넓이·자리 옮김, 좁은 화면 처리, 칸 바탕과 카드 색, 옛 배치 경로(창 밖·덮기·덮개) 제거, 관련 시험 교체.
- 밖: 칸 내용·묶음·문장, 마감 요청 주기, 알약(`IslandModel`) 동작, 칸 너비 290, 공개·버전.

## 요구

### REQ-DI-01 칸은 방 목록과 채팅 사이에 열린다
- AC-01(정상): 채팅을 펼친 채 칸을 열면 대화 창 안 가로 순서가 방 목록 → 칸(290pt) → 채팅 칸 → (열려 있으면) 웹 칸이다. 칸은 대화 보기의 맨 위부터 맨 아래까지 차지하고, 채팅 칸의 머리(알약·방 제목)·글 목록·입력 줄은 모두 칸 오른쪽 끝부터 시작한다.
- AC-02(정상): 칸이 열린 동안 방 목록 너비(접힘 68 / 펼침 212 / 숨김 0)를 바꿔도 순서와 칸 너비는 그대로이고 채팅 칸이 그만큼 옮겨진다.
- AC-03(정상): 칸과 채팅 칸은 겹치지 않는다. 칸 위를 덮는 막(덮개)은 없다.

### REQ-DI-02 열면 창이 오른쪽으로 넓어진다
- AC-01(정상): 오른쪽에 자리가 있으면, 열 때 창의 왼쪽 끝(방 목록의 화면 x)은 그대로이고 창 폭만 290 늘어난다. 채팅 칸의 폭은 그대로이며 화면 x가 290 오른쪽으로 옮겨진다. 웹 칸이 열려 있으면 웹 칸도 폭 그대로 290 오른쪽으로 옮겨진다. 펫 위치는 그대로다.
- AC-02(정상): 닫으면 창 프레임·펫 위치가 열기 전과 같아진다.
- AC-03(정상): 여닫는 움직임은 0.25초다. 움직이는 동안 채팅 칸은 칸이 드러난 폭만큼만 옮겨지고 칸과 겹치지 않는다. 칸 안 카드는 290 폭으로 배치된 채 잘려 보일 뿐 다시 줄바꿈되지 않는다. "동작 줄이기"가 켜져 있으면 바로 바뀐다.
- AC-04(경계, 2판): 칸이 드러난 폭은 창 폭 변화와 별개로 여닫기 시작 때의 값에서 목표 값(열기 290, 닫기 0)까지 창과 같은 완화 곡선으로 연속해서 바뀐다. 좁은 화면(REQ-DI-04)에서 창 폭 변화가 290보다 작아도 열기 시작은 0, 닫기 시작은 290이며 중간에 건너뛰지 않는다. 움직이는 도중 다시 누르면 그때의 값에서 새 목표로 이어진다.

### REQ-DI-03 오른쪽 끝에 자리가 모자라면 창 전체가 왼쪽으로 비킨다
- AC-01(정상): 넓어진 창의 오른쪽 끝이 화면 가시 영역 오른쪽 12pt 여백을 넘으면, 넘는 만큼만 창과 펫을 함께 왼쪽으로 옮긴다. 이때 창 폭은 290 늘어나고 채팅 칸 폭은 그대로다.
- AC-02(정상): 닫으면 창과 펫은 옮기기 전 자리로 돌아간다. 저장된 펫 위치(`petX`·`petY`)는 열고 닫는 동안 바뀌지 않는다.
- AC-03(경계): 오른쪽 끝이 여백과 정확히 같으면 옮기지 않는다.

### REQ-DI-04 화면이 좁으면 채팅을 좁혀 끼운다
- AC-01(경계): 왼쪽으로 비켜도 넓어진 창이 가시 영역(양쪽 12pt 여백) 안에 들어가지 않으면, 창은 가시 영역 폭을 넘지 않고 칸은 290 그대로이며 채팅 칸이 모자란 만큼 좁아진다. 덮기·어둡게 하는 막은 없다.
- AC-02(경계): 웹 칸이 열려 있으면 폭 나누기는 기존 웹 칸 규칙(`PetLayout.paneSplit`: 채팅이 자기 폭을 지키다가 남은 폭이 360 미만이면 채팅이 최소 폭까지 양보)을 칸 290을 뺀 화면 폭으로 적용한다. 웹 칸이 열려도 할 일 칸 상태는 바뀌지 않고, 웹 칸을 열고 닫아도 할 일 칸은 열린 채다.
- AC-03(정상): 칸을 닫으면 채팅 칸 폭은 좁히기 전 값으로 돌아간다. 칸이 열린 동안의 좁힘은 저장된 채팅 크기(`chatWidth`)를 바꾸지 않는다.
- AC-04(정상, 2판): 칸이 열린 동안 채팅 크기 조절은 **기존 크기 조절 규칙을 그대로** 따른다. 기준 상자는 칸을 뺀 상자(열린 창에서 오른쪽 290을 뺀 상자, 같은 `minX`, 펫과 함께 옮겨진 위치)이고, 기존 규칙(화면 여유가 있으면 펫 중심 기준 양쪽으로 늘어남: 오른쪽 끝을 `dx` 끌면 폭 +2·`dx`)이 이 상자에 적용된다. 저장 `chatWidth`는 이 상자의 결과 폭이며 칸 폭이 섞이지 않는다.

### REQ-DI-05 칸 바탕과 카드 색이 방 목록과 같은 결이다
- AC-01(정상): 칸은 불투명 판을 칠하지 않는다. 대화 창 유리·덮개가 그대로 비치고, 그 위에 방 목록과 같은 옅은 바탕(`SidebarTone.primary`, 어둡게 0.035 / 밝게 0.025)을 칠한다. 칸 오른쪽 끝에 방 목록 경계선과 같은 1px 선(`SidebarTone.primary(0.1)`)을 둔다.
- AC-02(정상): 대화 창 투명도 설정을 바꾸면 칸 영역도 채팅 영역과 같은 정도로 함께 바뀐다(칸만 따로 불투명하지 않다).
- AC-03(정상): 선택된 카드는 굵은 강조색 테두리 대신 방 목록 선택 행과 같은 채움(강조색, 어둡게 0.22 / 밝게 0.12, 모서리 10)으로 보인다.
- AC-04(정상): 급한 카드(답 요청, D-DAY·지남 마감)는 배지 글자만 빨강이고 카드 테두리·바탕은 다른 카드와 같은 옅은 회색이다. 나머지 카드도 같은 옅은 회색 테두리다.
- AC-05(정상): 어둡게·밝게 테마 전환 때 칸 바탕·선·카드 색이 함께 다시 그려진다.

### REQ-DI-06 옛 배치 경로를 없앤다
- AC-01: 창 밖 왼쪽 배치(`leading`·`withLeading`), 덮기 판정(`drawerOverlay`), 덮개(`TodoDrawerScrim`·`drawerScrim`), 칸 불투명 배경(`TodoDrawerView.backgroundColor`·`PetView.updateScrim`의 칸 색 설정)이 코드에서 사라진다. 칸은 `ConversationView`의 하위 보기로만 있고 `PetView`에 따로 꽂히지 않는다.
- AC-02(회귀): 유지되는 동작 — 알약 사장 칸·빈 알약 클릭으로 여닫기(AT-TD-27·41), Esc·"‹ 접기"로 닫기, 채팅 칸 클릭으로는 닫히지 않음, 카드 클릭 이동(AT-TD-25·39와 HEJO-DEADLINE-CLOSE 대체분), 열림 저장(REQ-TD-06), 채팅 접으면 칸 숨김과 마감 요청 중지(NFR-TD-03, AT-TD-37·42), 채팅 끌기 뒤 다시 판정, 세 손가락 탭, 웹 칸 시험.

### REQ-DI-07 로고와 버전이 방 목록 칸 가운데에 있다 (3판 추가, 사장 요청 2026-11-23)
- 현황: [확인] 로고 "HEJO."와 버전 글자는 방 목록 열 폭(`x:0, width:left`) 라벨에 `alignment = .center`를 주지만, 로고는 색을 입힌 `attributedStringValue`라 문단 정렬이 없어 왼쪽으로 쏠려 보인다(`ConversationView.swift:134-137,694`, 사장 스크린샷 2장). [가정] 원인은 attributed string의 문단 정렬 누락이며 구현 담당이 확인한다.
- AC-01(정상): 로고 글자와 버전 글자는 방 목록 열(폭 `S`) 안에서 가로 가운데에 그려진다. 접힘 68, 펼침 212, 끌어서 바꾼 폭 모두 같다.
- AC-02(정상): 방 목록 폭을 바꾸면 바로 새 폭의 가운데로 옮겨진다(할 일 칸 열림·닫힘과 무관).
