# HEJO-OWNER-PROFILE 명세 (2판, 2026-11-25, 계획 검증 1회차 반영)

결정 근거: [brainstorm.md](brainstorm.md), 시안 [mock-chat.png](mock-chat.png)·[mock-profile.png](mock-profile.png). 기준 커밋: 공개판 `github/main`(착수 시 고정, handoff 0절). ID 접두어 `OP`.

## 문제
사장은 앱·텔레그램·디스코드·직원 대화에서 이름이 "사장"이나 "나"로 고정되고 사진이 없다. 앱 채팅에서 내 글에는 이름·사진이 없고, 에이전트 글은 짧은 답글만 말풍선이고 긴 글·첫 글·스트리밍 글은 말풍선 없이 펼쳐져 모양이 섞인다.

## 목표
사장이 이름과 사진을 한 번 정하면, 그 사장의 문에 연결된 모든 기기의 앱 화면, 텔레그램·디스코드 거울 글, 직원이 받는 대화 맥락에 같은 이름이 쓰인다. 채팅의 모든 글은 같은 모양의 말풍선에 들어가며 색과 좌우만 다르다.

## 범위
- 안: 문(`gate/`)의 사장 프로필 저장·HTTP·wire 알림, 텔레그램·디스코드 표기, 직원 대화 맥락과 Hermes 사용자 이름, 앱의 내 프로필 설정·채팅 그리기·"나" 표기, 계약 문서(`schemas/hejo-wire-v1.json`, `schemas/pictures.md`).
- 밖: 서버 설치·운영 문 교체(별도 작업, 운영 줄 차이 때문), 허브(`hub/`) 계정 이름, 말풍선 색 설정, 직원에게 표·코드 작성 규칙 주기, 기록 검색의 내부 검색어(`gate/history_queries.py` `words`), 홈 방 스레드 머리(`HomeOwnerView`, 받는 직원 표시라 범위 밖), 개발 `main`.

## 용어
- **사장 이름**: 앞뒤 공백을 뺀 1~20자(유니코드 문자 단위) 문자열. 줄바꿈·제어 문자(유니코드 일반 범주 C*)를 넣을 수 없다. 없으면 "설정 안 됨".
- **표시 이름**: 사장 이름이 있으면 그 값, 없으면 앱·텔레그램·디스코드에서 `사장`, 직원 대화 맥락·버튼 결정 문구에서는 지금처럼 `나`.
- **사장 사진**: 직원 사진과 같은 규칙의 PNG(앱이 PNG로 바꿔 올림, 512 KiB 이하, 기존 `valid_png` 통과).
- **사장 프로필 알림**: 문이 앱에 보내는 `owner` 객체 `{"name": string|null, "avatar": string|null}`. `avatar`는 사진 주소(`/v1/pictures/owner/owner?v=<mtime_ns>`) 또는 null.

## 요구와 수락 기준

### REQ-OP-01 사장 프로필 저장(문)
- AC-01 (정상) Given 인증된 기기, When `PUT /v1/owner {"name":"길동"}`, Then 200 `{"ok":true,"owner":{"name":"길동","avatar":…}}`이고 `<HOME>/shared/hejo/owner.json`에 이름이 남으며 파일은 0600이다. 문을 다시 시작해도 같은 값이 읽힌다.
  - 폴더 권한: `shared/hejo`가 없으면 0700으로 만든다. 이미 있으면 그 권한을 바꾸지 않는다(기록장·첨부·텔레그램 등이 함께 쓰는 폴더이며 이름은 비밀값이 아니므로 파일 0600으로 충분하다). 사장 사진 폴더 `shared/hejo/pictures`는 방 사진과 같이 0700으로 맞춘다.
- AC-02 (경계) 앞뒤 공백은 지워 저장한다. `{"name":null}`·`{"name":""}`·공백만이면 이름을 지운다(설정 안 됨, 200).
- AC-03 (실패) 21자 이상, 줄바꿈·제어 문자, 문자열·null이 아닌 값, JSON이 아닌 본문이면 400 `invalid_name`이고 저장된 값은 바뀌지 않는다.
- AC-04 (실패) 출입증 없음·다른 회원 출입증이면 401이고 저장된 값은 바뀌지 않는다.
- AC-05 (정상) `PUT /v1/pictures/owner/owner`(PNG)는 `<HOME>/shared/hejo/pictures/owner.png`(0600)에 저장되고 `GET`으로 같은 바이트를 받는다. `DELETE`는 지운다. `owner` 종류의 다른 id는 404다. 잘못된 PNG·크기 초과는 직원 사진과 같은 오류다.
- AC-06 (실패) 저장 파일이 깨졌거나(JSON 아님·형식 위반) 심볼릭 링크면 문은 "설정 안 됨"으로 읽고 시작·연결을 막지 않는다. 다음 정상 `PUT`이 원자적으로 덮어쓴다.

### REQ-OP-02 사장 프로필 알림(wire)
- AC-01 welcome 프레임에 `owner` 객체가 들어 있다(설정 안 됨이면 `{"name":null,"avatar":null}`).
- AC-02 이름 `PUT`이나 사장 사진 `PUT`·`DELETE`가 성공하면 연결된 모든 기기에 `{"type":"roster","ref":"owner",…,"owner":{…}}`가 간다. 기존 `roster` 프레임(앱의 명단 요청에 대한 응답, 직원 사진 변경 알림)에도 그 시점의 `owner`가 들어 있다.
- AC-03 `schemas/hejo-wire-v1.json`의 welcome·roster 정의에 `owner`가 있고 문 시험이 실제 프레임(welcome, 명단 요청 응답, 세 종류 변경 알림)을 이 스키마로 검사해 통과한다.
- AC-04 (앱, 하위 호환) `owner`가 없는 welcome은 "설정 안 됨"으로 받는다. `owner`가 없는 roster는 이미 받은 사장 프로필을 바꾸지 않는다(지우지 않는다).

### REQ-OP-03 문 밖 표기
- AC-01 사장 이름이 있을 때 텔레그램·디스코드로 가는 사장 글의 표기(`[사장] …`, 디스코드 표기)가 그 이름으로 바뀐다. 없으면 `사장` 그대로다.
- AC-02 사장 이름이 있을 때 직원이 받는 대화 맥락 줄(`conversation_lines`: 스레드 맥락·방 놓친 글)의 사장 줄이 `<이름>: …`이다. 없으면 `나: …` 그대로다.
- AC-03 사장 이름이 있을 때 문이 사장 글을 Hermes에 넘기는 출처(`gate/adapter.py`의 사장 글 처리, 기준 커밋 762행 `build_source`)의 `user_name`이 그 이름이다. 없으면 `user_name`을 넣지 않는다(지금과 같음). `user_id`·세션 키·스레드는 바뀌지 않는다.
- AC-04 버튼 결정 문구(`gate/buttons.py` `decision`의 `user`)는 이름이 있으면 그 이름, 없으면 `나`다.
- AC-05 이름 변경은 다음에 보내는 글부터 적용된다. 이미 보낸 텔레그램·디스코드 글과 기록장의 글은 고치지 않는다.

### REQ-OP-04 내 프로필 설정(앱)
- AC-01 설정 창에 "내 프로필" 영역이 있고 사진 미리보기(사진 없으면 표시 이름 첫 글자 아바타), "사진 고르기…", "사진 지우기", 이름 입력, 저장, 안내 문구("비우면 '사장'으로 보여요", "직원 대화와 텔레그램·디스코드에도 이 이름이 쓰여요")가 있다.
- AC-02 채팅에서 내 사진을 우클릭하면 "내 프로필…" 메뉴가 있고 고르면 위 영역이 열린다.
- AC-03 설정 화면에서 유효한 사진을 고르고 이름을 저장하면, 저장한 앱과 같은 문에 연결된 다른 앱 모두에서 다시 연결하지 않아도 내 글 머리줄 이름과 아바타에 그려지는 실제 사진이 바뀐다. 사진을 다른 사진으로 다시 바꾸면 두 앱 모두 새 사진이 그려지고 이전 사진이 남지 않는다. 사진을 지우면 두 앱 모두 글자 아바타로 돌아간다.
- AC-04 문이 거절하면(400·401·연결 끊김) 입력은 그대로 남고 이유를 알리는 문구가 보이며 화면의 이름·사진은 바뀌지 않는다. 사진 오류 문구는 직원 사진과 같다.
- AC-05 문에 연결되지 않았으면 저장·사진 버튼을 누를 수 없다.

### REQ-OP-05 채팅 말풍선 통일(앱)
- AC-01 직원 글은 첫 글·답글·이어 쓴 글·스트리밍 중 글·첨부가 있는 글·긴 글(240자·4줄 초과, 제목·목록·인용·표·코드 포함)을 가리지 않고 본문이 회색 반투명 말풍선 안에 그려진다. 색은 지금 짧은 답글 말풍선 색(카드 스타일의 `replyBackground`, 없으면 글자색 7%)이다.
- AC-02 표와 코드 블록은 말풍선 안쪽 폭을 넘지 않는다. 표 칸 글과 긴 코드 줄은 줄바꿈하며, 원문 모든 문자(코드 줄의 마지막 문자 포함)가 잘리거나 생략되지 않고 배치된다. 표·코드에 가로 스크롤(가로 스크롤 막대, 안쪽 폭보다 넓은 스크롤 내용)이 없다. 말풍선 폭의 최대값은 지금 카드의 말풍선 최대 폭(`bubbleWidth`)이다.
- AC-03 내 말풍선과 직원 말풍선은 모서리 반지름과 안쪽 여백이 같다(한 상수). 내 말풍선 색은 지금 사용자 말풍선 색(`UserBubblePalette`) 그대로다.
- AC-04 첨부 미리보기, 선택 버튼, "관련 …" 같은 칩, 이전 답글 묶음, 답하는 중·생각 중 줄, "끼어들었어요"는 말풍선 밖(아래)에 그대로 있다. "더 보기/접기"는 본문 바로 아래 말풍선 안에 있다.
- AC-05 직원 글 머리줄은 지금처럼 왼쪽 `[사진] 이름 시간`이다.

### REQ-OP-06 내 글 머리줄(앱)
- AC-01 내 글 위 머리줄은 오른쪽 끝에서 안쪽으로 `[사진] 이름 시간` 순서다. 즉 화면에서 왼→오 `시간 이름 [사진]`이고, 사진은 직원 사진과 같은 크기(34pt)·모양, 이름은 표시 이름이다.
- AC-02 같은 스레드에서 바로 앞에 보이는 글도 내 글이면(직원 글 이어 쓰기와 같은 규칙) 머리줄과 사진을 생략한다.
- AC-03 보내는 중이면 시간 자리에 "보내는 중"이 보인다. "답이 중단됐어요"는 말풍선 아래에 그대로 있다. 말풍선 아래의 시간 줄은 없어진다.
- AC-04 사진이 없으면 표시 이름 첫 글자와 이름에서 정한 색의 아바타다(직원과 같은 `ProfileAvatar` 규칙).
- AC-05 채팅 모양 미리보기(설정의 말풍선 미리보기)도 같은 머리줄·모양으로 그린다.

### REQ-OP-07 앱 안 "나" 표기
- AC-01 검색 결과의 화자, 스레드 복사 글(`ThreadTools`), 작업 공간 보기의 화자(`WorkspaceViews`)에서 사장 글은 표시 이름이다(설정 안 됨이면 `사장`).

## 비기능
- NFR-OP-01 개인값: 시험·문서·코드 예시에 실제 이름·계정·경로를 넣지 않는다. 시험은 임시 `HERMES_HOME`과 가짜 이름만 쓴다.
- NFR-OP-02 하위 호환: `owner`가 없는 옛 문에 새 앱이 붙어도, 새 문에 옛 앱이 붙어도 연결·대화가 된다.
- NFR-OP-03 그리기 성능: 기존 성능 하네스(있으면 `HejoSmoothProbe` 계열)의 기준 대비 새 실패가 없다. 수치 목표는 정하지 않는다(근거 없음).
