# HEJO-FINDER-FOLDERS 브레인스토밍 결정 요약

2026-11-21 · 진행 방식: 연합개발(계획 검증 켜기)

## 요청
1. "처리할 일의 카드를 클릭해도 해당 스레드로 이동하지 않는 문제가 있다."
2. "시놀로지 드라이브를 연결하는 것보다는, 파인더로 시놀로지 폴더를 관리하게 하는 건 어때? 어차피 시놀로지 클라이언트 설치랑 로그인 등은 내가 하고, 그럼 공유 폴더처럼 접근 가능하니까 에이전트가 그 공유 폴더의 파일 저장·수정·삭제 등을 할 수 있으면 동일한 역할을 하게 되니까."
3. "파인더 설정 여기서 넘어가지가 않는다. 실질적으로 에이전트 연결 파트가 UI만 되어 있고 실제 연결이나 구현은 안 된 거야?"

## 실측
- [확인] 처리할 일의 D+N 카드는 마감 카드다. 마감 장부에는 hejo 스레드 정보가 없고(`<운영 저장소>/hermes/plugin-store/team-kit/deadline_watch.py:149` 읽기 필드), 마감 점검 알림은 Slack 보고 채널로만 간다(`deadline_watch.py:270-277`). 그래서 앱은 명세(HEJO-TODO-DRAWER REQ-TD-04.AC-02)대로 직원 1:1 방으로 간다(`app/Sources/ConversationView.swift:11-17`). 고장이 아니라 명세 빈칸이다.
- [확인] 직원의 파일 읽기·쓰기·삭제는 고른 폴더(`files.folders`)를 그대로 쓴다(`team-kit/lib/hermes_packs/files_docs/files.py:150-162`). NAS 로그인은 시놀로지 공유 링크 만들기(`file_location`, `files.py:349-400`)에만 쓴다.
- [확인] 연결 기능은 실제로 동작한다(앱 → 문 → team-kit `app_connect`, HEJO-CONNECTIONS·CONN-MANAGE 검증 완료). Finder 연결만 막힌다. Finder 연결의 고르기 후보는 서버의 iCloud Drive 하나뿐이고(`team-kit/lib/hermes_packs/mac_apps/catalog.py:69-71`), 나머지는 사용자가 Mac 기본 폴더 고르기 창으로 직접 넣는 설계다(`app_setup.py:144-150`, ddots `AgentAppConnections.swift:236-237·305-311`). hejo 연결 화면에는 그 단추가 없다. 서버에 iCloud Drive가 없으면 후보 0개 → `SCOPE_EMPTY` → "확인하고 저장"이 꺼진 채 멈춘다(`app_connect.py:694-698`, `app/Sources/ConnectionsWindow.swift:463`).
- [확인] 사장은 hejo를 서버가 아닌 다른 Mac에서만 쓴다. 그 Mac의 폴더 고르기 창 경로는 서버에 없으므로 ddots 단추를 옮기는 것만으로는 풀리지 않는다.

## 이 작업(A)의 목적과 범위
- 목적: 다른 Mac의 hejo에서 Finder 연결을 열면 서버의 Synology Drive·iCloud Drive 등 동기화 폴더가 후보로 나오고, 클릭으로 골라 저장할 수 있다. 그러면 NAS 로그인 없이 직원이 그 폴더의 파일을 저장·수정·삭제한다.
- 하지 않는 것: 시놀로지 계정 연결 제거(공유 링크가 필요할 때 쓰도록 그대로), 다른 Mac 경로 사용, 경로 직접 입력, B(마감 알림 hejo 이전, 별도 작업).

## 대안과 선택
| 대안 | 판단 |
|---|---|
| 서버 동기화 폴더와 그 아래 두 단계까지를 고르기 후보로 보여 주기 | **채택(계획 단계에서 구체화)**. team-kit 한 곳만 바뀌고 문·앱 계약이 그대로라 앱 공개가 필요 없다. 위 폴더를 고르면 그 아래 전체를 쓰므로 두 단계면 실제로 충분하다. Obsidian 보관함 하위 폴더 후보(`app_setup.py:109-113`)와 같은 방식 |
| 서버 폴더를 한 단계씩 들어가며 고르는 탐색 화면 | 기각(지금). 새 동작·문 중계·앱 화면·앱 공개가 필요하다. 두 단계 목록이 실제로 불편하면 후속 작업 |
| ddots의 "이 Mac에서 폴더 고르기" 단추 이식 | 기각. 다른 Mac 경로는 서버에 없다 |
| 경로를 글로 직접 입력 | 기각. 오타·이해 부담 |

브레인스토밍 요약에서는 "하위 폴더로 들어가며 고르기"(탐색 화면)를 제안했었다. 계획 단계에서 위 표처럼 두 단계 목록으로 바꿨다(바뀌는 곳·공개 비용이 훨씬 작음). 사장 계획 확인 때 이 변경을 함께 확인받는다.
