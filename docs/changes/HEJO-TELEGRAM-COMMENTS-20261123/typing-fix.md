# 댓글 연결 방의 작성 중 표시 복구

상태: 로컬 수정·자체 점검 완료, 배포 미실행. 기준: 09ddcece1aeb940a71c1f926b6883de32c2d3863.

## 원인과 범위

사용자가 현재 댓글 방식을 유지하며 HEJO 내부 개별 방 및 질문별 댓글창의 작성 중 표시를 요청했다. Telegram.send_typing은 comments 경로를 무조건 제외했다. 기존 사람 토픽으로 보내는 알림을 comments에서도 허용한다. 예약된 비동기 알림은 실행 직전 현재 짝·활성 여부·경로·토픽을 재확인한다. 본문, 카드, 댓글 전달, 앱, 저장 계약은 변경하지 않는다. 기존 질문 대응표의 discussion anchor를 사용해 해당 댓글창에도 알림을 보낸다. 채널에는 보내지 않는다. 댓글 목적지는 기존 권한·연결을 재검증하며 실패해도 본문 전달을 중단하지 않는다. 종료된 작업의 예약 알림은 보내지 않는다.

칸은 기존 gate 문, 원본은 runtime typing 이벤트와 기존 연결 정보이며 새 원본/금고 값은 없다. 일반 위험의 기존 기능 회귀 수정이다. 4초 제한 및 알림 오류 격리는 기존 동작을 유지한다.

## 운영 적용 인계 — 승인 대기

이 수정 후보를 별도 로컬 브랜치에 고정한다. 배포 전 현재 설치가 기준 후보와 일치하는지, 활성 세션이 없는지 확인한다. 유휴 상태에서 후보 설치와 gateway 정상 재시작 1회만 수행하며 연결/바인딩/기록은 보존한다. 실패 시 같은 hub 저장 계약을 사용하는 기준 후보로 복구하고 연결 상태를 확인한다. 새 bind/off/probe, 자동 질문 발신은 하지 않는다. 사용자가 기존 개별 방 및 댓글창에서 질문하여 작성 중 표시를 확인한다. 클라이언트 실제 표시 확인 전 대역 성공을 실물 성공으로 표현하지 않는다. 과거 H5 1회 승인을 새 배포 승인으로 재사용하지 않는다.

## 별도 요구: 다수방 댓글 묶음

현재 Comments.rooms는 직원 명부만 반환하고 bind의 활성 rooms 변경도 거부한다. Telegram.rooms와 달리 일반 방을 포함하지 않아 다수방은 댓글 경로 대상이 아니다. 사용자는 다수방 수신 직원을 hejo 방 대표직원과 일치시키기로 정했다. 대표직원 설정을 복제하지 않고 기존 방에서 읽는다. 이 요구는 아직 구현하지 않았다.

후속 변경은 일반 방 식별/대표 유효성, adapter.receive의 room 및 targeted 전달, 직원별 첨부 staging, 방 세션 busy 검사, 발신 구성원 검사와 기존 hub에 방을 안전하게 추가하는 계약을 함께 설계해야 한다. 대표가 없거나 유효한 구성원이 아니면 임의 fallback하지 않는다. 앱의 멘션/주인 선택 규칙을 전역 변경하지 않는다. 기존 대화/방/외부 쌍은 보존하며 실제 연결 확대는 구체 인계 후 승인한다.

초기 댓글 시험은 준비 단계의 자동 typing이 같은 throttle 창을 이미 사용하여 3개가 실패했다. 준비 완료 후 새 heartbeat 창으로 시험하도록 fixture를 수정했으며 실패 로그는 target-before-fixture-fix.log에 보존했다. 제품의 전송 제한은 완화하지 않았다.
