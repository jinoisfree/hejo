# 텔레그램 질문별 댓글 묶음

## 칸·원본·쓰기 주체·수명

| 다루는 것 | 칸 | 원본 위치 | 쓰기 주체 | 수명 |
|---|---|---|---|---|
| 텔레그램 연결 처리 | 공항 시설·탑승교 | `gate/telegram.py` | 개발 | 갱신 때 교체 |
| 연결 대상·사장 신원 | 사장 금고 | 기존 텔레그램 금고 계약 | 문, 사장 요청에 한정 | 연결 해제까지 보존 |
| 외부 메시지 대응 | 공용 창고 | 기존 텔레그램 대응표 | 문 단독 | 영구 |
| 대화 원본 | 공용 창고 | 기존 기록장 | 문 단독 | 기존 정책 유지 |

근간은 [ARCHITECTURE](../../ARCHITECTURE.md). 새 저장 위치나 두 번째 대화 원본은 제안하지 않는다. 여러 채널을 담는 계약의 구체 형식은 설계 전 미확정이다.

## 사용자 결정

- 목적: 사람별 공간을 유지하면서 질문마다 답장 묶음을 열어 보기.
- hejo 앱을 수정하지 않는다. 텔레그램 기본 화면을 이용한다.
- 사람별 비공개 채널의 게시물을 질문으로, 연결된 토론 그룹의 댓글을 해당 질문의 대화로 쓰는 대안을 설명한 뒤 사용자가 구현 진행을 요청했다.
- 연합개발, 계획 검증 켜기. 실제 구현 담당 및 계획 검증 담당 전달은 호스트가 관리한다.
- 서버 연결 코드의 구체 변경, 운영 전환 절차와 수락 기준은 아직 확정하지 않았다.

## 하는 것·하지 않는 것

목표는 새 질문을 채널 게시물로 보여 주고 관련 답변·사진·후속 질문을 댓글에서 읽는 것이다. 기존 사람별 토픽 자체를 그대로 유지하는 설계는 아니다. 기존 대화 삭제·과거 기록 일괄 이관은 요청되지 않았다. 앱 화면, Hermes 본체, 별도 텔레그램 클라이언트 개발은 범위 밖이다.

## 선행 조사

| 자료 | 확인 내용 | 판단 |
|---|---|---|
| https://core.telegram.org/api/forum#interacting-within-topics | 토픽 안에는 하위 메시지 스레드가 생기지 않음 | 기존 토픽 내부 표시만으로 목표 충족 불가 |
| https://core.telegram.org/api/threads | 일반 메시지 스레드와 채널 댓글 존재 | 공식 기능 활용 |
| https://telegram.org/blog/filters-anonymous-admins-comments | 채널에 토론 그룹을 연결하면 게시물별 댓글 버튼과 별도 스레드 제공 | 채널 댓글 대안 채택 방향 |

별도 오픈소스 클라이언트 채택은 사용자가 앱 수정 없이 텔레그램에서 쓰기를 원하므로 이번 조사 대상에서 제외했다. 공식 기능 확인은 완료했으나 실제 봇 연결은 검증하지 않았다.

## 대안과 선택

1. 사람별 채널 + 게시물별 댓글: 사용자 선택 방향. 사람별 공간은 유지하지만 기존 토픽에서 채널로 사용 동선이 바뀜.
2. 일감별 토픽: 사람별 방 유지 요구와 맞지 않음.
3. hejo 앱의 묶음 화면: 사용자 명시 제외.

## 실측·가정·열린 문제

[확인] 현재 구현은 포럼 그룹 하나에 짝짓고 방마다 토픽을 만들도록 고정되어 있다. 설정만으로 채널 댓글로 전환할 수 없다. 상세 근거는 [조사 기록](investigation.md).

[가정] 앱 무수정은 서버의 기존 텔레그램 문 변경까지 금지한다는 뜻으로 확대하지 않는다. 다만 구현 계획에 서버 변경 범위를 명시해야 한다.

[미확정] 채널 게시자의 신원 판정, 자동 전달 원문과 댓글의 대응, 플랫폼 처리기 단계까지 도착하기 전 필터, 연결 설정 방식, 기존 경로 전환·복구, 실제 클라이언트 화면 시험.

위험도 1차 판단: 고위험. 연결 대상·권한 및 영구 메시지 대응 계약이 바뀌며 다른 사람/질문으로의 오배송을 막아야 한다. 계획 검증과 실제 환경 증거 없이 완료로 판정하지 않는다.
