# 최종 공개 후보와 Git 보존 조건

## 확정 범위

외부 개발 변경20파일, 기존 문서32개와 독립 검토 보고2개·최종 검증 근거12개를 공개 후보로 고정했다. 정확한 상대 경로와 SHA-256은 [목록](logs/release-candidate/inventory.json)에 있다. 이 정리 문서와 아래 검사 근거도 포함한다. 목록 자체는 자기 해시를 포함하지 않으며 최종 Git tree로 고정한다. 목록에 없는 파일을 글롭으로 stage하지 않는다.

개발 코드20파일은 외부 개발 저장소에만 반영한다. 생성401파일은 기존 생성기의 공개 배포 결과이며 별도 생성 공개 저장소에만 반영한다. hejo에는 검토 문서·검증 근거만 전달한다. 기존5시험 원문, 비추적 private 실행기/원문/.build/archive와 운영 설정·명부·자격은 제외하고 로컬에서 보존한다.

## 개발 기준과 공개 이력

[현재 Git 읽기](logs/release-candidate/git-boundaries.json) 기준 외부 개발 HEAD는 cf79f4527949c88a9b74612872cf4c09a51441db이나 로컬 main은4bbc16ddba02236fe4645ab7244603c44a78af91로 진행됐다. 원격 main은 이전 HEAD와 같다. 새 기준의5파일은 이번20파일과 겹치지 않는다. 운영 자료 본문은 열지 않았고 기존 작업을 버리거나 되돌리지 않는다. 개발 브랜치에 최신 로컬 기준을 포함한 뒤 영향 검증이 필요하다.

hejo 개발 HEAD39f954c1bd3a50fd27d4f11a3b03774d0e74aa41에는 로컬 main236b0177468b90d9ea23a1b1190e996db78a0694가 포함되지 않는다. 실제 공개 원격 main은dbc512be27804fa5b0dd36507eabc069b93f1293이며 로컬 원격추적 tip은 오래됐다. 개발 main과 공개 원격은 공통조상이 없는 snapshot 이력이다. 개발에는 개발 기준만 포함하고 공개 이력을 임의 merge하지 않는다.

공개 hejo에는 후속 입력/성능/UI 변경이 있다. 최종 공개 tree는 현재 원격 공개 tree를 보존하고 이번 확정 문서만 더하는 방식으로 검증해야 한다. 원격 부모는 정확히 하나이며 개발 HEAD/기준 포함 증명은 별도로 보존한다. 오래된 개발 tree 전체로 원격 공개판을 덮어쓰지 않는다.

생성 공개 저장소 HEAD/로컬main/원격main은fe52d5a97739c71fae6ccd1b936a6f73cecd56ae로 일치한다. 검증된 입력과 기존 생성기 출력만 반영하고 비대상/타 작업 차이가 생기면 보존 대조 후 진행한다. 공개checkout 직접 편집·전체 sync·publish 실행으로 우회하지 않는다.
