# 공개 배포 경로·수집 보존 경계 조사

읽기 조사 완료. 정상 연결/서비스·수집 사본·생성 공개판은 변경하지 않았다. 근거 코드 해시는 [감사 기록](logs/distribution-audit/evidence.json)에 있다. 기존 사용자 정상 사용 확인은 유지한다.

## 기존 책임과 전달 경로

- hejo `install/hejo-release`는 gate/hub/schemas/config/install을 공유 배포 위치에 복사한다. team-kit은 이 복사 목록에 없다. `install/hejo-join`은 사용자 자신의 Hermes에 hejo 문을 설치하고 gateway를 재시작하는 실행기이므로 이번 조사에서 실행하지 않았다.
- `gate/connection_runtime.py`의 TeamKit은 요청 home의 `bin/hermes-connections`를 호출한다. 따라서 앱만 새로 배포해도 외부 team-kit 수정이 함께 전달되지는 않는다.
- 운영 저장소의 기존 `sync`가 설치 원본을 수집하고, `make-starter`의 대상 분기가 `starter-public.py`로 전달한다. `starter-manifest`는 수집된 `hermes/plugin-store/team-kit`을 공개 `plugins/team-kit`에 포함한다. 공개판을 손으로 고치거나 hejo 안에 두 번째 team-kit 원본을 만들지 않는다.
- `starter-public.py`는 기존 manifest 생성·개인값 검사를 재사용한다. publish/prepare는 수집/생성기 입력의 미커밋 변경을 source-dirty로 거부하며 대상 원격/브랜치/clean 및 원격 HEAD 동일성을 확인한다. `--prepare`도 fetch·대상 쓰기·stage·commit·훅 설치를 수행한다. 단순 읽기 검사가 아니다. `--publish`는 직접 push하므로 이 작업에서 사용하지 않는다. 기존 지역 규칙의 자동 푸시 허용보다 이번 사용자/플러그인 푸시 계약이 우선한다.

## 보존 경계

`sync`는 hermes/launchd/local-bin 사본을 rmtree한 뒤 재수집한다. `--split --dry-run` 역시 이 수집 이후의 커밋 분할만 미리 본다. 수집 전 본체 백업 export도 호출하므로 읽기 명령으로 오해하면 안 된다. 현재 범위 밖 변경의 보존을 증명하지 못한 상태에서 어떤 sync 변형도 실행하지 않는다.

현재 수집 status는 내용 조회 없이 해시만 기록했다. 과거 미보존7항목이 지금도 정확히 같은 바이트/개수라고 단정하지 않는다. status 동일성이나 설치 코드 archive는 범위 밖 개인자료 보존 증명이 아니다. 해당 자료 내용·비밀·자격은 열지 않았다.

## 후속 작업 경계

1. 기존 설치 후보와 수집 코드의 해당 파일만 해시로 비교하고, 공개 manifest에 필요한 CLI/공유 라이브러리/플러그인 의존성의 포함 여부를 확인한다. 정상 운영을 변경하지 않는다.
2. 수집을 실행하기 전에 무관 변경을 보존할 방법과 기존 수집 책임 안의 최소 변경 반영 방법을 구체화한다. 개인자료 읽기·범위 밖 정리·전체 sync로 우회하지 않는다. 아직 보존 해결이나 수집 실행 승인을 얻었다고 보지 않는다.
3. 지정 구현 worktree에 해당하는 개발 이력과 별도 생성 공개판의 저장소 경계를 확정한다. 현재 지정 hejo worktree 하나의 커밋만으로 외부 team-kit 배포까지 완료됐다고 할 수 없다. 추가 저장소 변경/커밋은 지정 작업 범위와 충돌하지 않도록 별도 실행 범위를 확정한 뒤 진행한다.
4. 검증된 입력으로 기존 생성기를 사용한 공개 검사·독립 임시 설치 검증을 준비한다. 생성 공개판 자체 편집이나 실제 계정/운영 재시작은 하지 않는다. 독립 사용자 자기 계정 실사용은 별도 증거로 유지한다.
5. 실제 변경과 검증·커밋이 준비된 뒤 정확한 저장소/원격/브랜치/전체 커밋으로 플러그인 푸시 승인을 요청한다. 이번에는 푸시대상이 확정되지 않았으며 원격 포함도 확인하지 않았다.

이번 판정은 배포 책임과 보존 위험의 소스 조사이며 배포 실행 성공이 아니다. 새로운 제품 결함을 확인한 것은 아니다.
