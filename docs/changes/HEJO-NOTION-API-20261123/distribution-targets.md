# 공개 반영 대상·의존성 대조

[해시 대조](logs/distribution-audit/target-comparison.json)에서 설치13파일(제품11·기존 회귀시험2)은 각 최종 수락 해시와 모두 일치했다. 수집13파일은 모두 알려진 변경 전 해시다. app_setup은 제목 수정 전 기준, 나머지는 v1 또는 상위 범위 수정 전 기준이다. 이 대상들에는 모르는 바이트 충돌이 발견되지 않았다. 이 사실을 범위 밖 개인자료 보존 증명으로 확대하지 않는다.

## 포함되는 것과 빠진 것

공개 manifest의 team-kit 전체 코드 트리는 제품11파일과 lib/hermes_facility/connections.py 및 관련 공유 라이브러리를 포함할 수 있다. 조사한 관련 의존 코드의 설치/수집 해시는 동일하다. generator의 트리 순회는 tests 디렉터리를 제외하므로 개발 시험을 보존할 위치와 사용자 배포 트리는 구별해야 한다. 최종 상위 범위 후보의 추가 시험5파일은 설치13파일 대조에 포함하지 않았으며 개발 반영 시 별도 목록에 포함한다.

hejo gate의 TeamKit은 home/bin/hermes-connections를 필수 진입점으로 사용한다. 현재 운영 wrapper는 설치 runtime을 선택하고 plugin-store/team-kit/lib의 hermes_facility.connections.main(root)를 호출한다. 읽은 공개 manifest·starter 설치기·hejo 설치기에는 이 wrapper를 배포/설치하는 경로가 없다. 공개 시작 틀 설치기는 plugin-store 코드와 링크·설정을 관리하며 CLI 모듈 존재만으로 bin 실행 파일을 만들어 주지 않는다. 따라서 다른 사용자 신규 설치의 연결 진입점 제공은 배포 설계 보완 대상이다. 아직 깨끗한 환경 실행으로 재현한 결과는 아니며, 외부 설치 도구가 이미 제공하는 환경까지 실패한다고 단정하지 않는다.

## 최소 반영 범위

1. 기능 누적분은 기존 team-kit 원본 책임에서 제품11파일·기존 회귀2파일을 반영하고, 별도 수락 후보 시험5파일을 개발 증거로 보존한다. 관련 의존 코드를 불필요하게 다시 수정하지 않는다. 공개 생성 결과는 직접 고치지 않는다.
2. CLI 배포 보완은 기존 공개 설치 책임에서 wrapper 원본·실행 모드·설치 기록·업데이트/충돌/복구 처리를 설계한다. hejo에 라이브러리를 중복 내장하거나 본체를 수정하지 않는다. 기존 사용자 wrapper를 무조건 덮어쓰지 않는다. runtime 탐색은 지원되는 설치 계약을 사용하고 특정 운영자 경로를 고정하지 않는다.
3. 수집은 현재 전체 삭제/재수집 대신 기존 sync 책임 안의 명시 코드 목록만 다루는 보완 가능성을 검토한다. 실제 변경 전 대상 CAS·모드·원본 확인과 비대상 무쓰기, 링크/경로 이탈 거부를 요구한다. 현재 사본을 손으로 바꾸거나 별도 수집 원본을 만들지 않는다. 범위 밖7항목 내용 조회/정리로 해결하지 않는다.
4. 위 보완은 외부 운영 저장소의 수집/공개 설치 코드 책임이므로 지정 hejo worktree만 변경하는 현재 계약과 경계를 확정해야 한다. 이번 조사에서 추가 저장소 변경·worktree 생성·커밋은 하지 않았다. 후속은 정확한 변경 파일과 격리 시험 계획을 준비하는 것이며 현재 정상 연결을 재설치하는 단계가 아니다.

수락할 격리 검증은 가짜 홈 신규 설치의 gate→CLI 진입, 서로 다른 두 홈의 runtime/profile/자격 분리, 기존 wrapper 충돌 보존과 업데이트/원복, 코드 한정 수집의 비대상 무쓰기다. 실제 자격/API나 운영 서비스는 사용하지 않는다. 기존 기능90/474 시험은 후보가 같으므로 이번에 반복하지 않았다.
