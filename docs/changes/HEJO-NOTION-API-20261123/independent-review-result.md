## V-IR-01 — 차단, CLI 시작 실패의 안전한 오류 처리 누락

위치: 외부 개발 starter-templates/install_support.py:171~175, starter-templates/hermes-connections.py:10. AT-HNA-DIST-08 위반.

실행권한만 확인한 runtime의 exec가 실패하면 셸/로더 원문 오류가 나갈 수 있다. Python 실행 뒤 connections import도 main의 오류 변환 밖이어서 traceback/설치 경로 노출 및 재설치 안내 누락이 가능하다. 기존 시험은 runtime 경로 없음만 다뤘다. 소스 도달 경로 확인이며 실행 재현은 하지 않았다.

처분: 수락. 기존 launcher/template에서 시작 실패와 import 실패를 고정된 안전한 오류로 처리한다. 정상 stdout JSON·stdin·인자·종료 의미와 gate의 취소/timeout 동작을 보존해야 한다. 재시도/fallback/다운로드는 추가하지 않는다. 실행권한 있는 고장 runtime, import-time 실패, runtime 없음, 정상 두 홈 및 기존 실패 JSON 전달 시험을 추가한다. 변경 뒤 설치 출력/receipt 해시 및 생성 결과는 새 후보로 검증한다. 기존134시험 결과를 새 코드 통과로 승계하지 않는다.

## V-IR-02 — 차단, 공개 시험 증거의 식별값

위치: hejo evidence/accepted-tests/test_notion.py.txt:32,55,87,96,102 및56,196,1142. :15 DB ID의 합성 근거도 부족하다. 사람 이름형·기존 직원 별칭/profile 형태 값이 신규 공개 후보에 남아 있다. 실제 개인값인지는 운영/비밀 자료로 대조하지 않았다. 해당 문자열을 이 보고에 재출력하지 않는다.

처분: 수락. 원본5시험 증거는 로컬에 바이트/해시를 보존하고 공개 후보에서 제외한다. 실제 파일을 지우거나 원본 해시를 새 사본에 붙이지 않는다. Git 문서 후보 목록의 기존5증거 포함 제안은 이 처분으로 대체한다. 공개 재현용 시험이 필요하면 명확한 합성 fixture로 별도 검증해야 한다. 공개32문서와 실제 배포 대상도 이름/직원 식별값 관점으로 심사하며 이전 제한적 패턴0을 전체 개인정보 통과로 표시하지 않는다.

## 확인 범위와 한계

검토자는 제출25파일·private 실행기2개 해시/모드 일치,외부20파일 전체 변경 diff·새 template·주요 호출자,scope/setup/middleware/grant/journal/undo 소비자와 관련 시험을 읽었다. sync의 조기 분기/CAS/FIFO/부분복구에서 추가 차단 결함을 찾지 못했다. 기존134시험 및23시험 통과는 보존 로그 확인이며 직접 실행이 아니다. 읽기 명령은 cat/sed/rg/git diff/status/rev-parse 및 SHA/텍스트 diff이고 검토자 자체 로그 파일은 만들지 않았다.

모든 기존 코드/긴 회귀시험을 매 줄 재검토하지 않았다. 실제 변경과 중요 실패경로 중심이다. mutation/수락시험/실제계정/독립컴퓨터/공개32문서 전체 개인정보 검사는 미실행이다. 04B-R1의같은Python·빈APP_ROOTS·gateSucceeded 위주 단언은 홈별 실제 명부/Notion후보 전체를 입증하지 않는다. 공개 최소fixture에는 홈별 명부/후보 단언 보완을 권고한다.

독립 읽기 검토는 완료됐지만 독립 실행 검증 완료가 아니다. 두 지적의 한정 delta·관련 시험·공개 목록 변경을 같은 검토자에게 재검토받을 수 있다. 정상 연결/서비스는 유지한다. 커밋/푸시는 아직 하지 않는다.
