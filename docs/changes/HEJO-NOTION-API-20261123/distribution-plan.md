# TASK-04A — 수집·공개 설치 보완 계획

상태: 사용자 ‘진행’으로 외부 저장소 격리 구현·가짜 시험 승인. TASK-04A 자체 점검 결과는 impl-report-task04a.md를 따른다. 아래 실행 전 경계와 별도 운영 승인 조건은 유지한다. 현재 대화가 직접 구현한다. 정상 사용 중인 Notion 연결·서비스는 변경하지 않는다. [대상 대조](distribution-targets.md)와 [배포 경계](distribution-audit.md)를 근거로 한다. 이번에는 제품 코드나 외부 저장소를 수정하지 않았다.

## 칸·원본·저장소 경계

수집 책임은 운영 저장소의 sync, 공개 배포 책임은 그 저장소의 starter-manifest 및 starter-templates/install_support.py다. 생성 공개판은 결과이며 직접 수정하지 않는다. Hermes 본체와 hejo gate의 호출 계약은 유지한다.

현재 지정 hejo 구현 worktree/브랜치는 그대로 보존한다. 외부 운영 저장소 파일은 그 브랜치에서 추적할 수 없으므로 같은 경로에 복사해 두 번째 원본을 만들지 않는다. 외부 저장소 구현은 별도 격리 worktree/브랜치를 사용자 승인 후 확정하고 로컬 인계에 경로·기준 HEAD를 기록한다. 현 운영 checkout과 무관한 미커밋 자료를 편집/정리하지 않는다. 이번 제안은 외부 코드의 격리 구현·가짜 환경 검증까지다. 실제 수집·공개 생성·설치·서비스 제어·커밋·푸시는 후속 구체 인계로 분리한다.

## 정확한 변경 파일

| 기존 운영 저장소 상대 경로 | 변경 책임 |
|---|---|

| tests/test_sync.py | 명시 목록·CAS·무관 파일 보존·실패 복구·무부작용 회귀 |
| starter-templates/hermes-connections.py (신규) | 공개용 얇은 CLI 실행 템플릿. 연결 로직은 기존 hermes_facility.connections.main에 남긴다 |
| starter-manifest | 템플릿을 commands/hermes-connections.py로 포함. 기존 bin 일괄 금지/개인자료 차단을 완화하지 않는다 |
| starter-templates/install_support.py | 기존 runtime_python 선택을 이용한 홈별 실행 파일 설치, 관리 기록·모드·충돌·업데이트·복구 연결 |

make-starter/starter-public.py의 필터·publish·원격 쓰기 경로는 변경하지 않는다. 계획 밖 파일이나 본체 변경이 필요하면 근거를 먼저 기록하고 범위를 재확정한다. 기존 제품 누적11파일·회귀2파일 및 후보 시험5파일은 수집 기능이 검증된 뒤 별도 반영 대상이며 이번 도구 보완에서 재작성하지 않는다.

## 코드 한정 수집 계약

- 일회성 입력은 허용된 team-kit 코드 상대 경로, 설치 원본 예상 해시/모드, 수집 기존 예상 해시/모드로 한정한다. 소스 루트/대상 루트는 기존 sync의 책임을 유지한다. 임의 절대 경로·상위 이탈·빈/중복 목록·심볼릭 링크 경로·비밀/설정/개인자료는 거부한다.
- 파일 단위 명시 목록만 사용한다. 디렉터리 전체/글롭·삭제 동기화·비대상 재수집·본체 export·커밋/푸시·조립·재시작을 호출하지 않는다. 한정 모드와 commit/split/core-only 조합은 시작 전에 거부한다.
- 모든 대상의 원본/기존 사본을 먼저 확인한 뒤 복사한다. 읽은 바이트 해시와 현재 경로/identity를 확인하고 쓰기 직전 충돌을 재확인한다. 외부 작성자를 강제로 막을 수 있다는 주장은 하지 않는다. 변경 감지 시 중단하고 겹치는 타 작업 바이트를 복구로 덮어쓰지 않는다.
- 임시 파일+원자 교체와 자기 대상만의 임시 복구 기록을 사용한다. 부분 쓰기 실패 시 자기 직전 바이트/모드만 복구할 수 있어야 한다. 복구 충돌은 수동 처분으로 보고한다. 개인자료를 archive에 넣지 않는다.
- 미리보기는 파일/인덱스/백업/로그 디렉터리를 만들지 않는다. 운영 재사용 승인 전에 격리 fixture로 실제 쓰기 경계와 실패 경로를 검증한다. 범위 밖 기존7항목을 보존했다고 주장하려면 비대상 무쓰기 설계 및 해당 실행 증거가 필요하며 status만으로 대신하지 않는다.

## CLI 공개 설치 계약

- 배포 원본은 공개 템플릿 한 곳이다. 운영자의 기존 wrapper를 공개판에 그대로 복사하지 않는다. 계정값·자격·개인 홈·고정 직원은 템플릿에 없다. 기존 연결 로직/권한/트랜잭션은 복제하지 않는다.
- 설치 시 기존 runtime_python 계약으로 선택한 Python을 사용한다. 해당 설치 홈과 runtime 경로는 로컬 설치 결과에만 결합한다. 실행은 명시 HERMES_HOME 또는 자신의 설치 홈을 사용하며 다른 사용자 홈·기본 운영 계정으로 fallback하지 않는다. runtime이 사라지거나 변경돼 유효하지 않으면 안전하게 재설치/업데이트를 안내하며 임의 다운로드하지 않는다.
- 설치 대상은 bin/hermes-connections, 모드0755다. 배포 commands 템플릿은 일반 코드 파일로 관리한다. 기존 signature/receipt의 해시 외 모드도 검사할 수 있도록 호환 가능한 최소 확장을 한다. 기존 영수증에 mode가 없다고 전체 설치를 깨뜨리지 않되 새 CLI 실행권한 손실은 탐지해야 한다.
- apply_files의 plugin-store 전용 roots 탐색을 경로 종류별로 구분한다. bin 파일을 플러그인 이름으로 오인하여 엉뚱한 트리를 검사하지 않는다. 기존 플러그인 미추적 파일 보존은 유지한다.
- 신규 설치는 소유하지 않은 다른 wrapper/링크가 있으면 사전 거부한다. 업데이트는 기록된 자기 코드만 바꾸며 외부 편집은 보존한다. 설치 실패 시 바이트·모드·관리 기록을 복원하고 기존 설정/금고를 바꾸지 않는다. 정상 운영 환경에 재설치하지 않는다.

## 위험·완료·다음 승인

설치와 기존 파일 보존에 영향을 주므로 고위험으로 취급한다. 격리 구현은 증거 수준2를 요구하며 실제 배포/실사용은 별도다. 직접 구현 뒤 결과는 자체 점검으로 표시하고 고위험 최종 검토를 대체하지 않는다.

이번 계획의 준비는 완료다. 구현 전 필요한 결정은 현재 지정 hejo worktree 밖의 기존 운영 저장소에 별도 격리 worktree를 만들어 위7파일만 구현·가짜 시험하도록 범위를 확장할지 여부다. 사용자 정상 연결·서비스·개인자료를 건드리는 승인이 아니며 원격 쓰기 승인도 아니다.
