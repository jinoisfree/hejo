## 사용자 결정

- 연결 해제하면 이 직원의 Google 계정 연결과 화면 이메일을 제거한다.
- 다음 연결은 기존 계정을 자동 재사용하지 않고 Google 계정 선택부터 진행한다.
- ‘사용 중지’와 ‘계정 바꾸기’를 따로 두는 대안은 채택하지 않았다.
- 연합개발, 계획 검증 켜기. 담당 대화 생성·전달은 호스트가 맡는다.
- 직원별 Google 연결을 기존 금고에 두고 전용 인증 위치로 분리하는 배치안에 대해 사용자가 “너의 추천대로 진행하자”로 승인했다. 실제 운영 계정 변경·푸시 승인은 별도다.

## 범위와 제안

대상은 Google 개인 연결 문제다. 다른 직원 연결 보존을 설계 제약으로 제안한다. 공용 계정 전체 권한 철회·Google 계정 자체 삭제·다른 서비스 해제 의미 변경은 제외한다. 인증 취소·실패 시 해제 상태를 유지하고 성공 검증 뒤에만 새 연결을 저장하는 것을 목표로 한다.

## 확인한 현재 동작

- hejo 기준: 236b0177468b90d9ea23a1b1190e996db78a0694.
- 운영 저장소 기준: 4bbc16ddba02236fe4645ab7244603c44a78af91. 실제 경로는 추적하지 않는 AGENTS.local.md 참조.
- ConnectionsWindow.swift의 perform은 해제 확인에 값 보존을 명시한다.
- tests/acceptance/HEJO-CONN-MANAGE.md AT-CM-09·10은 Google 해제를 enabled 변경, 재연결을 기존 값 재사용으로 규정한다. 이번 요구는 이 의미를 바꾼다.
- 운영 저장소 hermes/plugin-store/team-kit/lib/hermes_facility/account_connect.py의 run/set_enabled는 Google 서비스 스위치와 스킬 비활성 목록을 변경하며 계정 매핑을 지우지 않는다.
- 같은 폴더 connections.py의 connection_rows는 직원 gmail.account를 공용 personal/company 이메일과 대조한다. Google 상태 확인도 이 두 범위 단위다.
- hermes_packs/mail/google_reauth.py는 기존 금고 계정과 인증 결과가 같은지 검증하고 기존 인증 명령을 실행한다.
- 운영 저장소 hermes/bin/hermes-personal-google-auth는 범위별 기존 계정·토큰 위치와 login_hint를 사용한다. 개인값은 이 문서에 복사하지 않는다.
- 따라서 표시 제거와 select_account 추가만으로 직원별 독립 계정 교체를 보장할 수 없다. 인증 생산자와 메일·캘린더 소비자 경로 조사가 더 필요하다.

## 선행 조사·위험·미확정

내부 계약 변경이므로 외부 사례 조사는 생략했다. 위험도는 고위험(인증·개인정보·연결 삭제·공유 상태). 필요한 증거는 격리 홈 대역 통합(2), 실제 앱 동작(3), 사용자 직접 계정 선택에 의한 실제 인증(4)을 구분한다. 실제 계정 접속·운영 설정 변경·재시작·시험은 미실행.

두 저장소 모두 기존 미커밋 변경이 있다. 특히 운영 저장소 app_connect.py는 계정 연결의 트랜잭션 기반이므로 작업 겹침을 확인하기 전 구현하지 않는다. 다른 작업 파일을 되돌리거나 함께 커밋하지 않는다.

열린 조사: 조립 원본의 직원별 매핑, 각 Google 소비자의 인증 조회 책임, 기존 금고 안에서 독립 연결을 표현할 수 있는지, 해제 후 옛 OAuth 완료의 재연결 방지, 공유 토큰 보존과 접근 차단, undo 의미, 운영 적용 및 복구 범위. 근간의 새 칸 또는 두 번째 원본이 필요하면 구현 계획을 확정하지 않고 배치를 보고한다.
