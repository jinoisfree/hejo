## 목표·범위

직원의 Google 개인 연결을 해제하면 계정 표시와 사용 권한이 없어지고 다음 연결에서 다른 Google 계정을 선택할 수 있다. 다른 직원과 회사 계정의 연결은 보존한다. Google 개인 연결의 의미 변경이며 다른 서비스의 ‘해제 후 값 재사용’은 변경하지 않는다.

포함: 기존 연결 화면/문/계정 CLI, 직원별 금고 연결·인증, 메일·캘린더와 해당 인증의 실제 소비자, 개인정보 보호·동시 처리·구버전 안전 경계, 수락 시험. 회사 계정 교체 UI, 일반 다중 계정 관리, 계정 자체 삭제·Google 전체 권한 철회, Hermes 본체 수정, Slack/고객 메시지, ddots 수정은 제외한다. 실환경 적용은 별도 운영 인계 승인 후에만 한다.

## 실패 상태와 문구

Google 개인 해제 확인: ‘이 직원의 Google 계정 연결과 저장된 인증 정보를 지웁니다. 다시 연결할 때 계정을 선택해야 합니다. 다른 직원의 연결은 유지됩니다.’ 공용 자격은 다른 직원 때문에 유지될 수 있으므로 상세에는 ‘이 직원 전용 인증 정보’로 표현한다. 기존 다른 서비스의 보존 문구는 그대로 둔다.

연결 실패 시 새 계정이 성공 표시되지 않는다. 계정 변경/인증 만료/권한 부족/저장 실패를 구분하되 외부 오류 원문과 계정·토큰은 로그에 싣지 않는다. 해제 접근 차단은 됐으나 파일 삭제가 실패하면 ‘인증 정보 정리 필요’로 알리고 완료로 보고하지 않는다.

## 완료·증거

고위험(인증·개인정보·삭제·동시성). 자동 대역 통합은 수준 2, 실제 AppKit은 수준 3, 사용자 직접 실계정 연결은 수준 4로 구분한다. 계획 독립 검증 및 구현에 참여하지 않은 다른 모델의 최종 검증이 필요하다. 설계자 최종 검증 외에 고위험 결과의 독립 검토 또는 사용자 검토도 남긴다. 코드·문서·수락 시험 통과와 실환경 증거, 적용 후 현재 명세 반영, 사용자 화면 푸시까지 구분해 보고한다. 미실행 실환경 검증을 임의로 통과 처리하지 않는다.
