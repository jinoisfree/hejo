병렬 갈래: 없음(Controller→Model→View가 같은 프레임/조회 경계를 공유하고 동일 시험 fixture로 비교해야 함). 다른 미완료 작업의 파일은 수정·커밋하지 않는다. 호스트의 겹침 경고가 있으면 별도 worktree 또는 대기 선택을 따른다.

TASK-01A 순서: 내용·계정·방 ID 없이 프레임 종류별 횟수와 관측 시간을 먼저 측정하고, 기준 HEAD에서 고정 가짜 입력의 출력·성능을 보존한다. 입력·결과 해시, 기준 커밋, 빌드 옵션, 반복별 결과를 남긴다. 설치 앱을 임의 교체하지 않으며 실제 수신 빈도를 안전하게 계측할 수 없으면 미측정 이유를 보고한다. 시험 하네스 또는 동작을 바꾸지 않는 격리 계측만 허용한다.

TASK-01A 결과를 계획 담당에게 반환한다. 계획 담당이 CPU·입력 지연·개선 폭의 합격 수치를 근거와 함께 수락 명세에 고정하기 전 TASK-01B 이후는 시작하지 않는다. 프레임 폭주·재전송 등으로 동기 중복 제거만으로 해결하기 어렵거나 서버·수신 스케줄링 변경이 필요하면 범위를 확대하지 않고 재설계로 돌린다.

v3 착수 시점 기록: 위 TASK-01A 결과 반환과 계획 담당의 수치 확정 절차를 마쳤다. 당시 실행 범위는 TASK-01B~03이었으며 기준 fixture 재동결·전체 기준 계측 반복은 하지 않는다. 검토 지적 V-HP-02 설명 정정 및 V-HP-04 실제 View 회귀를 포함한다. 측정 방식·조건을 바꿔야 하면 기존 기준과 섞지 말고 계획 담당에게 반환한다.

검토 2회 당시 상태: TASK-01B·02 제품 수정 및 TASK-03 격리 검증 수락. TASK-03 설치 후보는 V-HP-05 Google 배포 구성 누락으로 보완 중. 현재 인계는 패키징 보완뿐이며 실제 앱 교체는 보완 후보 검토 뒤다. TASK-04 및 전체 완료는 미완료.

검토 3회 당시 상태: V-HP-05 패키징 보완 수락. TASK-01B~03 완료, 현재 TASK-04 로컬 설치·실제 앱 검증 인계. 초안 보존 확인 전 종료 금지. 실제 앱 개선·현재 문서 반영·최종 판정은 남음.

검토 4회 수락 이후 현재 상태: TASK-01A~03 및 TASK-04 실제 앱 검증 수락. 최종 문서 반영과 공개/개발 이력 차이 조사를 구현 보고로 반환한다. 제품·fixture·설치 앱 변경 및 전체 시험 반복은 없으며, 최종 문서 커밋 재검토와 원격 처리 방식의 사용자 결정은 남아 있다.
