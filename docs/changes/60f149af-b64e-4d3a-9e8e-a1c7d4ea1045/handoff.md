## 이전 후속 인계: TASK-04 로컬 설치·실제 앱 검증 (검토 수락)

[verdict 3회 검토](verdict.md)에서 수락한 커밋 `221e84082a4230caca6b450cb3b2e0ee9d085ee8`의 `packaging/artifacts/hejo.app`만 사용한다. 실행 파일 SHA-256은 `01827d9ce8acbe89c631e477f66977caaf2ce8e934aeefebcac13f510b57ca65`다. 아래 경로는 구현 worktree의 `.build/hejo-perf-evidence/` 기준이다. 기존 시험용 v3 후보를 사용하지 않는다.

1. 후보·현재 설치본·`v3/rollback/hejo.app` 해시와 서명을 재확인한다. 다른 작업이 설치본을 바꿨으면 덮어쓰지 말고 보고한다. 설치 전 PID·CPU·3초 sample을 `live/`에 저장한다. 개인 경로를 포함할 수 있는 원시 표본은 추적하지 않는다.
2. 현재 앱의 미전송 초안·첨부·전송 대기 보존을 확인한다. 초안은 메모리에만 있으므로 정상 종료도 자동 보존을 보장하지 않는다. 안전한 확인이 불가능하면 사용자에게 초안 보존 여부를 물어 input으로 기다린다. 이 조건을 빼거나 실수로 메시지를 전송해서 비우지 않는다. 자동 로그인 설정에 따른 기존 로그아웃 동작도 우회하지 않는다.
3. 보존 확인 뒤 앱만 정상 종료한다. 종료되지 않으면 강제 종료하지 않고 보고한다. 백업을 유지하며 새 후보로 로컬 설치 번들을 교체하고 정상 실행한다. 이는 이 인계가 허가하는 범위이며 별도 운영 게이트웨이 재시작·설정 변경은 허가하지 않는다.
4. 실행 경로·PID·설치 바이너리/BuildInfo가 검토된 후보와 일치하는지 확인한다. 기존 연결과 기록이 유지되는지 관측한다. 로그인 사용자 조작이 필요하면 비밀값을 다루지 말고 사용자 입력을 기다린다.
5. 실제 표시된 앱에서 입력·스크롤·직접방/홈 전환을 반복 관측한다. 시험 입력은 보내지 않고 원래 초안을 보존한다. 동작별 성공 여부·관측 방식·조건·CPU 및 3초 sample을 남긴다. 자연 수신이 있을 때 반응도 관측하되 시험 메시지를 보내지 않는다. 운영 수신 빈도를 측정하지 못하면 미확인으로 명시한다. 합성 시험이나 CPU 저하만으로 실제 앱 통과를 선언하지 않는다. GUI 관측 수단이 없으면 설치 사실과 미검증을 구분하고 사용자 실사용 확인을 요청한다.
6. 새 앱이 시작되지 않거나 동작이 악화되면 새 초안 보존 후 정상 종료하고 백업 번들을 복원·정상 실행한다. 복구 해시를 확인한다. 게이트웨이·설정·대화 기록은 그대로 둔다.
