# 공개 스냅샷 푸시 지원 보완 계획

상태: 2026-11-23 사용자 “진행”으로 별도 플러그인 보완 승인. HEJO 제품·공개 후보는 보존한다. 이번 구현 경계는 플러그인의 격리 구현·시험·커밋·검토 요청이며 운영 반영과 원격 푸시는 후속 검토 뒤다.

## 원본·소유·범위

대상은 Paseo 시설 저장소의 `plugin/role-workflow`다. 확인한 기준 커밋은 `8c620391b013cbf52e24ed2b1e3a9afd84820b48`. 해당 저장소 AGENTS.md와 docs/ARCHITECTURE.md를 따른다. 활성 운영 checkout은 깨끗하지만 직접 편집하지 않는다. 같은 저장소의 별도 worktree/브랜치에서 작업한다. HEJO worktree에 플러그인 코드를 넣지 않는다. 현재 작업의 공식 기획 문서 원본은 이 문서이며 구현 보고는 공식 작업 폴더의 `plugin-impl-report.md`로 구분한다. 플러그인 저장소에는 자체 변경 문서로 필요한 계약·시험 결과를 남기되 운영 절대 경로와 개인값을 넣지 않는다.

소유 칸은 기존 공항 시설/위험 행동 집행이다. 계약 원본은 기존 shared 스키마, 실행 주체는 기존 server managed push, UI는 기존 승인 화면이다. 준비·승인·복구 기록은 기존 사물함의 workflow/managedPush 기록에 넣고 제2 상태 파일·별도 푸시 실행기를 만들지 않는다. 수명은 해당 승인 기록과 같다. 새 기능 점검표: 기존 칸 확장, 본체/금고/계정 설정 중복 없음, 개인값은 런타임에만 존재, 업데이트·롤백이 작업 기록을 지우지 않음, 개발·운영 분리 유지.

승인 경계·원격 쓰기 집행 변경이므로 고위험으로 취급한다. 구현에 참여하지 않은 다른 모델의 검토 및 설계와 독립된 추가 검토 조건을 충족하기 전 운영 반영/최종 완료로 판정하지 않는다. 검토자 지정은 호스트와 사용자 선택을 따른다. 이 조건은 구현·격리 시험 착수를 막지 않는다.

## 계약과 변경 경로

1. 기존 PushTarget의 기본 동작은 유지하고 명시적 선택 속성 `snapshot: { developmentCommit: <전체 해시> }`를 추가한다. `commit`은 공개 커밋이다. 스키마·구조화 응답 파서·저장/복구·ManagedPush·승인 키·UI·규칙 인계까지 같은 계약을 전달한다. 경로나 HEJO 이름으로 자동 감지하지 않는다. 전역 검사 생략 옵션은 금지한다. 필드가 없는 과거 기록은 기존 일반 푸시로 동작한다.
2. snapshot 모드에서만 기준 검사를 분리한다. 동일 저장소/객체 형식/실행 worktree를 검증하고 developmentCommit이 배정 개발 HEAD와 일치하며 현재 로컬 기준 main을 포함하는지 확인한다. 공개 commit과 developmentCommit의 전체 Git tree가 정확히 같아야 한다. 실제 원격 tip은 공개 후보의 단일 부모여야 한다. 이미 원격에 포함된 동일 후보 재확인은 성공을 읽기 검증하며 부모 조건 때문에 재푸시하지 않는다. 추적 tip·실제 tip은 공개 이력에서 확인한다. 원격 불일치·빈 원격·조회 실패·tree 불일치는 거절하고 일반 경로로 fallback하지 않는다.
3. 준비와 실행 직전에 위 조건을 모두 재검증한다. 승인 키/epoch에는 snapshot 모드와 developmentCommit도 포함한다. 개발 commit/공개 commit/목적지/모드 변경과 원격 선행은 기존 승인을 사용할 수 없어야 한다. 저장된 예전 prepared 기록의 불완전한 확장 필드는 거절하고 새 준비를 요구한다. UI 승인 이후 실행이라는 기존 경계를 그대로 둔다.
4. 승인 화면에 공개 대상·공개 전체 커밋·대응 개발 커밋·tree 검증·개발 checkout 유지 방침을 표시한다. 작업 문서·규칙도 기본 푸시와 스냅샷을 구분한다. 규칙을 바꾸면 rules:sync 생성물도 갱신한다. shell push 차단과 원격 주소 검증은 그대로 유지한다.
5. snapshot 성공 뒤 integrateWorktree는 planner checkout을 공개 commit으로 ff-only하지 않는다. 이번 범위에서는 개발 checkout·브랜치·worktree·증거를 모두 보존하며 자동 정리를 건너뛴 사실을 명확히 표시한다. 정상 통합이 된 것처럼 integration.ok를 꾸미지 않는다. cleanup/recovery/recheck/수동 archive 경로에서도 보존 정책을 유지한다. 일반 푸시의 기존 통합/정리 경로는 유지한다.
6. 승인된 요청에 의한 실행만 기존 ManagedPushRunner가 담당한다. 구현 에이전트는 실제 원격 쓰기·승인 RPC를 호출하지 않는다. 검사 약화, 상태 JSON 수동 편집, unrelated merge, remote 설정 변경으로 해결하지 않는다.

## 수락 시험

- AT-PS-01: 별도 개발/공개 이력의 같은 tree·원격 부모 후보가 준비되고 승인 화면에 두 커밋이 정확히 표시된다. 과거 snapshot 없는 대상은 기존 동작과 같다.
- AT-PS-02: tree 한 파일 변조, 다른 저장소 개발 commit, 개발 HEAD 불일치, 기준 main 미포함, 잘못된 부모/다중 부모, 조회 실패를 각각 거절한다. 검사를 제거한 변이로 핵심 거절 시험이 실패함을 확인한다.
- AT-PS-03: 준비 후 개발/공개/모드/원격 변경 시 오래된 승인으로 실행하지 않는다. mode 제거로 일반 경로를 타도 우회되지 않는다. 중복 실행·재시작/저장 복구·이미 원격 포함 재확인을 검증한다.
- AT-PS-04: 실제 fixture Git 저장소에서 개발과 공개 이력을 분리해 준비→사용자 승인 모사→격리 runner→확인 흐름을 시험한다. 테스트 임시 bare remote 외 운영 원격을 사용하지 않는다. 실제 외부 푸시는 에이전트가 실행하지 않는다.
- AT-PS-05: snapshot 성공/복구/재검사 뒤 planner HEAD·개발 branch/worktree·증거가 그대로다. 기존 일반 푸시 ff-only와 cleanup 회귀를 검사한다. 미통합 상태가 잘못 완료/정리로 표기되지 않아야 한다.
- AT-PS-06: 넓은/좁은 승인 화면에서 두 대상의 차이와 오류를 확인한다. 코드 검사만으로 UI 성공을 대신하지 않는다. 기존 화면 시험 패턴과 가짜 입력을 쓴다.

필수 검사는 저장소 기준 `npm test`, `npm run typecheck`, `python3 -m unittest discover -s scripts -p 'test_*.py'`, 상태 저장/복구 변경에 따른 `npm run e2e`, `python3 scripts/privacy_scan.py --staged` 및 diff 검사다. 운영 홈·운영 작업 상태를 fixture로 쓰지 않는다. 실패를 skip이나 예산 완화로 감추지 말고 실제 종료 코드·로그·커밋을 보고한다.

## 구현 경계와 후속 적용

P1: 원본 저장소/활성 경로/기준·동시 변경 확인, 격리 worktree 준비, 해당 AGENTS/HANDOFF 준수.
P2: 계약→검증→승인 화면→통합/정리/복구를 기존 경로에서 수정하고 수락 시험 실행.
P3: 관련 변경만 커밋하고 diff·검증·한계·실제 UI 결과 및 운영 반영/롤백 절차를 보고. 이 단계는 운영 플러그인 등록·reload·데몬 재시작·업데이트 설정 변경을 하지 않는다.
P4(후속 검토): 독립 검토 통과 후 운영 적용 방식을 확정한다. 원본/운영 분리를 지키고 공식 plugin reload 경로를 쓰며 데몬 재시작은 하지 않는다. 호스트 흐름이 유지되는지 확인한 뒤 HEJO 후보를 재검증하고 플러그인 화면 푸시 승인을 받는다. 플러그인 코드의 원격 반영과 HEJO 공개 승인은 별도 대상이다.

유지할 HEJO 공개 후보는 `740f5be61f0f9826eae991039992fb17a57788f2`, 개발 커밋은 `b2e485110b49f6ed5c19d5e9c32b11ba2d46b079`, tree는 `0857b4a1d84611c27d9cebe29119de4e7e241d90`이다. 이를 플러그인 코드·시험에 고정하지 않고 검토 인계 값으로만 쓴다. 본 계획/보고 때문에 후보를 재생성하지 않는다.

참고: [Paseo plugin reference](https://paseo.sh/docs/plugins/reference.md), [quickstart](https://paseo.sh/docs/plugins.md). 설치된 저장소 계약을 기준으로 구현하며 새 SDK API가 필요하지 않으면 의존성을 올리지 않는다.
