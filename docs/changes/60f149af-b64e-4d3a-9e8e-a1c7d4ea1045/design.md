# 설계 v3

칸 배치·범위·기준은 [spec](spec.md)이 원본이다.

## 경로와 변경

변경 전(최초 조사): GateClient 수신·순서 검사·저장 → Controller.receive → Model.apply → model.onChange → 화면 refresh → Controller의 추가 notifyChange → 화면 refresh.

변경: 기존 메인 액터와 프레임 순서 그대로, Controller의 기존 performUpdates로 프레임 처리의 화면 통지를 하나의 동기 transaction으로 통합한다. 저장·모델 적용·오류·전송 확인 부작용은 생략하지 않는다. 전용 응답과 조기 return도 조사하고 transaction 경계에 맞춘다. 전역 notifyChange 의미를 바꾸지 않는다.

refresh가 소비할 파생 데이터는 기존 모델 책임 안에서 한 동기 조회 범위에 한정해 재사용한다. room notices와 스레드별 timeline·assessment 재사용을 TASK-02 필수 범위로 한다. notices 정렬 비교자와 originalSeq도 같은 timeline 결과를 소비하여 비교마다 전체 messages를 다시 필터·정렬하지 않는다. 실제 비용은 수정 전후 계측한다. 조회 중 모델 상태가 바뀔 수 있는 지점을 조사하고, 변경이 발생하면 파생값을 폐기하거나 변경 후 새 범위를 시작한다. 명시적 now와 기본 noticeClock을 섞지 않고 한 조회 범위의 시간은 일관되게 취급한다. 다음 렌더에는 새 시간·상태를 사용한다.

파생값은 모델 원본을 대체하지 않는다. 새 디스크 캐시·전역 무기한 날짜 캐시·버전 장부를 만들지 않는다. 계산 최적화에 장기 캐시나 비동기 처리 변경이 필요하면 구현을 확대하지 말고 설계로 돌려보낸다.

| 기존 경로 | 판정 | 이유 |
|---|---|---|
| GateClient, LocalStore 수신 순서·영속 기록 | 유지 | 성능 수정으로 자료 계약을 바꾸지 않음 |
| receive 중 여러 화면 통지 | 통합 | 기존 performUpdates의 동기 종료 계약 활용 |
| 렌더 안 같은 방의 notices 반복 도출 | 교체 | 한 갱신 범위의 도출 결과 공유, 중복 경로 제거 |
| ThreadAssessment·ThreadTools.date의 판단 의미 | 유지 | 질문·날짜 해석 결과 보존 |
| 타이머·스트리밍 reveal·열기/닫기 transaction | 유지 | 현재 화면 및 애니메이션 계약 |

## 대안

- 채택: 동기 transaction과 렌더 범위 파생값 공유. 기존 메인 액터·저장 흐름을 유지하며 확인된 중복을 제거한다.
- 기각: 모든 onChange를 시간 기반 debounce로 지연. 열기 애니메이션 캡처 전에 동기 렌더되어야 하는 기존 시험과 충돌한다.
- 기각: 계산을 바로 백그라운드로 이동. 상태 순서·동시성 위험이 커지고 중복 계산 자체가 남는다.

## 위험·복구

일반: UI 버그 수정, 동기 호출 순서와 저장·권한은 유지한다. 비동기/동시성 또는 저장 계약을 바꾸면 고위험으로 재분류 후 재설계한다. 주요 위험은 조회 중 상태 변화 및 알림 시간 경계의 오래된 결과이며 AT-HP-03으로 검증한다. 별도 계획 검증은 호스트에서 사용자가 고른 설정을 따르며 본 문서가 임의 활성화하지 않는다.

필요 증거: 수준 1 빌드, 수준 2 가짜 통합·회귀, 수준 3 실제 macOS AppKit 실행, 수준 4 실제 설치 앱 응답성 관측. 배포 전 기존 앱 번들을 로컬 백업하며 새 앱 문제 시 이전 번들로 복귀한다. 기록장·설정은 건드리지 않는다. 설치/재실행은 검증된 산출물과 복구 경로를 제시한 뒤 진행하며 강제 종료로 미전송 초안을 잃지 않는다. 운영 게이트웨이는 재시작하지 않는다.

## TASK-01A 뒤 확정한 렌더 범위

직접방의 replyButton 계산에서 홈 스레드 조회를 먼저 수행하는 경로를 제거한다. 홈 여부를 먼저 분기하고 현재 방에 필요한 계산만 수행하되 버튼 활성화 결과는 유지한다. 홈 화면에서는 homeThreads의 스레드별 최신 날짜 정렬 키를 한 동기 범위에서 도출해 공유하고 기존 날짜·ID 타이브레이커를 보존한다. 같은 범위에서 전체 메시지의 스레드별 분류를 재사용하여 timeline마다 전수 순회를 반복하지 않는다. notices·assessment·날짜 키도 이 범위에 귀속하고 범위 종료/상태 변경 시 폐기한다. 원본 의미·시간·무효화 계약은 위 경로를 따른다.

별도 장기 캐시나 신규 서비스 없이 기존 Model의 파생 조회와 View의 분기 책임에서 해결한다. 사용자에게 보이는 결과는 그대로 두고 필요 없는 계산을 없앤다. ddots의 내부 구현은 소스 접근 실패로 검증되지 않았으며 그 구조를 추측해 복제하지 않는다.
