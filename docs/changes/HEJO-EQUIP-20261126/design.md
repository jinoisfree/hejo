# HEJO-EQUIP 근간 개정안: 직원 · 가이드북 · 도구 창고

- 상태: 개정안 2판 · 승인(2026-11-27) · 적용(0~4단계, 2026-11-27)
- 1판(가이드북 → 상자 → 기본 도구 3층, `a702e05`)은 사용자가 "너무 복잡하다"고 해서 대체한다.
- 진행 방식: 연합개발. 근간 개정은 사용자 결정 사항이다(15-design-guide 3절).
- 출발점: [HEJO-REF-PHOTO brainstorm "추가 요청"](../HEJO-REF-PHOTO-20261126/brainstorm.md), [HEJO-REF-PHOTO verdict T-1](../HEJO-REF-PHOTO-20261126/verdict.md)

## 1. 사용자 구상과 결정
- 구상(2026-11-26, 사용자): "직원이 있고, 도구가 있고, 가이드북이 있다. 직원은 일을 할 때 가이드북(스킬)을 찾아보고, 도구 창고의 도구 목록에서 필요한 도구를 찾아, 창고에서 가져와 조합해 실현한다."
- 결정 유지: 코드의 직책 질문은 단계적으로 옮긴다. Hermes 기본 도구는 도구 창고 칸(팩)이 선언한다. 팩 도구 목록의 원본은 `pack.yaml`이다(에이전트 선택, 사용자 위임).
- 1판의 "명부의 장착 목록"은 2판에서 "명부의 출입증"으로 바뀐다. 직원이 미리 들고 있는 것이 아니라, 들어갈 수 있는 창고 칸을 뜻한다.

## 2. 한 줄 구조
**직원(성격 + 출입증) → 일이 생기면 가이드북(스킬)을 펼친다 → 도구 목록에서 찾는다 → 출입증이 있는 칸에서 꺼내 쓴다.**

```
직원 ──일──▶ 가이드북(스킬): "낙화 확인은 cctv_now, 자세히 보려면 cctv_zoom"
         ──▶ 도구 목록 검색 ──▶ 도구 창고 [cctv 칸] 에서 꺼내 씀
                                   └ 출입증에 cctv 칸이 있어야 열린다
```

## 3. Hermes에 이미 있는 것 [확인]
| 구상의 부분 | Hermes 기능 | 근거 |
|---|---|---|
| 가이드북을 펼친다 | 스킬: 일과 관련된 스킬을 그때 읽는다 | 직원 `skills/`(조립 결과), 원본은 매뉴얼 서가 |
| 도구 목록에서 찾는다 | Tool Search `tool_search` | `hermes-agent/model_tools.py` `_compute_tool_definitions` |
| 창고에서 꺼내 쓴다 | `tool_describe` → `tool_call` | 같은 곳. 플러그인·MCP 도구만 미룬다. 기본(core) 도구는 미루지 않는다 |
- 현재 설정: 직원들의 `config.yaml`에 `tools.tool_search` 칸이 있다. 담당 직원 한 명은 `enabled: 'off'`이고, Hermes 기본값은 `auto`(도구가 문맥 한도의 5%를 넘으면 켜짐)다.

## 4. 칸 (개정 후)
| 다루는 것 | 칸 | 원본 위치 | 쓰기 주체 | 수명 |
|---|---|---|---|---|
| 직원 | 직원 명부·성격 | `owner/team.yaml`(이름·별칭·연결 앱), `soul/personas/` | 사장 | 영구 |
| 출입증: 직원이 들어갈 수 있는 창고 칸 목록 | 직원 명부 | `owner/team.yaml` 직원별 `access`(새 키, `roles` 대체) | 사장(앱 경유) | 영구 |
| 가이드북 = 일하는 방법(어떤 도구를 쓰는지 적힘) | 매뉴얼 서가 | `roles/<칸>/skills`, `shared/secretary-skills` — 칸 이름 아래로 정리 | 개발 | 갱신 때 교체 |
| 도구 창고 칸: 도구·필요한 기본 도구·그 칸의 가이드북 위치 | 도구 창고 | `hermes_packs/<칸>/pack.yaml`(`tools`, 새 키 `core_toolsets`) | 개발 | 갱신 때 교체 |
| 도구 목록표 | 조립 결과 | `hermes_packs/catalog.json` — 모든 `pack.yaml`에서 생성, 검사가 어긋남을 잡음 | 생성기 | 다시 생성 |
| 직원 설정의 도구 범위 | 조립 결과 | 직원 `config.yaml`의 팩 목록·`platform_toolsets` — 출입증에서 생성 | 조립기 | 다시 생성 |
| 도구 검색 켜기 | 사장 지시서 | `owner/policy.yaml`(키 이름은 3단계 설계), 조립기가 직원 설정에 반영 | 사장 | 영구 |
| 멘션 없는 새 글의 기본 담당 | 사장 지시서 | `owner/policy.yaml` 경로 결정 | 사장 | 영구 |
| 직책 | 저장하지 않음 | 코드는 "이 칸 출입증이 있나"만 묻는다 | — | — |

칸 이름은 일의 단위다. 도구가 있는 칸(cctv, mail, calendar…)도 있고, 범위 규칙과 가이드북이 중심인 칸(개인 비서, 회사 비서, 진단…)도 있다. 지금 직책 이름 personal·work·doctor·customers·sns·wiki·standby는 같은 이름의 칸이 된다. 도구가 없는 칸은 가이드북과 범위 규칙만 가진 칸이다.

원칙 문장(두 근간에 넣을 것): **직원은 성격과 출입증만 가진다. 일은 가이드북을 보고, 도구는 출입증이 있는 창고 칸에서 그때 꺼낸다. 직책은 저장하지 않는다.**

## 5. 실측 [확인] 2026-11-26
1. "누가 무엇을 가졌나"가 지금 세 곳에 있다. 명부 `roles`·`apps`와 직원 `config.yaml`의 `packs.enabled`(조립 결과)다. 팩 목록이 없는 직원은 팩 필터가 꺼져 모든 팩 도구가 등록되고, 코드의 직책 검사가 실제로 막는다(예: cctv 도구는 `home_has_role(home, 'customers')`).
2. 직책 질문 함수 호출(시험 제외): `has_role` 158, `first_with` 54, `home_has_role` 46, `home_of_role` 41, `agents_with` 8, `roles_of` 2, `role_hint` 2. 명부 `roles`를 직접 읽는 파일 7개, 조립기 3개, 시험 58개 파일.
3. Hermes 기본 도구 목록(`platform_toolsets`)은 직원 `config.yaml`에만 있고 원본 칸이 없다.
4. 팩 도구 목록이 `pack.yaml`과 `catalog.json` 두 곳에 있다.
5. hejo 앱·문·허브는 명부 `roles`를 읽지 않는다.

## 6. 단계 (각각 따로 계획·검증·적용)
| 단계 | 내용 | 동작 변화 | 위험도 |
|---|---|---|---|
| 0 근간 반영 | 두 근간 문서에 4절 칸과 원칙 문장 반영, ADR | 없음(문서) | 경미 |
| 1 도구 목록 단일 원본 | 모든 칸의 `pack.yaml`에 `tools`, `catalog.json`은 생성, 어긋나면 검사 실패 | 없음 | 일반 |
| 2 출입증 이관 | 명부 `roles` → `access`. `team_registry`가 출입증으로 기존 직책 함수에 같은 답을 준다. 직접 읽는 7곳·조립기 3개는 `team_registry`를 거친다. 멘션 없는 새 글 담당은 지시서로. 시험 명부도 이관. 옛 키는 이관 뒤 거부 | 없음(답 동일) | 고위험 |
| 3 출입증 → 직원 설정 조립 | `pack.yaml` `core_toolsets` 선언. 조립기가 출입증에서 직원 `config.yaml`의 팩 목록·기본 도구 목록을 만든다. 도구 검색 켜기는 지시서 값으로. 지금 값과 다른 부분은 차이 표를 사장 승인 뒤 적용 | 직원별 도구 범위 정리 | 고위험 |
| 4… 칸별 질문 전환 | 칸마다 "직책이 X인가"를 "X 칸 출입증이 있나"로(예: cctv 등록) | 칸별 | 칸별 |

## 7. 대안과 기각
- 1판(가이드북이 상자를 부르고 상자가 기본 도구를 부르는 3층): 사용자가 복잡하다고 해서 기각했다.
- 출입증 없이 모든 직원이 모든 칸을 연다: 고객 응대 직원이 메일 발송·터미널을 꺼낼 수 있어 기각했다.
- 직원에게 도구를 미리 장착: 도구 검색이 이미 있어 필요 없고, 직원 설정만 무거워져 기각했다.

## 8. 순서·겹침
- 운영 저장소의 팩 이관 작업(판정 "보류")이 같은 파일(`catalog.json`, `__init__.py`, 팩 폴더)을 건드리므로, 1단계는 그 작업이 끝나거나 접힌 뒤 착수한다.
- 0단계는 문서만 바꾸므로 승인 뒤 계획 담당이 직접 한다.

## 9. 열린 질문(각 단계 설계 때)
- 칸 이름 정리: 지금 직책 이름을 칸 이름으로 그대로 쓸지(2단계).
- 배경 작업(예약·감시)의 담당 직원: 그 칸 출입증을 가진 직원 중 누구인지 정하는 규칙(2단계).
- 도구 검색을 기본으로 켤지, 직원별로 정할지(3단계, 사장 지시서).
