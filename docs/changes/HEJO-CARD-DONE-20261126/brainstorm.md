# 브레인스토밍 결정 요약 — 가운데 칸 카드 한 번에 종결(✓ 띠)

- 목적: 사장이 이미 봤지만 답할 필요는 없는 카드(예: "재확인: 지금 낙화 진행중")를 가운데 칸에서 클릭 한 번으로 종결한다.
- 하는 것: 답 요청 카드와 마감 카드에 마우스를 올리면 카드 오른쪽 끝에 초록 띠(✓)가 나온다. 답 요청 카드는 5초 되돌리기 뒤 직원에게 "확인" 글을 보내고, 마감 카드는 기존 "완료로 닫기"(5초 되돌리기)를 한다.
- 하지 않는 것: 알림 카드 버튼, 문(gate)·안내판(통신 규격)·직원 규칙 변경, 새 저장 항목, 대화 안 "확인" 버튼 동작 변경, 앱 버전 빌드·배포(별도 릴리스 작업).

1. 새 칸·두 번째 원본 없음. 기존 전송·마감 닫기 경로를 다시 쓴다.
2. 사장이 누를 때만 쓴다. 시설 코드가 스스로 쓰지 않는다.
3. 갱신·제거는 앱 코드만 교체. 기록장·마감 장부는 6절 보존 규칙 그대로.
4. 개인값 없음(시험은 가짜 명부).
5. 다른 사장의 공항에서도 코드 수정 없이 같은 방식으로 동작한다.

- 실측 [확인] (`github/main` `018036c`):
  - 마감 카드는 우클릭 "완료로 닫기/취소로 닫기"와 5초 지연 전송·되돌리기 줄이 있다(`ConversationController.swift:69-82`, `TodoDrawerView.swift:91-98,117-124`).
  - 답 요청 카드는 클릭하면 대화로 이동할 뿐 종결 수단이 없다. 현재 명세 REQ-AS-01: "답 요청 카드는 답해야 빠진다".
  - 문은 사장 글이 스레드 마지막이면 카드를 내리고(`gate/history_queries.py:151`), 사장의 일반 답 뒤 직원 글이 오면 완결(settled, 초록)로 본다(`history_queries.py:52-75`, HEJO-THREAD-DONE).
  - 대화 안 "확인" 버튼(직원 버튼 없는 요청)은 글을 보내지 않고 `confirm:` 표시만 남긴다(`ConversationView.swift:1494`).
- 선행 조사: 외부 도구·오픈소스 해당 없음(앱 안 기존 부품 재사용).
