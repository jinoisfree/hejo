# HEJO-BUBBLE-WIDTH 명세

- 2판(계획 검증 1회차 반영, [plan-review.md](plan-review.md)) · 2026-11-26 · 상태: 적용(공개판 커밋, 푸시 승인 대기) · 승인(사용자 결정 D-01·D-02, [tasks.md](tasks.md)) · 대상: 공개판 `github/main`(설계 기준 `2dea766cbdbd5e179a6269aabbfefc750036b219`)
- 칸 표와 점검표 답: [design.md](design.md) 1절.

## 1. 문제
채팅에서 긴 글 말풍선이 반대쪽 사진 자리 바로 앞까지 찬다. 두 줄 이상인 글은 가장 긴 줄이 짧아도 최대 폭으로 그려져 말풍선 안 오른쪽이 빈다.

## 2. 목표와 범위
- 범위 안: 채팅·스레드의 글 말풍선(내 글, 직원 글, 답글, 이어 쓴 글, 써지는 중인 글)의 최대 폭과 폭 맞춤.
- 범위 밖: 시간·이름·사진 배치, 색·모서리·안쪽 여백, 알림 줄·묶음·첨부 같은 말풍선 밖 요소, 설정 창 미리보기, 앱 배포·설치.

## 3. 용어
- 글 칸 폭 `C` = 카드 폭 − 양쪽 카드 여백 − 사진(34) − 사진 간격(9). 지금 배치의 `columnWidth`와 같다.
- 최대 말풍선 폭 `B` = `min(C, max(240, 0.75 × C))`. 말풍선 바깥 폭 기준이다.
- 안쪽 최대 폭 = `B − 24`(안쪽 여백 12 × 2).
- 자동 줄바꿈 = 글쓴이가 넣은 줄바꿈이 아니라 안쪽 최대 폭에 다 들어가지 않아 생긴 줄바꿈.

## 4. 요구와 수락 기준

### REQ-BW-01 최대 폭과 같은 여백
말풍선 바깥 폭은 `B`를 넘지 않는다. 내 글과 직원 글은 같은 식을 쓴다.
- AC-01(정상): Given 같은 카드 폭에서 자동 줄바꿈이 생기는 긴 내 글과 긴 직원 글, Then 두 말풍선 폭은 모두 `B`이고, 내 글은 글 칸 오른쪽 끝에, 직원 글은 글 칸 왼쪽 끝에 붙는다. 그래서 반대쪽에 남는 폭이 둘 다 `C − B`로 같다.
- AC-02(경계): 카드 폭이 바뀌면 `B`도 새 폭으로 다시 계산된다. 화면에 떠 있는 대화 목록의 폭을 바꿔도(창 크기 변경) 이미 보이는 같은 카드의 말풍선이 새 `B`로 다시 그려진다.
- AC-03(경계): `0.75 × C < 240`이면 `B = min(C, 240)`이다. `C < 240`이면 `B = C`다.

### REQ-BW-02 가장 긴 줄에 맞춤
- AC-01(정상): Given 줄바꿈이 글쓴이가 넣은 것뿐이고 모든 줄이 안쪽 최대 폭보다 짧은 두 줄 이상 글, Then 말풍선 폭 = 가장 긴 줄의 폭 + 24이고 `B`보다 작다(AC-05·06이 먼저다). 줄 수와 높이는 최대 폭으로 그렸을 때와 같다(줄이 더 꺾이지 않는다). 내 글·직원 글 모두 같다.
- AC-02(보존): 한 줄 글은 지금처럼 글 길이에 맞춘다.
- AC-03(경계): 자동 줄바꿈이 하나라도 있으면 말풍선 폭은 `B`다.
- AC-04(경계): 표 또는 코드 상자가 든 글은 말풍선 폭이 `B`다. 표·코드는 안쪽 폭 안에서 줄을 바꾸고 가로 스크롤이 없다(기존 규칙 유지).
- AC-05(우선순위): 직원 글의 "더 보기/접기" 글자는 지금처럼 말풍선 안에 다 들어간다. 이 조건이 가장 긴 줄 맞춤보다 먼저다. 접기 글자가 가장 긴 줄보다 넓으면 말풍선 폭 = 접기 글자 폭 + 24(지금 배치가 두는 여유 2pt 포함 가능)이고, 어느 경우에도 `B`를 넘지 않는다.
- AC-06(경계): 왼쪽 정렬이 아닌 문단(가운데·오른쪽·양쪽 정렬)이 하나라도 있는 글은 말풍선 폭이 `B`다. 좁히면 줄 시작 위치가 달라지기 때문이다.

### REQ-BW-03 써지는 중의 폭
- AC-01(정상): Given 같은 카드 폭에서 써지는 중인 같은 글이 이어서 다시 그려질 때, Then 말풍선 폭은 앞서 그린 폭보다 줄지 않는다.
- AC-02(경계): 다 써진 글은 REQ-BW-01·02의 폭을 그대로 가진다(써지는 중의 폭을 남기지 않는다). 카드 폭이나 글씨 크기가 바뀌면 앞서 그린 폭은 버린다.

### NFR-BW-01 원본 하나
최대 폭을 정하는 숫자와 식은 앱 안에 한 곳만 있다. 대화 영역 폭에 0.82를 곱해 넘기던 경로는 남기지 않는다.

### NFR-BW-02 회귀 없음
기존 시험이 새로 실패하지 않는다. 옛 폭 규칙을 그대로 적어 둔 기대값만 새 규칙으로 바꿀 수 있고, 바꾼 것은 구현 보고에 전·후 값으로 적는다.

## 5. 실패 후 상태
저장하는 자료가 없다. 잘못되면 화면 배치만 틀리고, 커밋을 되돌리면 모두 복구된다.
