[확인] ConversationView.textDidChange는 홈에서 매번 refresh를 직접 호출한다(886–892행). refresh는 사이드바·스레드·카드·서랍·전체 레이아웃 갱신까지 수행한다(574–699행). setText 자체는 전체 통지를 하지 않는다(ConversationController.swift:479). [가정] 이 불필요한 동기 갱신이 입력 지연의 원인 중 하나다. 실제 지연과 설치 앱의 코드 일치는 아직 미측정이다.

범위: AppKit 입력 이벤트의 불필요한 전체 갱신 제거, 영향받는 표시와 입력 의미 보존, 실제 View를 통한 전후 검증. 통신·저장 형식·수신 스케줄링·서버·새 UI 설계·운영 설정 변경은 제외.

지연 예산은 기존 [HEJO-PERF](../../../tests/acceptance/HEJO-PERF.md)의 입력 예산을 재사용하며 현재 달성값이 아니다. 완료에는 자동 회귀, 빌드, 개인값 검사 및 실제 AppKit 입력 관측 증거가 필요하다. 설치 앱 교체는 검증 후보와 초안 보존·롤백을 검토한 후 별도 인계한다.

AC-02의 버튼 조건 통일은 기존 refresh의 조건을 기준으로 입력 직후 공백 초안에서만 버튼이 활성화되던 불일치를 수정하는 작은 의미 변경이다. 실제 sendCurrent의 공백 전송 거부는 유지한다. 이 수정도 계획 승인 범위에 포함한다.

검토 후 구현 기준 통합과 계측 순서는 design v3을 따른다. 요구·수락 기준·지연 예산은 v2와 동일하다.
