## 문제
직원이 작업 중에 파일을 먼저 보내면 답글 칸에 "얼굴·이름 + 파일" 글이 생기고, 그 아래 입력 중 표시가 같은 얼굴·이름을 한 번 더 그린다. 같은 직원이 둘로 보인다. 최종 답도 얼굴·이름을 또 단다.

## 목표
같은 직원이 답글 칸에 연달아 낸 것은 처음부터 끝까지 얼굴·이름 한 번 아래 이어서 보인다.

## 범위 밖
문(gate)·기록·프로토콜, Hermes 본체, 사장 글(말풍선), 스레드 첫 글(top) 영역의 표시, 작업 줄(`WorkingControlRow`) 모양, 펫·알림.

## 용어
- **답글 칸:** `threadContent`가 만드는 `replies` 조각 목록. 스레드 첫 글(top)은 포함하지 않는다.
- **바로 앞 답글:** 스레드 타임라인(`controller.timeline(key)`의 첫 글을 뺀 `replies`)에서 이 답글 바로 앞 원소. 접힘으로 그 원소가 화면에 없으면 "없음"으로 본다.
- **같은 직원:** 두 메시지 모두 `role != "owner"`이고 `speaker`(직원 id)가 같음.

## 요구와 수락 기준
**REQ-PG-01 연속 답글 묶기**
- AC-01(정상): 바로 앞 답글이 같은 직원인 답글의 글(`Post`)은 `continuation == true`(얼굴·이름·시간 줄 없음). 연속 묶음의 첫 답글은 `false`.
- AC-02(끊김): 사장 글, 다른 직원 글, "이전 답글 N개" 더미가 사이에 있으면 묶지 않는다. 사장 글은 늘 `false`.
- AC-03(경계): 스레드 첫 글이 같은 직원이어도 첫 답글은 `false`.
- AC-04(접힘): 접힌 스레드에서 보이는 두 답글이 타임라인상 붙어 있지 않으면 묶지 않는다.
- AC-05(버튼 나눔): 버튼으로 나뉘는 글(`ReplyButtonPolicy.split`)이 묶일 때 앞부분도 `continuation == true`, 뒷부분은 지금처럼 `true`.

**REQ-PG-02 작업 중 표시 묶기**
- AC-01(정상): 답글 칸 마지막 답글이 직원 A이고 A가 입력 중이면 A의 `TypingBubbleView`를 만들지 않는다. 작업 줄은 지금처럼 하나 있다.
- AC-02(끊김): 마지막 답글이 사장 글이거나 다른 직원 글이거나 답글이 없거나 "끼어들었어요" 줄이 있으면 A의 `TypingBubbleView`를 지금처럼 만든다.
- AC-03(생각 중 글): 답글 칸의 "생각 중" 글은 바로 앞 답글이 같은 직원이면 `TypingBubbleView`를 만들지 않는다(조각 없음). 아니면 지금처럼 만든다.
- AC-04(이어짐): 생각 중 글 바로 다음 같은 직원 글은 `continuation == true`. 생각 중 글이 같은 메시지 수정(`edit`)으로 본문이 바뀌어도 바로 앞 답글 기준은 같다(전환 중 이름 머리가 늘지 않음, AT-PG-13).

**REQ-PG-03 묶인 글의 시간**
- AC-01: `continuation == true`가 된 답글 글의 `textHelp`는 그 글의 시간 문자열(`Post.time`과 같은 값). 이미 체크박스 도움말이 있으면 그것을 유지한다. 묶이지 않은 글의 `textHelp`는 지금과 같다.

**REQ-PG-04 회귀 없음**
- AC-01: `bash scripts/test.sh`(HEJO_PYTHON=Hermes venv Python) 전부 통과, 기존 시험 기대값 수정 없음. `python3 scripts/scan_private.py` 통과.
