# HEJO-DISCORD 브레인스토밍 결정 요약

- 일시: 2026-11-24. 진행 방식: 연합개발, 계획 검증 켜기(사장 선택).
- 근간: [ARCHITECTURE.md](../../ARCHITECTURE.md). 앞선 작업: [HEJO-TELEGRAM](../HEJO-TELEGRAM-20261122/spec.md).

## 목적

헤르메스 → hejo → 디스코드. hejo가 원본이고 디스코드는 휴대폰(안드로이드 포함)에서 보는 무료 보조 창이다. 디스코드에 쓴 글은 hejo에 기록되고, hejo에 남은 글은 디스코드에도 보인다.

## 하는 것 · 하지 않는 것

- 한다: 디스코드 문(짝짓기·켜기·해제), 방마다 포럼 채널, hejo 스레드마다 포럼 글, 양방향 글·첨부, 직원별 이름 표시, 작성 중 표시, 앱 설정 구역, 서버 적용·실물 확인.
- 하지 않는다: Hermes 본체 수정, 디스코드에서 방 만들기, 과거 기록 되보내기, 보낸 뒤 고친·지운 글 반영, 버튼 누르기, 텔레그램 제거(아래 결정 — 별도 작업).

## 칸

[spec.md 첫 절](spec.md#칸원본쓰기-주체수명)이 원본이다. 요약: 문 코드는 공항 시설(`gate/`), 짝 정보는 사장 금고, 대응표는 공용 창고(`shared/hejo/discord`), 화면은 관제 화면. 새 칸·두 번째 대화 원본 없음.

## 사장 결정

- 무료, 안드로이드 필수, hejo 원본, 디스코드는 보조 창.
- 디스코드 채택(Slack보다 세팅 단순, 작성 중 표시).
- 진행: 연합개발, 계획 검증 켜기.
- 텔레그램: **디스코드가 안정되면 끈다.** 이번 작업에서는 텔레그램을 그대로 두고, 끄기·텔레그램 댓글 작업 정리는 별도 작업으로 한다.

## 에이전트 제안(계획에서 확정, 사장 확인 대상)

- 포럼 채널을 쓰려면 디스코드 서버의 "커뮤니티" 기능을 켜야 한다(디스코드 공식 안내). 준비 안내에 넣는다.
- 직원 이름 표시는 채널 웹후크(봇이 만든 것)로, 작성 중 표시는 봇 이름(`hejo` 권장)으로 나온다.
- 서버가 꺼져 있던 동안 디스코드에 쓴 글은 들여오지 않는다(알려진 한계, 이후 작업 후보).
- (계획 검증 1회차 뒤 추가) Hermes 디스코드는 hejo 전용 "닫힘 운영": Hermes가 디스코드 글을 직접 받지 않게 두고 hejo만 받는다. 그래서 디스코드로 Hermes 직원과 직접(1:1) 대화하는 길은 없다.
