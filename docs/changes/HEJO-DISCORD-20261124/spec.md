## 문제와 목표

- 문제: 사장은 안드로이드 폰에서 hejo 방을 본다. 텔레그램 창은 토픽 안 스레드가 조잡하다. Slack은 세팅이 복잡하고 작성 중 표시가 없다.
- 목표: 사장이 만든 디스코드 서버를 짝지으면 hejo의 쓸 수 있는 방마다 포럼 채널이 생기고, hejo 스레드마다 포럼 글이 생겨 그 방의 글(직원 글·앱이나 다른 창에서 쓴 사장 글)이 올라간다. 사장이 포럼에 새 글을 쓰면 그 방의 새 스레드, 글 안에 답하면 그 스레드에 사장 글로 기록된다. 원본은 hejo 기록장 하나다.

## 용어

- **쓸 수 있는 방:** 명부 직원의 1:1 방(id = 직원 id)과 삭제·보관되지 않은 단체방. HEJO-TELEGRAM과 같다(`Telegram.rooms()`).
- **짝지은 서버:** 짝짓기 코드를 받은 디스코드 서버(guild) 하나와 그 코드를 보낸 계정 하나(사장 계정).
- **방 채널:** `channels.json`이 그 방에 대응시킨 포럼 채널.
- **글 묶음:** 포럼 채널 안의 글 하나(디스코드 스레드). hejo 스레드 하나에 대응한다.
- **활성:** 짝지은 서버가 있고, 켜짐이며, 디스코드 문이 연결(`platform_ready`)돼 있고, hejo 기본 어댑터가 연결돼 있음.
- **남은 글·정착:** HEJO-TELEGRAM과 같다.
- **창:** hejo 기록장을 비추는 바깥 메신저(텔레그램, 디스코드). 창끼리 직접 주고받지 않는다.

## 범위

- 안: 디스코드 처리기 공장 등록(hejo 수신 듣기), 원래 처리기 닫힘 확인, 짝짓기·해제·켜기, 채널 동기화, 수신(새 글·글 묶음 안 답·첨부), 발신(직원 남은 글·다른 경로 사장 글·첨부, 직원 이름 표시), 작성 중 표시, 앱 설정 구역, 서버 적용·실물 확인.
- 밖: Hermes 본체·디스코드 플러그인 수정, 디스코드에서 방 만들기, 짝짓기 전 기록 되보내기, 서버가 꺼져 있던 동안의 디스코드 글 들여오기, 보낸 뒤 고치거나 지운 글 반영(양쪽 다), hejo 스레드 삭제의 디스코드 반영, 버튼 누르기, 직원 사진(웹후크 아바타), 텔레그램 끄기·텔레그램 댓글 작업 정리(별도 작업), 디스코드 1:1(DM) 대화의 hejo 기록.

## 제약

- Hermes 본체·디스코드 플러그인 무수정. 문은 `register_platform_handler("discord", 공장)` 계약만 쓴다(공장은 `(native=commands.Bot, adapter)`로 불림 — design 1절).
- **닫힘 운영:** Hermes 디스코드 플랫폼은 hejo 전용이며, 원래 처리기는 사람 글을 받지 않는 상태(디스코드 허용 사용자·역할·채널 없음, 디스코드·게이트웨이 전체 허용 꺼짐, 디스코드 짝 승인 없음)와 봇 글 허용 `none`으로 운영한다. 이때 원래 처리기는 본문 변경·자동 스레드·안내·첨부 수집 **전**의 들이기 판정에서 모든 글을 거부한다(design 1절). 문은 이 상태를 글마다 확인하며("닫힘 확인"), 열려 있으면 그 글을 hejo에 기록하지 않는다. 원래 처리기를 감싸지 않는다.
- 민감값 허용 위치:

| 값 | 나타나도 되는 곳 |
|---|---|
| 코드 평문 | 요청한 앱 연결의 `discord_code` 프레임 하나 |
| 코드 해시 | `discord.json` |
| 서버 id·사장 계정 id | `discord.json` 하나(다른 파일·기록장·앱 프레임·hejo 로그 0건) |
| 짝 표지(짝지을 때마다 새 무작위 8자) | `discord.json`, `channels.json`, `sent.jsonl`, 기록장 `client_msg_id`와 그것을 싣는 앱 `message` 프레임 |
| 채널·분류·글 묶음·디스코드 글 id | `channels.json`, `sent.jsonl`, 기록장 `client_msg_id`와 그것을 싣는 앱 `message` 프레임 |
| 웹후크 id·토큰 | 문 프로세스 메모리(파일·로그·프레임 0건) |
| 글 본문·파일 | 기존 대화 경로(기록장·첨부 저장소·앱 프레임)와 디스코드 발신 |

  로그 계약(NFR-HD-04) 범위: (가) hejo 문 로거의 모든 줄, (나) hejo가 이 기능 때문에 부르는 디스코드 호출(채널·분류·웹후크·글 묶음 만들기·이름 바꾸기·옮기기·웹후크 발신·작성 중)이 남기는 hejo 쪽 줄. 위 값은 하나도 나오지 않는다(종류 이름만). 디스코드 어댑터·discord.py가 원래 남기는 로그는 본체 동작이라 범위 밖이다.

## 요구

### REQ-HD-01 짝짓기

- AC-01(정상): 앱이 `discord_pair`를 보내면 요청한 연결에만 `discord_code`(12자, 72비트 무작위, 600초)가 온다. 새 요청은 이전 코드를 대체한다.
- AC-02(정상): 디스코드 문이 연결돼 있고, 서버 안 채널(글 묶음 포함)에서 사람 계정이 쓴 글 전체(앞뒤 공백 제외)가 유효한 코드이며, 닫힘 확인이 그 글에 대해 참이면 짝짓기가 된다(인증은 hejo 앱만 받을 수 있는 1회용 코드): 금고에 `{platform:"discord", guild_id, user_id, tag, paired_at}`이 쓰이고 코드는 쓰임으로 표시되며, 그 채널에 "연결됐어요"가 가고 상태가 방송된다. 켜짐은 바뀌지 않는다.
- AC-03(실패): 쓰인 코드, 만료된 코드, 틀린 글, 1:1(DM) 글, 봇·웹후크가 쓴 글, 닫힘 확인이 거짓인 코드 글은 짝짓지 않는다. 금고나 설정 파일을 읽을 수 없으면 짝짓지 않는다.
- AC-04(정상): `discord_unpair`는 짝과 코드를 지우고 켜짐을 끈다. `channels.json`은 남긴다(다시 짝지으면 새 표지라 쓰지 않음).
- AC-05(경계): 다시 짝지으면(같은 서버여도) 이전 짝을 대체하고 새 짝 표지를 뽑는다. 이전 표지의 채널·글 대응은 쓰지 않는다(다음 동기화가 채널을 새로 만든다).
- AC-06(실패): 디스코드 문이 없거나 끊겼으면 `discord_pair`는 `error discord_unavailable`.
- AC-07(보안): 제약 표 밖에 민감값 0건. `discord.json`은 0600.

### REQ-HD-02 설정과 상태

- AC-01: `discord`(조회)는 요청 연결에 `discord_status`(`ref` 포함) 하나를 돌려준다. 필드: `platform_ready`, `paired`, `enabled`, `channel_problem`(마지막 채널 작업이 실패했으면 참), `core_open`(짝지은 서버·사장 계정 기준 닫힘 확인이 거짓이거나, 마지막 수신 글의 닫힘 확인이 거짓이었으면 참).
- AC-02: `discord_save{enabled}`·`discord_unpair`는 저장 뒤 `discord` 기능을 밝힌 연결마다 `discord_status`를 하나씩 보낸다. 요청한 연결의 것에만 `ref`가 있고 나머지는 `ref`가 없다(텔레그램 `publish(conn, ref)`와 같다). 그 밖의 상태 변화(짝짓기, 연결, 채널 문제, 닫힘 확인)는 모든 연결에 `ref` 없이 보낸다. 짝 없이 켜면 `error discord_unpaired`(상태 프레임 없음).
- AC-03: `discord` 기능을 밝히지 않은 연결은 이 프레임들을 보내면 `error unexpected_frame`, 받는 방송도 없다.

### REQ-HD-03 채널 동기화

- AC-01(정상): 활성이 되는 순간 짝지은 서버에 분류 `hejo`(없으면 만듦)를 두고, 쓸 수 있는 방마다 대응 채널이 없으면 방 이름(1:1 방은 직원 이름, 단체방은 제목)으로 포럼 채널을 그 분류 안에 만들어 `channels.json`에 적는다. 이미 있으면 만들지 않는다.
- AC-02(정상): 활성 중 단체방이 생기면 채널을 만든다. 이름이 바뀌면 채널 이름을 바꾼다. 보관·삭제되면 채널을 분류 `hejo 보관`(없으면 만듦)으로 옮긴다. 보관이 풀리면 `hejo`로 되돌린다.
- AC-03(경계): 발신할 방에 채널이 없으면 보내기 전에 만든다.
- AC-04(실패): 채널·분류 작업이 실패하면(권한 없음, 커뮤니티 꺼져 포럼 불가 포함) 로그 한 줄(종류만), `channel_problem` 참 방송, 기록장·앱 동작 영향 없음. 만들지 못한 방의 글은 보내지 않고 다음 동기화 계기에 다시 시도한다. 성공하면 `channel_problem` 거짓 방송.
- AC-05(경계): 사장이 디스코드에서 만든 채널은 방을 만들지 않는다. 사장이 방 채널을 지웠으면 다음 발신·동기화 때 새로 만든다.

### REQ-HD-04 수신

- AC-01(정상): 활성이고, 짝지은 서버·사장 계정이 쓴 글이며, 열린 방 채널에 새 포럼 글을 만들면 그 방의 새 스레드에 사장 글로 올라간다. 본문은 첫 글 내용이며, 내용이 글 제목으로 시작하지 않으면 `제목\n내용`이다. 앱 글과 같은 경로(`receive()`)이며 단체방 받는 직원은 멘션/주인/대표 규칙을 따른다.
- AC-02(정상): 방 채널의 글 묶음 안에 쓴 글은 그 글 묶음에 대응하는 hejo 스레드에 올라간다. 대응 스레드가 지워졌거나 없으면 그 채널 방의 새 스레드에 올라가고, 그 글 묶음은 이후 새 스레드에 대응한다(가장 최근 대응이 이긴다).
- AC-03(정상): 첨부는 방 첨부로 저장해 같은 사장 글에 붙인다. 본문과 첨부가 모두 없으면 올리지 않는다.
- AC-04(실패): 활성이고 닫힘 확인이 참일 때, 짝지은 서버에서 사장이 방 채널이 아닌 곳(일반 글 채널, 대응 없는 채널, `hejo 보관`의 채널)에 쓴 글은 올리지 않고 그 자리에 "앱에서 만든 방 채널에 써 주세요"를 보낸다(유효한 짝짓기 코드 글은 REQ-HD-01이 먼저).
- AC-05(실패): 활성이 아니거나, 사장 계정이 아니거나, 봇·웹후크 글이거나, 판정 코드가 예외를 내면 hejo는 아무것도 기록·발신하지 않는다. 닫힘 확인이 거짓인 사장 글도 기록·안내하지 않고, 로그 한 줄(종류만)과 `core_open` 참 방송만 한다.
- AC-06(경계): 같은 디스코드 글 id는 한 번만 올라간다.
- AC-07(실패): 차지한 뒤 처리 실패(첨부 내려받기·저장 실패, 본문 `text_bytes` 초과, 기록 오류)는 "지금은 받지 못했어요"를 보낸다.
- AC-08(경계·보안): 닫힘 운영에서 짝지은 서버의 사장 글(봇 멘션 포함, 일반 글 채널·포럼 글 묶음, 첨부 포함)과 hejo 웹후크 글은 원래 처리기의 들이기 판정에서 거부된다: Hermes 차례 0, 자동 스레드 0, 원래 처리기의 안내 발신 0, 첨부 읽기 0, `message.content` 불변. 이 중 방 채널 글 묶음의 사장 글만 hejo가 정확히 한 번, 원문 그대로 기록한다(일반 글 채널 글은 AC-04 안내만, 웹후크·봇 글은 AC-05에 따라 기록 0). 원래 처리기는 감싸지 않는다(hejo 문은 원래 처리 경로를 바꾸지 않음).

### REQ-HD-05 발신

- AC-01(정상): 활성일 때, 문이 시작된 뒤 쓸 수 있는 방에 기록된 직원 남은 글은 정착 뒤 그 방 채널로 간다. 그 hejo 스레드에 **현재 방 채널에 속한** 대응 글 묶음이 있으면 그중 가장 나중에 대응된 것 안에 보내고, 없으면 새 포럼 글(제목 = 본문의 첫 번째 비어 있지 않은 줄의 앞 100자, 그런 줄이 없으면 `새 대화`)을 현재 방 채널에 만든다. 새로 만든 글 묶음은 이후 그 스레드의 대응이 된다. 글 묶음 안 발신이 "글 묶음 없음"으로 실패하면 같은 글을 새 포럼 글로 한 번 보낸다(그 밖의 실패는 AC-06). 표시 이름은 직원 이름이다(채널 웹후크).
- AC-02(정상): 디스코드가 아닌 경로(앱, 텔레그램)에서 기록된 사장 글은 정착을 기다리지 않고 표시 이름 `사장`으로 간다. 디스코드에서 받은 사장 글은 다시 보내지 않는다.
- AC-03(정상): 한 스레드의 글은 기록 순서대로 간다. 2000자를 넘는 글은 순서대로 나눠 보내고 모든 통의 id를 같은 hejo 글에 대응시킨다(`sent.jsonl`). 재시작해도 대응은 남는다.
- AC-04(정상): 첨부는 같은 글 묶음에 파일로 보낸다. 보내기 전에 못 보낼 것을 아는 첨부(파일 없음, 디스코드 한도 초과 — design 5절 상수)는 본문 끝에 `📎 이름 (hejo 앱에서 열기)` 줄로 남긴다. 파일 발신 실패는 로그 한 줄(종류만), 다시 보내지 않음. 버튼은 HEJO-TELEGRAM과 같은 덧붙임 줄.
- AC-05(보안): 보낸 글은 누구도 호출하지 않는다(`@everyone`·`@here`·사용자·역할 멘션 해제).
- AC-06(실패): 발신 실패는 로그 한 줄(종류만), 다시 보내지 않음, 기록장·앱 영향 없음.
- AC-07(경계): 활성이 아닌 동안 기록된 글은 나중에 활성이 돼도 보내지 않는다. 생각 중 글·작성 중인 스레드의 글은 보내지 않는다.
- AC-08(보존): 같은 hejo 쪽 입력에 대해 이 기능이 있든 없든 기록장 행과 앱 프레임은 같다(디스코드 수신 제외).

### REQ-HD-06 작성 중 표시

- AC-01: 활성이고 그 hejo 스레드에 대응 글 묶음이 있을 때, 방의 직원 차례가 도는 동안(문의 `send_typing`이 불리는 동안) 그 글 묶음에 작성 중 표시를 요청한다. 같은 글 묶음은 8초에 한 번 이하.
- AC-02: 요청 실패·지연은 차례와 발신을 막지 않는다. 표시용 글을 보내지 않는다.

### REQ-HD-07 창 공존

- AC-01: 텔레그램 창의 동작과 기존 수락 시험(`tests/acceptance/test_telegram.py`)은 그대로 통과한다.
- AC-02: 텔레그램에서 받은 사장 글은 디스코드로, 디스코드에서 받은 사장 글은 텔레그램으로 간다(각 창은 자기에게서 온 글만 되보내지 않는다).

### REQ-HD-08 앱

- AC-01: 설정 "연결과 동기화" 쪽에 텔레그램 구역과 나란히 "디스코드" 구역: 상태(서버가 지원하지 않음 / 서버 연결 전 / 서버에 디스코드가 연결돼 있지 않음 / Hermes 디스코드 허용이 열려 있음 / 채널 권한 문제 / 연결됨 / 연결 안 됨), 연결 코드 받기·복사·남은 초, 켜기, 연결 해제, 준비 안내(봇 만들기·Message Content 켜기·서버 만들기·커뮤니티 켜기·봇 초대 권한·코드 입력 위치).
- AC-02: `hello.features`에 `discord`를 더한다. 옛 문에 붙으면 "서버가 지원하지 않음".
- AC-03: AppKit. SwiftUI 예외 없음.

### REQ-HD-09 서버 적용과 실물 확인

- AC-01: 적용 전 기록(공용 릴리스 커밋, 바꿀 설정 파일의 복사본과 해시, 디스코드 플랫폼 꺼짐 확인, Hermes 환경 설치 꾸러미 목록), 복원 절차를 먼저 쓴다(design 10절). 사장이 봇·서버·커뮤니티·초대·토큰을 준비한다(에이전트는 비밀 파일을 열지 않는다).
- AC-02: Hermes 공식 방법으로 디스코드 의존성 설치, 기본 프로필에서만 디스코드 플랫폼 켜기(닫힘 운영 — 허용 값을 넣지 않음; 사장이 `.env`에 허용 값을 넣지 않았음을 확인), 앱의 `core_open` 거짓 확인, 공용 릴리스 갱신, 게이트웨이 재시작, 디스코드·hejo·텔레그램 연결과 새 오류 로그 확인.
- AC-03: 사장이 안드로이드 폰에서 실물 확인 M1~M10과 M6b(수락 시험 명세).

## 비기능

- NFR-HD-01: `python3 scripts/scan_private.py` 통과. 시험은 임시 `HERMES_HOME`과 가짜 디스코드 어댑터·가짜 봇만 쓴다. 예외: AT-HD-30은 실제 `DiscordAdapter`(가짜 `discord` 모듈, 가짜 네트워크 객체)를 쓴다.
- NFR-HD-02: Hermes 본체·플러그인 무수정.
- NFR-HD-03: `bash scripts/test.sh` 전체 통과. 기록장 레코드 종류 불변.
- NFR-HD-04: 로그 계약 범위의 로그에 본문·코드·id·짝 표지·웹후크 토큰 없음.
- NFR-HD-05: `discord.json`·`settings.json`·`channels.json`·`sent.jsonl` 손상이 문 시작을 막지 않는다. 금고·설정 손상이면 짝짓기 0·기록 0·발신 0(원래 처리기는 닫힘 운영대로 거부).

## 알려진 한계

- 서버(게이트웨이)가 꺼져 있던 동안 디스코드에 쓴 글은 들여오지 않는다.
- 디스코드에서 고치거나 지운 글, hejo에서 고치거나 지운 글은 반대쪽에 반영되지 않는다.
- 작성 중 표시는 봇 이름으로 나온다(웹후크는 작성 중 표시를 못 함). 직원 사진은 없다(기본 아바타).
- 포럼 채널은 디스코드 "커뮤니티" 서버에서만 만들 수 있다.
- 디스코드는 채널 이름을 정규화할 수 있다(소문자·공백 등). 문은 자기가 정한 이름만 비교한다.
- 짝지은 서버의 다른 사람 글은 무시된다(사장 혼자 쓰는 서버 전제).
- 닫힘 운영이라 Hermes 디스코드로 직접(1:1 등) 직원과 대화할 수 없다. 디스코드 길은 hejo 창 전용이다.
- 원래 어댑터는 글 묶음 만들기·글 고침·지움을 플랫폼 이벤트로 구독자에게 알린다(차례 아님, 구독자 없으면 무동작 — design 1절). hejo는 이를 바꾸지 않는다.
- 보낸 글 묶음이 디스코드에서 보관(archived)된 상태면 웹후크 발신이 다시 열 수 있다고 가정한다(실물 M6b에서 확인 — M6만으로는 확인되지 않음). 잠긴 글 묶음이면 "글 묶음 없음"이 아닌 실패로 로그만 남는다.
