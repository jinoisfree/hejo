## 요구·수락 기준
- REQ-CS-01 / AC-01: next.kind=gateway_restart를 받으면 주 버튼은 ‘다시 시작’이고 입력값 저장 안내는 나오지 않는다. 입력 단계의 기존 라벨·검증은 유지한다.
- REQ-CS-02 / AC-02: 입력창에서 재시작을 누르면 기존 인증과 명시 확인을 유지하며, 확인창이 보이고 클릭 가능하다. 일반 창과 떠 있는 대화창이 함께 있는 경우 모두 확인한다. 취소하면 재시작 요청은 0회이고 입력창이 다시 조작 가능하다.
- REQ-CS-03 / AC-03: 확인 수락 시 재개 요청은 한 번이며 저장 전 값·change를 재전송하지 않는다. 명시적인 미실행 거절(BUSY 등)은 이유를 표시하고 입력창 조작을 복구한다. 수락 후 전송·응답 대기에는 진행 상태를 표시한다. 연결 끊김·시간 초과처럼 실행 여부가 불명확하면 재시작 재시도를 안내하거나 요청을 재전송하지 않고, 기존 job_status로 결과를 조회한다(job을 알면 해당 job, 모르면 latest). pending은 기존 작업 추적, done은 결과 표시, failed/refused/partial/unknown/timeout/UNKNOWN_JOB은 해당 결과 또는 확인 불가를 표시하며 닫기를 허용한다. 조회 실패·조회 기한 종료에도 실행 성공·실패를 추정하지 않고 결과 확인 불가를 표시한다. 새 재시작 대신 읽기 전용 결과 확인만 허용한다. 자동 재시작 재시도는 없다.
- REQ-CS-04 / AC-04: 확인 중 창 닫기와 다시 열기로 숨은 sheet·미완료 확인 대기가 남지 않는다. 이미 전송된 작업을 취소한 것처럼 표시하지 않으며 늦은 응답으로 닫은 창을 다시 열지 않는다.
- NFR-CS-01: 실명·계정·주소·비밀값 없이 임시 HERMES_HOME과 가짜 명부만 사용한다. 기존 권한·재인증·중복 방지는 그대로다.

완료: AC별 시험 증거, 실제 AppKit 조작 증거, 빌드·회귀·개인값 검사, 검토 판정과 현재 명세 반영. 구현 완료와 원격 푸시 완료는 구별한다.

현재 명세 반영 대상: 검증 완료 후 기획 담당이 docs/spec/current/hejo-connections.md에 이번 적용 동작과 기존 계약 참조를 기록한다. 과거 HEJO-CONNECTIONS spec의 REQ-HC-06 AC-01은 주소 입력 단계의 “확인하고 저장”이므로 유지한다. 이번 변경은 gateway_restart 단계에만 적용하며 과거 명세를 소급 수정하지 않는다.

AC-03 적용 경로: 입력창의 resume=gateway_restart뿐 아니라 게이트웨이 줄의 직접 gateway_restart 요청도 포함한다. 직접 요청은 기존 프레임 계약을 유지하며 불필요한 resume 또는 저장값을 붙이지 않는다.
