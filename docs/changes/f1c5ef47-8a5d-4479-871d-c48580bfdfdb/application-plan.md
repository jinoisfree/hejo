## TASK-CS-04 공개 통합
- 기존 배정 개발 worktree·커밋·증거는 유지한다. 현재 공개 main 기반의 별도 통합 worktree/브랜치를 만든다. 다른 작업의 공개 worktree를 수정하지 않는다. 경로는 추적 문서가 아니라 로컬 기록·상태 블록에 보고한다.
- 개발 기준 236b0177468b90d9ea23a1b1190e996db78a0694 → 검증 대상의 제품 변경 3파일만 이식한다. 두 이력을 merge하거나 개발 트리로 공개판을 덮지 않는다. 공개 TestMain은 문맥 차이로 자동 적용이 실패함을 확인했다. 기존 공개 시험 분기를 보존하며 이번 시험 진입점만 같은 구조로 통합한다.
- 공개판의 다른 기능을 보존한다. 범위 밖 의도 충돌은 보고하며 덮어쓰지 않는다. 이번 작업 문서·수락 시험·현재 명세만 선별 보존하고 원본 문서 링크를 검사한다. 전체 미추적 문서를 일괄 추가하지 않는다.
- 공개 기준이 개발 기준과 다르므로 새 통합 트리에서 격리 전체 시험 bash scripts/test.sh, 빌드(시험에 포함 가능), 개인값 검사, 실제 AppKit 새 AC를 수행한다. 이번 공개 통합에 개발 증거만으로 합격을 대체하지 않는다.
- 실제 공개 tip이 대상의 조상임을 확인한다. 새로운 공개 변경이 발견되면 내용을 보존하며 기준을 갱신·재검증한다. 강제 푸시·unrelated merge·개발 트리 스냅샷 치환 금지.

## TASK-CS-05 로컬 앱 설치
- 쓰기 범위는 사용자에게 실제 실행되는 hejo 앱 번들만이다. 설치 위치는 현재 실행 프로세스와 번들 ID로 재확인해 로컬 증거에 기록한다. 확인한 번들 ID는 io.github.hermes-hejo.hejo, 기존 표시 버전은 0.2.7/9다. 개인 경로는 추적 파일에 넣지 않는다.
- 테스트용 빌드 옵션이 기능을 빠뜨리는 설치를 하지 않는다. 기존 배포 빌드 설정·서명·필요 리소스가 보존되는지 확인하되 비밀 내용을 로그/문서에 출력하지 않는다. 운영 Hermes 비밀 파일은 열지 않는다.
- 교체 전 원본 앱 번들을 이번 작업 전용 새 백업 위치에 보존하고 서명·실행 파일 해시·버전을 기록한다. 이전 작업의 백업을 덮지 않는다. 새 앱의 서명 검증과 BuildInfo/커밋 대응을 확인한 뒤 교체한다.
- 앱만 정상 종료·교체·재실행한다. 강제 종료로 작성 중 입력을 버리지 않는다. 정상 종료가 거부되면 이유를 보고한다. Hermes 게이트웨이·허브·플러그인·설정·키체인·명부·대화 저장소는 변경하거나 재시작하지 않는다.
- 설치 뒤 실제 실행 경로·실행 파일 해시가 후보와 같은지 확인하고 연결창이 열리고 닫히는지 검사한다. 실제 연결 저장·재시작 버튼 실행·메시지 전송 없이 검증한다. 재시작 확인의 가시성 시험은 가짜 서비스 AppKit 시험으로 유지한다.
- 실패 시 새 앱을 정상 종료하고 보존한 기존 번들을 원위치에 복원·서명 확인·재실행한다. 새 사용자 데이터 삭제나 백업 외 파일 복원은 하지 않는다. 복구 결과와 남은 문제를 보고한다.

위험도 일반: 복구 가능한 로컬 앱 번들 교체, 데이터/인증/서버 변경 없음. 추가 운영 설정·자료 이관이 필요하면 중단·재분류한다. 증거 수준 1·2·3 및 실제 로컬 설치/실행 확인이 완료 조건이다.

## 보고·검토
공개 통합 커밋·전체 검사·설치 전후 해시·실제 실행 경로·백업·복구 명령·미검증 범위를 원본 impl-report에 추가한다. 민감 경로와 전체 로그는 로컬 증거에 두고 상대 경로로 참조한다. 원본 verdict는 검토자가 공개 통합·설치 증거를 확인한 뒤 갱신한다. 푸시할 저장소·github/main·전체 커밋 후보는 보고만 하고 직접 푸시하지 않는다.
