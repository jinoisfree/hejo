# HEJO-RESULT-DONE 브레인스토밍 결정 요약

- 일자: 2026-11-27 · 진행 방식: 브레인스토밍 → 연합개발(계획 검증 켜기)
- 계기: 직원이 "일정 등록 완료 … 되돌릴 수 있습니다"라고 보고했는데, 스레드가 빨간 띠의 "답을 기다려요" 카드로 남았다. 사장 요청: 더 답할 필요가 없는 글은 초록색이 되고 가운데 칸 카드에서도 빠져야 한다. 되돌리기는 질문·요청에서 예외다.

## 목적
확인·되돌리기 버튼만 달린 직원 글(앱 쓰기 결과 보고, 이하 "결과 알림")은 질문이 아니다. 스레드는 끝난 일(초록)이 되고 답 요청 카드·방 질문 숫자·섬 질문에서 빠진다. 되돌리기 버튼은 계속 누를 수 있다.

## 하는 것 / 하지 않는 것
- 한다: 문 판정(`gate/history_queries.py`의 `assess`·`questions`)에 결과 알림 예외 추가. 문 요약이 답 버튼을 보여 줄 글 id 목록을 보내고(안내판 계약 추가) 앱이 그 목록으로 대화 안 답 버튼을 그린다. 공개판과 운영 문 줄 두 곳에 넣고 서버에 설치한다. 앱 새 버전을 만든다.
- 하지 않는다: 직원 쪽(team-kit)이 붙이는 `reply_state` 변경, 다른 버튼 조합(승인·거절, 메모 등)의 판정 변경, 앱의 옛 기준본(`ThreadAssessment.assess`, `HEJO_LEGACY_REFERENCE` 빌드 전용) 변경, 기록장 수정.

## 실측 [확인]
- 서버 기록장(`<HOME>/shared/hejo/journal/2026-11.jsonl`)의 해당 스레드는 직원 글 `asked`+[승인, 거절] → 사장 "일정에 등록" → 직원 글 `asked`+[확인, 되돌리기] 순서다(실제 id는 운영 저장소 대응표에 둔다).
- 설치된 앱(이력 모드)의 스레드 판정은 문 요약 `assessment`에서 온다(`app/Sources/ConversationModel.swift` `assessment(_:)` 이력 분기, 문 `gate/history_queries.py` `assess`). 앱 `ThreadAssessment.assess`는 옛 기준본 빌드에서만 쓴다.
- 문 `assess`는 상태값이나 버튼이 있는 직원 글을 요청으로 보고, 그 뒤 사장 답이 없으면 `pendingID`로 둔다 → 빨간 띠·답 요청 카드.
- 이력 모드 앱은 `assessment.buttons`를 채우지 않는다. 문 요약에는 `waitingButtonCount`(개수)만 있다. 그래서 대화 안 답 버튼이 어느 글에도 보이지 않는다(스크린샷에 확인·되돌리기 버튼이 없던 이유).
- 섬 질문(`HistoryQueries.questions`)은 `reply_state == 'asked'`이면 모두 넣도록 일부러 넓게 잡혀 있다.
- `ReplyButtonPolicy.contexts`에 `["확인", "되돌리기"] = 앱 쓰기 결과` 구분이 이미 있다(버튼 설명용).

## 선행 조사
생략: 저장소 내부 판정 버그이며 외부 기술 선택이 없다.

## 대안과 선택
| 대안 | 판정 |
|---|---|
| 문 판정 한 곳(`assess`·`questions`) + 답 버튼 id 전달 | **선택.** 이전 기록에도 적용되고 화면 전체(카드·띠·숫자·섬)가 한 원본을 따른다 |
| 직원 쪽(team-kit)이 결과 보고에 `asked`를 붙이지 않음 | 기각. 이전 기록은 계속 질문으로 남고 운영 저장소 변경이 필요하다 |
| 앱 판정만 | 기각. 설치된 앱은 문 판정을 쓰므로 화면이 바뀌지 않는다(처음 추천은 이 사실을 확인하기 전이었음) |

## 가정
- 사용자 결정: 고칠 곳 = 문 판정 한 곳, 섬 질문에서도 뺀다, 서버 설치까지 한다, 답 버튼이 안 보이는 문제도 이번에 함께 고친다, 되돌리기 버튼은 초록이 된 뒤에도 누를 수 있다.
- 에이전트 제안: 결과 알림 = 버튼 라벨이 가공 없이 이 순서 그대로 [확인, 되돌리기]인 직원 글(앱 누름 규칙과 같은 입력, spec 2절). 사장 글 없이 결과 알림만 있는 스레드도 끝난 일로 보고 알림 카드도 만들지 않는다.
