# HEJO-WAIT-JITTER 명세 (5판, 2026-11-25, 계획 검증 4회차 반영)

결정 근거: [brainstorm.md](brainstorm.md). 기준 커밋: HEJO-AUTOLOAD TASK-01이 반영된 `github/main` tip(착수 시 고정, handoff 0절).

## 문제
직원이 답하는 동안(답하는 중 표시, 생각 중·스트리밍 글 갱신) 가운데 대화 목록과 왼쪽 목록이 사용자가 아무것도 하지 않았는데 한 줄쯤 튀었다가 곧 돌아온다. [확인] 사용자 화면 기록 11.4초에 8회(brainstorm 실측).

## 목표
리더 입력이 없을 때, 한 번의 내용 변화에 대해 화면 위치 조정은 한 방향으로만 일어나고 되돌아오는 왕복이 없다. 내용 높이·순서가 바뀌지 않은 갱신에서는 화면이 움직이지 않는다. 기존 스크롤 규칙(따라가기, 끝 거리 유지, 기록 기준점, 리더 입력 우선)의 최종 위치는 그대로다.

## 범위
- 안: `NativeThreadList`의 자동 위치 조정, `ConversationView`의 왼쪽 목록 갱신, 원인 확인용 진단 기록(기존 `ThreeTapDiagnostics` 재사용, 환경 변수로만 켬).
- 밖: CPU 사용량, 스크롤 규칙 자체의 변경(어느 위치에 멈추는지), 게이트·스키마·설치, 개발 `main`.

## 요구와 수락 기준

용어
- **내용 변화 사건**: 목록에 들어가는 카드의 id·순서·높이 중 하나가 바뀐 `show` 1회(답하는 중 줄 추가·제거, 글 성장, 스트리밍 끝 등). 카드 내용이 같은 `show`는 사건이 아니다.
- **구간**: 한 사건(또는 시작)부터 다음 사건 직전까지. 구간마다 **목표 위치** = 그 구간의 입력을 기준 커밋 코드에 넣고 리더 입력 없이 정착시킨 스크롤 원점(시험 하네스가 기준 커밋에서 따로 재서 기록한다. 구현과 같은 코드에서 기대값을 가져오지 않는다).
- **되튐**: 한 구간 안에서 원점과 목표 위치의 거리 |y−목표|가 한 번이라도 0.5pt 넘게 커지는 것(목표 쪽으로 갔다가 멀어지거나, 목표에 있다가 벗어남). 구간 시작에서 목표로 다가가는 보정(즉시 또는 감속 이동)은 정상이다.
- **사건 서명**: 대화 목록에 들어간 카드 (id, 순서, 측정 높이) 목록의 해시. 서명이 바뀐 `show`/재측정이 사건이다. 왼쪽 목록은 (줄 id, 순서, 높이) 목록의 해시로 따로 센다.
- **반전**(관측 기준): 같은 구간 안에서 원점 이동 방향이 바뀌고 반대 방향 이동이 0.5pt를 넘는 것. 하네스는 되튐(목표 기준)과 반전을 모두 판정한다. 반전만으로는 사건 경계를 가로지르는 결함을 놓치므로(무관한 카드 높이 변화가 경계를 만들 수 있음) 실물·기록 판정은 아래 **설명 조건**을 함께 쓴다.
- **설명 조건**(대화 목록, 관측값만 씀): 사건 k의 문서 높이 변화 Δk와, 사건 k 시작 때 보이는 영역 맨 위보다 위에서 생긴 높이 변화 Δk↑(바뀐 카드 위치로 계산), 사건 k 시작 때 끝 여백 Gk를 기록한다. 사건 순번이 k인 동안 생긴 자동 원점 변화의 합 Sk는 다음 중 하나를 만족해야 설명된다(허용 0.5pt).
  - 유지: Sk = 0, 또는 Sk = Δk↑, 또는 Sk = Δk(끝 거리 유지). 즉 원점은 위쪽 변화량이나 전체 변화량만큼만, 같은 부호로 움직인다.
  - 따라가기(이유가 따라가기인 이동만 있을 때): 따라가기 목표 거리 Fk = (변경 후 따라가기 목표 원점) − (사건 k 시작 원점). 목표 원점은 변경 후 문서 높이·보이는 높이·따라가기 끝 여백(보통 0)으로 계산하고 0~최대값으로 자른다(끝에 붙어 따라가는 고정 뷰포트에서는 Fk = Gk + Δk). Sk는 Fk와 같은 부호이거나 0이고 |Sk| ≤ |Fk| (허용 0.5pt). 다음 사건 전에 일부만 간 경우도 정상이다. Δk의 부호는 쓰지 않는다(Δk<0이어도 Gk>|Δk|면 아래로 진행이 정상).
  - 경계 고정: 원점이 0 또는 최대값에 붙어 잘린 경우 그 잘림만큼은 설명된 것으로 본다.
  - 걸친 카드: 바뀐 카드가 보이는 영역 맨 위에 걸쳐 있으면(카드 안 글 단위 기준점 때문에) Sk는 Δk↑에 그 카드 변화량의 0~100%를 더한 범위 안(같은 부호)이면 설명된다.
  또한 각 구간 안 반전 0. 설명되지 않는 사건이 하나라도 있으면 실패. 리더 입력·방 전환·선택 변경 뒤 0.5초 안의 이동(이유 scrollTo/진입 포함)은 판정에서 뺀다.
- **왼쪽 설명 조건**: 왼쪽 목록 갱신마다 보이는 줄 각각의 창 좌표 y 변화는, 그 줄보다 위 줄들의 높이 변화 합(삽입·삭제 포함)과 원점 변화로 설명돼야 한다(허용 0.5pt). 위쪽에 아무 변화가 없는 줄이 움직이면 실패.
- 실물(영상)에서의 **왕복**은 REQ-WJ-04에서 따로 정의한다.

### REQ-WJ-01 답하는 중 갱신에서 대화 목록 되튐 없음
- AC-01 (정상, 중간 읽기): Given 리더가 목록 중간(끝에서 300pt)을 보고 있고 같은 방에 답하는 중 표시가 켜져 있다 / When 내용이 같은 갱신이 0~0.5초 간격으로 섞여 30회 오고, 그 사이 사건 4개(답하는 중 줄 34pt 추가 2회·제거 2회)가 각각 다른 시각에 온다 / Then 1/60초마다 잰 원점에 대해 모든 구간에서 되튐 0회, 각 구간 끝(다음 사건 직전 또는 마지막 갱신 0.5초 뒤) 원점이 그 구간 목표 위치 ±1pt. 사건이 없는 구간(내용 같은 갱신만 있는 구간)은 목표 위치가 직전 원점이므로 원점 변화 ≤0.5pt.
- AC-02 (경계, 끝 근처): AC-01과 같되 리더가 끝에서 0, 1.5, 2.5, 100pt에 있을 때, 일반 모드와 기록 모드 각각 / Then 되튐 0회, 구간 끝 원점이 목표 위치 ±1pt.
- AC-03 (정상, 스트리밍 따라가기): Given 리더가 끝에 있고 답이 스트리밍으로 자란다 / When 글이 12회 자라고(사건 12개) 마지막에 스트리밍 끝·답하는 중 줄 제거(사건) / Then 모든 구간 되튐 0회, 한 프레임 이동 ≤36pt(AT91), 마지막 구간 끝 여백 ≤1pt.
- AC-04 (실패, 리더 입력 우선): Given AC-01 진행 중 지연 자동 조정이 남아 있다 / When 리더가 휠, 마우스 클릭, 방향키 중 하나로 위치를 옮긴다(각 입력을 실제 이벤트 처리 경로 — 앱 이벤트 배송과 목록의 입력 감시 — 로 넣는다) / Then 세 입력 각각에서 그 뒤 0.5초 동안 자동 조정으로 원점이 0.5pt 넘게 움직이지 않는다.

### REQ-WJ-03 원인 확인 기록
- AC-01: 진단 환경 변수(`HEJO_THREE_TAP_TRACE`)가 켜졌을 때만 기존 진단 파일에 아래를 한 줄씩 남긴다. 모든 줄에 벽시계 시각(ms)과 단조 시각을 함께 적는다. 꺼져 있으면 기록 0줄. 사람 이름·글 본문·경로를 남기지 않는다(카드는 id 해시 또는 순번).
  - (가) 대화 목록 `show`/재측정마다: 사건 순번(서명이 바뀔 때만 1 증가), 서명 변경 여부, 문서 높이 전후(Δk), 바뀐 카드마다 순번·변경 전 프레임 y·높이 변화량, 변경 직전 원점과 보이는 높이, 끝 여백(Gk), 따라가기 중이면 그 끝 여백 목표와 계산한 Fk, 이로부터 계산한 Δk↑, 그 직후 원점.
  - (나) 대화 목록 원점이 바뀔 때마다(클립 뷰 bounds 변경 알림으로 모두 잡음 — `move(to:)`, AppKit, 리더 스크롤 포함): 이유(따라가기/유지/기준점/진입/scrollTo/크기 변경/AppKit/리더), 예약 세대, 이 이동이 예약된 때의 사건 순번, 현재 사건 순번, 전후 원점.
  - (다) 왼쪽 목록 갱신마다: 왼쪽 사건 순번(서명 변경 때만 증가), 재배치 호출 종류(`SidebarMotion.update`/`noteHeightOfRows`/없음), 바뀐 줄 순번·높이 전후·삽입/삭제, 원점, 갱신 전후(애니메이션 끝 포함) 보이는 줄마다 id 해시와 창 좌표 y.
  - (라) 리더 입력(휠·클릭·키·라이브 스크롤): 종류.
- AC-02 (판정식): 기록만으로 다음 다섯 값을 계산한다. 대화 목록: (1) 구간 안 반전 횟수, (2) 옛 사건의 늦은 이동 횟수(예약 사건 순번 < 현재 사건 순번), (3) 설명 조건을 못 지킨 사건 수. 왼쪽 목록: (4) 서명 변경 없는 재배치 호출 횟수, (5) 왼쪽 설명 조건을 못 지킨 줄 이동 수. 판정 스크립트(구현 담당 작성, `app/Tests/` 또는 `scripts/` 아래, 개인값 없음)가 다섯 값과 실패한 사건·줄 목록을 출력한다.
