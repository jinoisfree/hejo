## 2회 검토 후 보완 인계 — v4 (다음 실행 범위)

근거: [verdict](verdict.md) V-SM-02. 원인 분류는 환경·외부 요인이다. 설계·요구·수락 기준·예산과 보완 인계 v3의 작업 위치는 그대로다. 전용 작업 공간과 브랜치는 이미 만들어져 있으므로 다시 만들지 않는다.

1. Python 시험은 다음 조합으로 실행한다. 계획 담당이 전용 작업 공간에서 수집만 실행해 427개가 오류 없이 수집됨을 확인했다.
   - `HEJO_PYTHON`: Hermes 설치 폴더 아래 시험용 환경(`test-environment`의 현재 세대) venv의 Python. pytest가 여기에만 있다.
   - `PYTHONPATH`: Hermes 설치 폴더 아래 실행 환경(`environments`의 현재 것)의 `workspace` 폴더. `gateway` 등 본체 모듈이 여기서 읽힌다.
   - 기존대로 임시 `HERMES_HOME`, 짧은 임시 폴더, 짧은 pytest basetemp를 쓴다.
2. 두 경로는 읽기만 한다. Hermes 본체, 실행 환경·시험용 환경 venv에 패키지를 설치하거나 파일을 바꾸지 않는다. 실제 경로는 개인값이므로 추적 파일과 보고서에 쓰지 않고 `<Hermes 시험용 환경 Python>`, `<Hermes 실행 환경 workspace>`로 적는다.
3. 이 조합으로 수정 전 `bash scripts/test.sh`를 끝까지 실행해 결과를 남긴다. 기준에서 이미 실패하는 항목(예: 이전 작업들이 기록한 설치 영수증 시험)은 그대로 기록하고 진행한다. 스크립트가 중간 실패로 뒤 단계를 건너뛰면, 건너뛴 단계(앱 빌드와 앱 시험)를 따로 실행해 기준 결과를 확보한다.
4. 개인값 검사는 기존대로 실행 환경 venv Python으로 돌아간다.
5. 이 조합으로도 Python 시험이 환경 문제로 막히면 원인과 로그를 보고하되, 앱 쪽 작업(TASK-01 이후의 Swift 빌드·시험·계측)은 Python 게이트 시험과 독립이므로 앱 기준 결과를 확보한 뒤 계속 진행한다. 이 작업은 `gate/`를 고치지 않는다.
6. 그 뒤 TASK-01 → 02 → 03 → 05를 원래 인계와 v3대로 진행한다. TASK-04는 착수 차단을 유지한다.
