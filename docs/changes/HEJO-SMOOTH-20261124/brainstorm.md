# HEJO-SMOOTH 브레인스토밍 결정 요약

2026-11-24. 사용자 요청: 화면이 아직 완전히 부드럽지 않다. 새 스레드로 글을 쓸 때, 스레드를 선택해 펼칠 때, 알림을 눌러 스레드를 찾아가는 창 전환에서 버벅임이 남아 있다.

## 목적
대화 화면에서 누르고·쓰고·넘길 때 끊김 없이 움직이게 한다.

## 하는 것·하지 않는 것
- 한다: 내용이 바뀌지 않은 글의 꾸민 결과와 잰 높이를 재사용하고, 바뀐 스레드만 다시 만든다.
- 한다: 알림 클릭으로 창이 열리는 동안 전체 다시 그리기와 스크롤 이동이 전환 애니메이션과 겹치지 않게 한다.
- 대상 증상: 스레드 펼치기, 새 글 쓰기, 알림 클릭 창 전환, 답변이 흘러나올 때, 방 전환, 스크롤.
- 하지 않는다: 보이는 카드만 그리는 구조 개조, 화면 모양·글자 나타나는 느낌·스크롤 위치 규칙·읽음과 알림 의미 변경, 서버와 문(gate) 변경.

## 칸·원본·쓰기 주체·수명
| 다루는 것 | 칸 | 원본 위치 | 쓰기 주체 | 수명 |
|---|---|---|---|---|
| 대화 칸 다시 그리기 | 관제 화면 | app/Sources의 대화 화면 | 앱 개발 | 앱 갱신 시 교체 |
| 꾸민 글·잰 높이의 재사용 값 | 관제 화면 | 대화 모델에서 다시 만들 수 있는 파생값 | 화면 그리는 쪽 하나 | 입력이 바뀌면 폐기, 앱 종료 시 소멸 |

## 실측
- [확인] 글 150개의 높이 재기만 따로 잰 값: 200자 약 55ms, 800자 약 200ms, 3,000자 약 725ms. 저장소 밖 임시 공간의 독립 측정이며 앱 안의 지연이 아니다.
- [확인] 이전 성능 작업의 측정(짧은 글 3,200개, 실제 View 부착): 방 전환 동작 중앙값 약 0.111초, 수신 개별 약 0.108초. 원본은 [이전 구현 보고](../60f149af-b64e-4d3a-9e8e-a1c7d4ea1045/impl-report.md).
- [확인] 답변 수신 중에는 전체 다시 그리기가 초당 30회 예약된다(코드).
- [확인] 알림 클릭 시 전환 전에 전체 다시 그리기가 한 번 돌고, 이후 스크롤 이동이 0·0.15·0.45초에 다시 시작된다(코드).
- [미실행] 설치 앱 안에서 증상별 지연 측정.

## 선행 조사
생략. 앱 내부의 다시 그리기 낭비이며 가져다 쓸 외부 도구가 없다.

## 대안과 선택
| 안 | 결과 |
|---|---|
| A + 창 전환 다듬기 | 선택(사용자 결정) |
| A만 | 기각: 창 전환 끊김이 남을 수 있음 |
| B 보이는 카드만 그리기 | 기각: 스크롤 위치 계산을 새로 짜야 해 위험이 큼 |

## 가정
- 사용자 결정: 범위는 A + 창 전환 다듬기. 추가 증상 세 가지(답변 수신, 방 전환, 스크롤) 포함. 연합개발, 계획 검증 켜기.
- 사용자 결정: 시작 기준은 개발 main에 지난 성능·입력 개선 브랜치를 합친 것. 완료 뒤 기존 방식대로 공개 기준에 옮긴다.
- 에이전트 제안: 증상별 지연 예산은 화면 한 장 시간과 즉각 반응 한계를 근거로 정한다(spec).

## 열린 질문
- 스크롤 끊김의 원인은 확정되지 않았다. 기준 계측으로 가린 뒤 범위를 정한다.

## 위험도 1차 판단
일반. 화면 파일 여러 개를 고치며, 재사용 값이 낡으면 옛 글이 보이는 회귀가 생길 수 있다. 서버와 저장 자료에는 영향이 없다.
