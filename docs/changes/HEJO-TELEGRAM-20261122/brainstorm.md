# HEJO-TELEGRAM 브레인스토밍 결정 요약

- 날짜: 2026-11-22. 진행 방식: 연합개발, 계획 검증 켜기(사장 선택).
- 근간: [ARCHITECTURE.md](../../ARCHITECTURE.md). 새 칸 없음. 앞선 작업: [HEJO-IMESSAGE](../HEJO-IMESSAGE-20261119/spec.md).

## 1. 목적

안드로이드 폰에서도 hejo 방을 쓰도록, 방의 바깥 메신저 문을 아이메시지에서 텔레그램으로 바꾼다. 경로는 hermes-hejo-텔레그램이다.

## 2. 하는 것 · 하지 않는 것

하는 것(사장 결정):

- 아이메시지 문을 텔레그램으로 **교체**한다. 아이메시지 연결은 hejo에서 뺀다.
- 텔레그램 **포럼 그룹**(토픽을 켠 그룹)을 쓴다. 방 = 토픽, 스레드 = 토픽 안 답장.
- 방은 **앱에서만** 만든다. 앱의 방 생성·이름 변경을 토픽이 따라간다. 텔레그램에서 만든 토픽은 방을 만들지 않는다.
- **모든 방**을 텔레그램에 잇는다(아이메시지의 "연결된 방 하나"와 다름).
- 텔레그램에서 올린 사진·파일은 방 첨부로 올린다.
- 문이 Hermes 본체 텔레그램 어댑터 처리기를 감싼다(`register_platform_handler`, 아이메시지와 같은 방식).

하지 않는 것:

- Hermes 본체 수정, ddots, 실제 Slack·고객 메시지.
- 텔레그램 토픽 → 방 만들기.
- 직통 차단: 문이 맡지 않은 글은 아이메시지와 같이 이전 경로(Hermes)로 간다(사장 결정: "아이메시지와 동일 방식").

## 4. 실측 (2026-11-22)

- Hermes 텔레그램 어댑터: 답장 지정 발신(`plugins/platforms/telegram/adapter.py:3722`), 토픽 만들기·이름 바꾸기(`:2602`, `:2682`), 포럼 구분(`:985`), 4096자 한도(`:519`). 보낸 사람 허용 판정은 본체 공통(`gateway/platforms/base.py:2446`).
- 현재 아이메시지는 문이 맡지 않으면 Hermes 직통으로 간다(`gate/imessage.py:41-56`).
- 아이메시지 흔적: 문 5개 파일, 앱 7개 소스, 통신 규격, 수락 시험 3개, 앱·문 시험 여럿.

## 5. 선행 조사

| 후보 | 판단 |
|---|---|
| Hermes 본체 텔레그램 어댑터 감싸기 | 채택. 이미 있고 토픽·답장 지원 |
| Photon의 텔레그램 기능 | 기각. 설치물에 꾸러미만 있고 켜지 않음, 유료 중계 |
| 문이 Bot API 직접 호출 | 기각. 직통 차단이 필요 없어져 일만 늘어남 |
| WhatsApp / SMS / RCS / 카카오톡 | 기각. 계정 정지 위험 / 스레드 없음·유료 / 개인용 문 없음 |

## 6. 가정

- 사장 결정: 교체, 포럼 그룹, 방은 앱에서만, 첨부 포함, 직통 허용.
- 에이전트 제안(계획에서 확정): 포럼 그룹은 사장 혼자, 봇은 관리자. 짝짓기는 그룹 단위로 하고 사장 계정 글만 받음. 방 삭제·보관 시 토픽은 닫기.
- 운영 서버 적용(텔레그램 켜기·photon 끄기)은 인계서가 허가한 작업에서만 롤백과 함께. 봇 토큰은 사장이 넣는다.

## 7. 열린 질문

- 방 삭제·보관 시 토픽을 닫을지 지울지.
- 단체방 기록을 토픽으로도 보낼지.

## 8. 위험도 1차 판단

고위험 쪽: 인증·권한(짝짓기·보낸 사람 확인), 운영 게이트웨이, 운영 중인 문 제거. 앞선 HEJO-IMESSAGE도 고위험이었다.
