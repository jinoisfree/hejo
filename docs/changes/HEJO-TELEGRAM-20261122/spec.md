# HEJO-TELEGRAM 명세: 방의 바깥 메신저 문을 아이메시지에서 텔레그램 포럼 그룹으로

- 상태: 1판(2026-11-22, 초안 — 계획 검증 대기). 기준 커밋: [handoff.md](handoff.md) 0번.
- 근간: [ARCHITECTURE.md](../../ARCHITECTURE.md). 결정 요약: [brainstorm.md](brainstorm.md). 구조: [design.md](design.md). 수락 시험: [HEJO-TELEGRAM.md](../../../tests/acceptance/HEJO-TELEGRAM.md). 앞선 작업: [HEJO-IMESSAGE spec](../HEJO-IMESSAGE-20261119/spec.md).
- 작업 유형: 의미 변경(아이메시지 문 교체) + 신규 기능. 위험도: 고위험(공통 4절 — 인증·권한: 짝짓기가 사장을 정함, 운영 수신 경로를 감쌈, 운영 중인 문 제거).

|---|---|---|---|---|

## 문제와 목표

- 문제: 사장은 안드로이드 폰을 쓴다. 지금 hejo 방의 바깥 문은 아이메시지(아이폰 전용)뿐이고, 그마저 방 하나만 잇는다.
- 목표: 사장이 만든 텔레그램 포럼 그룹을 짝지으면 hejo의 쓸 수 있는 방마다 토픽이 생기고, 방의 글(직원 글과 앱에서 쓴 사장 글)이 그 토픽에 올라가며, 사장이 토픽에 쓴 글(첨부 포함)은 그 방에 사장 글로 올라간다. 경로는 Hermes → hejo 문 → 텔레그램이다.

## 용어

- **쓸 수 있는 방:** 명부에 있는 직원의 1:1 방(id = 직원 id)과 삭제·보관되지 않은 단체방(id = 방 id). HEJO-IMESSAGE와 같다.
- **짝지은 그룹:** 짝짓기 코드를 받은 텔레그램 포럼 그룹 하나와 그 코드를 보낸 계정 하나(사장 계정).
- **방 토픽:** `topics.json`이 그 방에 대응시킨 토픽.
- **활성:** 짝지은 그룹이 있고, 켜짐이며, 텔레그램 문이 연결돼 있고, hejo 기본 어댑터가 연결돼 있음.
- **남은 글:** HEJO-IMESSAGE와 같다 — 차례가 끝나고 정착 시간이 지난 뒤 방에 남아 있는 직원 글.

## 범위

- 안: 텔레그램 문 감싸기, 짝짓기·해제·켜기, 토픽 동기화(만들기·이름 바꾸기·닫기·다시 열기), 수신(새 글·답장·첨부), 발신(모든 쓸 수 있는 방의 직원 남은 글과 앱 사장 글, 첨부), 텔레그램 작성 중 표시, 앱 설정 구역, 아이메시지 연결 제거(문·규격·앱·시험), 서버 적용·앱 공개·실물 확인.
- 밖: Hermes 본체·photon·team-kit 수정, 서버의 photon 끄기(사장 결정: 그대로 둠), 텔레그램 토픽 → 방 만들기, 짝짓기 전 기록 되보내기, 보낸 뒤 hejo에서 고치거나 지운 글의 텔레그램 반영, 텔레그램에서 고친 글 반영, 직통 차단(문이 맡지 않은 글은 원래 처리기로 간다), 버튼 누르기.

## 제약

- Hermes 본체·텔레그램·photon 플러그인 무수정. 문은 플랫폼 처리기 계약(`register_platform_handler`)만 쓴다.
- 민감값 허용 위치(저장·내보내기 정책, HEJO-IMESSAGE PR-05 해석과 같음 — 텔레그램 문과 주고받는 런타임 전달은 정상 경로):

| 값 | 나타나도 되는 곳 |
|---|---|
| 코드 평문 | 요청한 앱 연결의 `telegram_code` 프레임 하나 |
| 코드 해시 | `telegram.json` |
| 그룹 id·사장 계정 id | `telegram.json` |
| 토픽 id·텔레그램 글 id | `topics.json`, `sent.jsonl`, 기록장 `client_msg_id` |
| 글 본문·파일 | 기존 대화 경로(기록장·첨부 저장소·앱 프레임)와 텔레그램 발신 |

  로그에는 위 값이 하나도 나오지 않는다(종류 이름만).

## 요구

### REQ-HT-01 짝짓기

- AC-01(정상): 앱이 `telegram_pair`를 보내면 요청한 연결에만 `telegram_code`(12자, 72비트 무작위, 600초)가 온다. 새 요청은 이전 코드를 대체한다.
- AC-02(정상): 텔레그램 문이 연결돼 있고, 포럼 그룹에서 글 전체(앞뒤 공백 제외)가 유효한 코드이며, 발신자 허용 검사가 `False`가 아니면 짝짓기가 된다: 금고에 `{platform:"telegram", chat_id, user_id, paired_at}`가 쓰이고 코드는 쓰임으로 표시되며, 그 토픽에 "연결됐어요"가 가고 상태가 방송된다. 켜짐은 바뀌지 않는다.
- AC-03(실패): 쓰인 코드, 만료된 코드, 틀린 글, 포럼이 아닌 그룹·1:1 대화, 허용 검사 `False`의 코드 글은 짝짓지 않고 원래 처리기로 같은 이벤트 객체가 한 번 간다.
- AC-04(정상): `telegram_unpair`는 짝과 코드를 지우고 켜짐을 끈다. `topics.json`은 남긴다(같은 그룹에 다시 짝지으면 다시 쓴다).
- AC-05(경계): 다른 그룹·다른 계정으로 다시 짝지으면 이전 짝을 대체한다. 그룹 id가 바뀌면 `topics.json`의 이전 그룹 대응은 쓰지 않는다(다음 동기화가 새로 만든다).
- AC-06(실패): 텔레그램 문이 없거나 끊겼으면 `telegram_pair`는 `error telegram_unavailable`.
- AC-07(보안): 코드 평문·해시·id가 제약 표 밖(로그, 다른 연결의 프레임, 다른 파일)에 0건. `telegram.json`은 0600.

### REQ-HT-02 설정과 상태

- AC-01: `telegram`(조회)은 `telegram_status`(`ref` 포함)를 돌려준다. 필드: `platform_ready`, `paired`, `enabled`, `topic_problem`(마지막 토픽 작업이 권한·포럼 아님으로 실패했으면 참).
- AC-02: `telegram_save{enabled}`는 저장 뒤 `telegram` 기능을 밝힌 모든 연결에 `ref` 없이 방송한다. 짝 없이 켜면 `error telegram_unpaired`.
- AC-03: `telegram` 기능을 밝히지 않은 연결은 이 프레임들을 보내면 `error unexpected_frame`, 받는 방송도 없다.
- AC-04: 아이메시지 프레임 4종(`imessage`, `imessage_pair`, `imessage_unpair`, `imessage_save`)은 기능과 상관없이 `error unexpected_frame`(옛 앱은 "서버가 지원하지 않음"을 보인다).

### REQ-HT-03 토픽 동기화

- AC-01(정상): 활성이 되는 순간(켜기, 짝지은 상태에서 문 연결) 쓸 수 있는 방마다 대응 토픽이 없으면 방 이름(1:1 방은 직원 이름, 단체방은 제목)으로 토픽을 만들고 `topics.json`에 적는다. 이미 있으면 만들지 않는다.
- AC-02(정상): 활성 중 단체방이 생기면 토픽을 만든다. 이름이 바뀌면 토픽 이름을 바꾼다. 보관·삭제되면 토픽을 닫는다. 보관이 풀리면 다시 연다.
- AC-03(경계): 발신할 방에 토픽이 없으면(명부 변경으로 생긴 1:1 방 등) 보내기 전에 만든다.
- AC-04(실패): 토픽 만들기·바꾸기·닫기가 실패하면 로그 한 줄(종류만), `topic_problem` 참, 기록장·앱 동작 영향 없음. 만들기 실패한 방의 글은 보내지 않고, 다음 동기화 계기에 다시 시도한다.
- AC-05(경계): 텔레그램에서 사장이 만든 토픽은 방을 만들지 않는다.

### REQ-HT-04 수신

- AC-01(정상): 활성이고, 짝지은 그룹·사장 계정의 글이며, 방 토픽에 쓴 답장 아닌 글은 그 방의 새 스레드에 사장 글로 올라간다. 앱 글과 같은 경로(`receive()`)이며 단체방 받는 직원은 `@이름`/대표 규칙을 따른다.
- AC-02(정상): 받은 글이든 보낸 글이든 hejo 글에 대응하는 텔레그램 글에 답장하면 그 hejo 글의 스레드에 올라간다(토픽과 상관없이 그 글의 방). 대상 글·스레드·방이 사라졌으면 AC-01처럼 그 토픽 방의 새 스레드다. 토픽 첫 글(토픽 만들기 표시)에 대한 답장은 답장이 아닌 것으로 본다.
- AC-03(정상): 사진·파일은 방 첨부로 저장해 같은 사장 글에 붙인다. 본문은 글·캡션이며, 어댑터가 본문에 붙인 문서 내용은 넣지 않는다. 본문과 첨부가 모두 없으면 올리지 않는다.
- AC-04(실패): 일반(General) 토픽, 대응 없는 토픽, 닫힌 방 토픽에 쓴 글은 올리지 않고 그 토픽에 "앱에서 만든 방 토픽에 써 주세요"를 보낸다.
- AC-05(실패): 활성이 아니거나, 짝지은 그룹·계정과 다르거나, 판정 코드가 예외를 내면 원래 처리기로 같은 이벤트 객체가 한 번 간다.
- AC-06(경계): 같은 텔레그램 글 id는 한 번만 올라간다(고친 글이 다시 와도 무시).
- AC-07(실패): 차지한 뒤 처리 실패(첨부 저장 실패·크기 초과·기록 오류)는 "지금은 받지 못했어요"를 보내고 원래 처리기로 넘기지 않는다.

### REQ-HT-05 발신

- AC-01(정상): 활성일 때, 문이 시작된 뒤 쓸 수 있는 방에 기록된 직원 남은 글은 정착 뒤 그 방 토픽에 `[직원 이름]` 이름표와 함께 간다. 알림이 울린다.
- AC-02(정상): 앱에서 쓴 사장 글은 정착을 기다리지 않고 `[사장]` 이름표로 간다. 알림은 울리지 않는다. 텔레그램에서 받은 사장 글은 다시 보내지 않는다.
- AC-03(정상): 한 스레드의 글은 기록 순서대로 간다. 스레드의 첫 텔레그램 글(받은 글이든 보낸 글이든)이 그 스레드의 닻이며, 이후 글은 닻에 답장으로 간다. 닻이 없으면 처음 보내는 글이 닻이 된다.
- AC-04(정상): 첨부는 같은 토픽에 파일로 보내며 그 글의 텔레그램 글에 답장으로 붙인다. 보내지 못한 첨부(크기 등)는 본문 끝에 `📎 이름 (hejo 앱에서 열기)` 줄로 남긴다. 버튼은 HEJO-IMESSAGE와 같은 덧붙임 줄로 보낸다.
- AC-05(정상): 텔레그램이 나눈 모든 통의 글 id를 같은 hejo 글에 대응시킨다(`sent.jsonl`). 문을 다시 시작해도 대응은 남는다.
- AC-06(실패): 발신 실패는 로그 한 줄(종류만), 다시 보내지 않음, 기록장·앱 영향 없음.
- AC-07(경계): 활성이 아닌 동안 기록된 글은 나중에 활성이 돼도 보내지 않는다. 생각 중 글·작성 중인 스레드의 글은 보내지 않는다. 남은 글 한계(HEJO-IMESSAGE REQ-HI-05.AC-12)는 그대로다.
- AC-08(보존): 이 기능이 있든 없든 기록장 행과 앱 프레임은 같다.

### REQ-HT-06 텔레그램 작성 중 표시

- AC-01: 활성일 때 방의 직원 차례가 도는 동안(문의 `send_typing`이 불리는 동안) 그 방 토픽에 텔레그램 작성 중 표시를 요청한다. 정지 요청은 없다(텔레그램이 스스로 끈다).
- AC-02: 요청 실패·지연은 차례와 발신을 막지 않는다. 표시용 글을 보내지 않는다.

### REQ-HT-07 앱

- AC-01: 설정 "연결과 동기화" 쪽의 아이메시지 구역을 "텔레그램" 구역으로 바꾼다: 상태(서버가 지원하지 않음 / 서버 연결 전 / 서버에 텔레그램이 연결돼 있지 않음 / 연결됨 / 연결 안 됨 / 토픽 권한 문제), 연결 코드 받기·복사·남은 초, 켜기, 연결 해제, 준비 안내 문구.
- AC-02: 방 메뉴의 아이메시지 두 항목과 아이메시지 상태 모델·시험을 지운다. 방 메뉴에 텔레그램 항목은 없다(모든 방이 대상).
- AC-03: `hello.features`에서 `imessage`를 빼고 `telegram`을 넣는다. 옛 문(텔레그램 미지원)에 붙으면 "서버가 지원하지 않음".
- AC-04: AppKit. SwiftUI 예외 없음.

### REQ-HT-08 아이메시지 연결 제거

- AC-01: 문은 `photon` 처리기를 등록하지 않는다. 아이메시지 글은 hejo가 차지하지 않고 원래 경로(Hermes·안내원)로 간다.
- AC-02: 아이메시지 모듈·프레임·앱 화면·시험·고정 시험 보조물이 남지 않는다(작업 문서·과거 증거 제외).
- AC-03: 서버의 옛 `imessage.json`·`shared/hejo/imessage/`는 지우거나 고치지 않는다.

### REQ-HT-09 서버 적용과 실물 확인

## 알려진 한계

- 텔레그램 어댑터는 짧은 간격의 연속 글을 한 이벤트로 합친다(첫 글 id 유지). 합친 글은 사장 글 하나가 된다.
- 텔레그램 어댑터는 본문의 마크다운을 텔레그램 서식으로 바꿔 보낸다.
- 문이 맡지 않은 글(활성 아님·다른 계정)은 Hermes 텔레그램 처리기로 간다(사장 결정). 운영 설정의 텔레그램 허용 계정이 마지막 문이다.
- 방이 많고 글이 몰리면 텔레그램 발신 속도 제한으로 늦어질 수 있다(어댑터가 기다린다).
