6. 기획설계로 넘긴 것(이번에 처리함)
   - D-1 기록 실패의 HTTP 상태. 설계는 오류를 4xx로만 적었고 구현은 `journal_write_failed`에 503을 쓴다. **구현이 옳다.** 요청을 거절한 것(다시 해도 같음)과 문이 쓰지 못한 것(다시 하면 될 수 있음)은 보내는 쪽이 다르게 다뤄야 하고, design 4.1의 다시 보내기 규칙도 이 구분을 전제한다. design 3.1을 "거절은 4xx, 기록 실패는 503, 보내는 쪽은 4xx면 끝내고 그 밖은 같은 열쇠로 다시"로 고쳤다.
   - D-2 고치기의 `reply_state: null`. 문의 `set_reply_state`는 상태를 지우는 동작이 없다. design 3.1에 "고치기의 `reply_state`는 기존 상태 값 중 하나, null 불가. 올리기에서는 null·생략이 상태 없는 글"을 적었다. 규격 파일의 고치기 요청에서 null을 빼는 것은 구현 몫이다.
   - 두 가지를 고정하는 AT-SM-09를 수락 시험 명세에 더했다(기록 실패 → 503 → 같은 열쇠로 복구, 고치기 null 거절).
   - 요구·범위·수락 기준의 뜻은 바뀌지 않았다. 설계가 비워 둔 계약 세부를 채운 것이라 사장 재승인 대상이 아니다.
