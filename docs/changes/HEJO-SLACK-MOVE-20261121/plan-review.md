- 3회차에 정한 네이버톡 열쇠 `사건 행 id + approval + status`가 틀렸다. PR-07을 고치려고 `notified`를 0으로 돌리는 쓰기를 모두 읽다가 찾았다. `bridge.py:801`과 `:817`은 `approval`을 빈 값으로 두고 `status`도 그대로인 채 사유만 바꿔 안내를 다시 내보낸다. 최초 초안의 `approval`이 빈 값이면 이 안내가 최초 글과 같은 열쇠가 되어 올라가지 않는다. `:817`이 두 번 일어나도 같다.
- 고침: 열쇠를 `사건 행 id + 알림 열쇠(notice_key)`로 바꿨다. 알림 열쇠는 0인 행을 올리려고 잡는 그 쓰기에서 새로 만들어 적고, 올리는 중(2)인 행은 적힌 값을 그대로 쓴다. 사건 표에 열 하나가 는다(이 파일이 이미 쓰는 열 추가 방식). 반영: design 4.1 발생 건 값 표와 네이버톡 항목, AT-SM-49b ⑧(같은 `approval`·`status`에서 다시 나가는 안내가 새 글), AT-SM-49c ①, handoff 2번.
- 3회차 기록의 PR-06 줄에 적힌 열쇠 값은 그때의 결정이고, 지금 유효한 값은 이 절이다.
