# HEJO-IMESSAGE 결정 요약 (브레인스토밍 2026-11-19)

근간은 [ARCHITECTURE.md](../../ARCHITECTURE.md)다. 이 문서는 브레인스토밍에서 정한 것만 적는다. 요구는 [spec.md](spec.md), 구조는 [design.md](design.md)가 원본이다.

## 목적

사장이 Mac 앞이 아닐 때도 아이메시지로 hejo 방의 직원과 대화하고 보고를 받는다. 대화는 hejo 방에 그대로 남는다.

| 항목 | 결정 | 출처 |

| 폰 보고 | 방마다 "폰으로 보고 받기" 스위치. 켠 방은 직원이 먼저 건 글과 앱에서 시작한 대화의 답도 폰으로 온다 | 사용자 결정 |

## 하지 않는 것

Hermes 본체와 아이메시지 문(photon) 수정, 사장 외 다른 사람과의 아이메시지 대화, 아이메시지 단체 대화방 연결, BlueBubbles 문 연결, 아이메시지 첨부 주고받기, 폰에서 버튼 누르기, 폰에서 연결 끄기.

## 실측 (2026-11-19, 이 서버)

- [확인] 아이메시지 문은 Hermes 플랫폼 플러그인 `photon`이며 켜져 있다. team-kit 안내원(`hermes_router`)이 `live`로 `slack`·`photon`·`bluebubbles`에 붙어 있다(`<운영 저장소>` team-kit `lib/hermes_router/plugin.py:22`).
- [확인] photon은 들어온 답장의 대상 글 id를 `reply_to_message_id`로 주고(`plugins/platforms/photon/adapter.py:852-860`), 보낼 때 `replyToMessageId`로 특정 글의 답장을 만들며 보낸 글 id를 돌려준다(같은 파일 `:1515-1538`).
- [확인] 플러그인은 `ctx.register_platform_handler(platform, factory)`로 다른 문의 수신(`handle_message`)을 감쌀 수 있다(`hermes_cli/plugins.py:859`, `gateway/platforms/base.py:2341`). team-kit 안내원이 이 방식이다(`lib/hermes_router/ingress.py:349-389`).
- [확인] 직원이 먼저 건 글은 문이 스레드 id를 만들어 방에 올린다(`gate/adapter.py:328-333`).
- [확인] 서버가 실행하는 문은 공용 릴리스 폴더의 사본이다(`<HOME>/plugins/hejo` 링크, `install/hejo-release`).

## 선행 조사

생략. 아이메시지 연결은 Hermes에 들어 있는 photon 문을 그대로 쓰고, 새로 만드는 것은 hejo 방과의 짝짓기뿐이라 가져다 쓸 외부 도구가 없다.

## 대안과 선택

| 대안 | 판정 | 이유 |
|---|---|---|
| 아이메시지를 hejo 방의 두 번째 문으로 | 채택 | 기록이 방에 남고 단체방이 된다 |
| 아이메시지에 답할 직원만 지정 | 기각 | 기록이 hejo에 안 남고 단체방이 안 된다 |
| 방마다 전용 스레드 하나 / 오래 쉬면 새 스레드 | 기각 | 답장을 스레드로 쓰면 경계가 눈에 보인다 |
| 서버가 이미 허용한 발신자를 사장으로 | 기각 | 허용된 사람이 여럿이면 모두 사장 글로 들어온다 |
| team-kit을 건드리지 않음 | 기각 | 안내원과 hejo 중 누가 먼저 잡는지가 플러그인 읽는 순서에 달린다 |
