# HEJO-DISCORD-FOLLOW 브레인스토밍 결정 요약

2026-11-27. 사장 실물 보고(휴대폰 디스코드 화면 2장)에서 시작했다.

## 사장 보고
1. 승인이 끝났는데도 포럼 글 제목이 빨간불(🔴)이다. 초록으로 바뀌어야 한다.
2. 포럼 글 묶음(스레드)이 끝없이 늘어나서 최신 글을 찾기 어렵다.
3. 어제(11-26) 오류 때 생긴 인스타그램 DM 알림 글이 너무 많다. 지워야 한다.

## 목적
디스코드가 hejo 기록장을 끝까지 따라가게 한다. 고치면 고치고, 끝나면 닫고, 지우면 지운다.

## 하는 것 · 하지 않는 것
- 하는 것: hejo 글 고침(`edit`)을 디스코드 본문에 반영하고, 그 글이 포럼 글의 첫 글이면 제목도 고친다. 종결된 글 묶음은 바로 보관하고, 하루 동안 새 글이 없는 글 묶음은 디스코드 자동 보관에 맡긴다. hejo의 글·스레드 삭제를 디스코드 글·글 묶음 삭제로 따라간다. 이미 hejo에서 지운 글은 새 문이 처음 켜질 때 한 번 정리한다.
- 하지 않는 것: 디스코드에서 고치거나 지운 것을 hejo에 반영하기(한 방향만 따라감), 상태에 맞춘 🔴/🟡/🟢 표식 규칙, 인스타 상태 알림을 한 스레드로 모으기(운영판 인스타 감시 수정).

## 칸 · 원본 · 쓰기 주체 · 수명
디스코드 문(`gate/discord.py`) 한 칸이다. 원본은 기록장이고, 대응은 이미 있는 `shared/hejo/discord/sent.jsonl`과 기록장 `client_msg_id`로 계산한다. 레코드 종류와 저장 파일은 늘리지 않는다. 고칠 곳은 공개판과 서버 운영 문 줄 두 줄이고, 서버 설치가 필요하다.

## 실측 [확인] (2026-11-27, 서버 기록장·대응표 읽기)
- 기록장 레코드 1575개: message 903, edit 315, state 169, delete 167, room 16, room_delete 5.
- 빨간불 사례: 인스타 DM 알림 글이 seq 1534에 `🔴 …`로 기록됐고, seq 1539에서 `✅ …`로 고쳐졌으며, seq 1540에서 `reply_state = closed`가 됐다. 디스코드 문 `recorded()`는 `message`만 발신 대기열에 넣고 `edit`·`state`·`delete`는 무시한다(공개 `gate/discord.py` `recorded`). 포럼 글 제목은 처음 보낼 때 첫 줄로 한 번만 정한다(`_send_message`의 `thread_name=title`).
- `sent.jsonl`(현재 짝 표지) 285줄, 글 묶음 114개. 그중 인스타 상태 알림 글 묶음이 56개다(못 읽고 있어 35, 다시 읽고 있어 14, 토큰 만료 7). 11-26 21시대에만 40개가 생겼다.
- 그 56개 알림 글은 hejo에서 이미 모두 삭제돼 있다. 디스코드에만 남아 있다.
- 처음 설계(HEJO-DISCORD spec 범위 밖)는 "보낸 뒤 고치거나 지운 글 반영, hejo 스레드 삭제의 디스코드 반영"을 미뤄 뒀다.

## 선행 조사
외부 도구를 고르는 일이 아니라 기존 문의 미뤄 둔 기능이라 오픈소스 조사는 생략한다. 디스코드 API 능력만 확인했다.

| 항목 | 결과 |
|---|---|
| 웹후크 글 고치기·지우기 | 서버의 discord.py 2.7.1에 `Webhook.edit_message`·`delete_message`·`fetch_message`(글 묶음 지정)가 있다 [확인] |
| 글 묶음 제목·보관·자동 보관·지우기 | `Thread.edit(name, archived, auto_archive_duration)`, `Thread.delete()`, 포럼 `edit(default_auto_archive_duration)`가 있다. 남이 만든 글 묶음은 `manage_threads` 권한이 필요하다 [확인: discord.py 2.7.1 docstring] |
| 제목 바꾸기 속도 제한 | 글 묶음 이름 바꾸기는 10분에 2번까지라고 알려져 있다 [가정 — 구현에서 실제 응답으로 확인] |
| 대체 수단 | 디스코드 쪽 설정·오픈소스로 대신할 방법 없음 |

## 대안과 선택 (사장 선택)
| 문제 | 선택 | 기각 |
|---|---|---|
| 1 초록불 | hejo 고침을 그대로 따라감(본문·첫 글이면 제목). 이번 사례는 ✅ | 문이 상태를 보고 🔴/🟡/🟢를 붙임 — 문에 해석 규칙이 늘어남 |

| 3 삭제 | hejo 삭제를 계속 따라감 + 이미 지운 것은 처음 켜질 때 한 번 정리 | 한 번만 정리(같은 문제 재발), 디스코드에서 손으로 지우기 |
