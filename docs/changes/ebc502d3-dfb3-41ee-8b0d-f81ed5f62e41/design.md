# 배치·입력 설계
6판 · 목표 · 기준은 [spec](spec.md).

## 현황과 원인
[확인] PetView.mouseDown/mouseDragged는 최초 anchor와 화면 포인터 차를 사용한다. 그러나 anchorOrigin은 drawerShift를 되돌린 좌표라 표시 위치와 다를 수 있다.
[확인] PetPlacement.init의 expanded 분기는 header 높이, minimumChatSize, perchScale로 펫을 다시 배치·축소한다. 접힌 분기도 말풍선 공간을 위해 sprite.origin.y를 올린다. withDrawer는 펫까지 왼쪽으로 이동한다.
[확인] PetController.setExpanded는 foldedPerchAnchor를 복원하고 placePet을 재호출한다. movePet은 petDragBottom과 carriedChatHeight로 높이를 변경한다. 이 경로들이 사용자 요구와 충돌한다. 실제 마우스 체감 재현은 미실행이다.
[확인] 일반 입력 흐름은 PetView → PetController.movePet → placePet → PetPlacement → apply(panel.setFrame/pet.arrange)다. 별도 창·새 타이머는 필요 없다.
외부 조사 생략: 저장소 내부 좌표 처리 결함이다.

## 선택
펫의 화면 좌표와 사용자 크기를 배치 기준으로 삼고, 채팅 사각형만 화면 가시 영역으로 보정한다. 같은 패널·기존 배치 객체를 유지한다. 대안인 별도 펫 창 분리는 포커스·창 계층·클릭 통과 책임을 늘리므로 채택하지 않는다. 개폐 직후 옛 좌표를 다시 덮는 우회는 중간 프레임 및 드래그를 고치지 못하므로 채택하지 않는다.
좌표는 AppKit 화면 좌표(pt). 화면 선택·펫 자체 제한은 기존 PetDisplay/constrainedSprite 책임을 유지한다. 창 로컬 좌표는 최종 펫·채팅 합집합에서만 파생한다. 전환·서랍·웹 너비 애니메이션의 출력은 펫 좌표에 역으로 쓰지 않는다.

## 경로 판정
| 경로 | 판정·변경 |
|---|---|
| PetView 입력 | 유지, 드래그 기준을 실제 표시 펫 좌표와 일치시킴. 최초 화면 포인터 기준 유지 |
| PetPlacement 초기화·withDrawer | 교체: 펫을 먼저 자체 화면 제한으로 확정, 채팅만 위치/크기 보정. drawerShift 좌표 복원 제거 |
| perchScale·foldedPerchAnchor | 개폐 시 강제 위치/축소 경로 제거. 사용처 전수 확인 뒤 불필요 상태·함수 제거 |
| movePet의 petDragBottom·carriedChatHeight | 제거: 드래그로 채팅 높이 저장값을 변경하지 않음 |
| PetBubbleMotion·genie | 유지: 채팅 표현 전용. 펫 입력은 같은 이벤트에서 적용 |
| dragged·resize·resizedSpriteOrigin | 기존 헤더 이동/가장자리 크기 조절 유지, 새 배치 기준과 충돌하는 재부착만 교체. 좌우 중심 유지·세로 반대쪽 가장자리 유지 검증 |
| paneAnchor·paneBelow | 웹 개폐 전 펫 좌표·방향을 복원하는 상태 제거. webChanged는 현재 펫 좌표로 채팅만 재배치한다. 웹 폭·높이 선호 저장은 유지 |
| expandToFit | 채팅 표시 영역 확보만 유지, 헤더를 올리면서 펫을 움직이는 효과 제거 |
| resizedBelow | 사용자가 크기를 바꾼 채팅의 위/아래 배치 선호로만 유지. foldedPerchAnchor·carry에서의 강제 설정과 웹의 옛 방향 복원은 제거. 펫 좌표 계산에는 영향 없음 |
| 접힌 말풍선 공간 보정 | sprite.origin.y를 올리는 경로 제거. 말풍선만 이동·표시 크기 보정하며 펫 위치 고정 |
| fitOpenThread·toggleChatWidth·resetChatSize·사이드바 폭 변경 | 기능 유지, spec의 현재 펫 쪽 가장자리 고정 규칙으로 새 크기를 적용한 뒤 화면 제한만 반영하도록 재배치 호출을 통합. 헤더 이동 이전의 펫 중심 배치로 복귀 금지 |
| screensChanged | 화면 변경 안전 복귀 유지. 현재 펫·채팅 사각형을 각각 새 화면에 보정하며 현재 화면에서 유효한 위치는 유지 |
| LocalStore | 기존 좌표·크기 필드 재사용, 이관·새 필드 없음 |

채팅은 기존 위/아래 선호를 재사용하되 공간이 부족하면 화면 내 이동·크기 보정하며 펫을 옮기지 않는다. 충분한 공간에서는 선호 크기를 유지한다. 펫과 채팅 표시 영역은 겹치지 않도록 같은 배치 책임에서 계산한다. 최소 크기보다 작은 화면에는 기존 화면 맞춤을 적용하고 음수 크기를 만들지 않는다.

위험도 일반: 되돌릴 수 있는 UI 버그 수정, 저장 형식·권한 변경 없음. 별도 사전 검토를 의무화할 불확실한 외부 계약은 없음. 필요한 증거 수준 1(빌드), 2(주입한 화면·시계로 AppKit 통합), 3(격리된 실행 앱의 실제 마우스). 복구는 이 작업 코드 커밋만 되돌리고 운영 설정을 건드리지 않는다.

## 헤더 이동 후 위치 보존
헤더 입력 시작의 펫·채팅 사각형과 포인터를 기준으로 두 사각형에 동일 변위를 적용한 뒤 각각 화면 제한한다. 제한으로 상대 간격이 달라져도 놓기·서랍/웹 갱신에서 헤더에 재부착하지 않는다. 현재 배치 객체를 단일 실행 상태로 유지하고, 필요한 상대 배치는 그 객체에서 파생한다. 새 영구 좌표 필드나 두 번째 원본은 만들지 않는다. 기존 dragged 및 endChatDrag의 재계산 경로를 이 기준에 맞춰 함께 교체한다.

실제 입력 지연의 원인은 아직 미확정이다. 좌표 제약 확인을 지연 원인 확정으로 보지 않는다. 구현 전 기준판과 수정판의 같은 시나리오에서 입력·표시 결과를 비교하며, 지연이 남으면 이벤트 전달·apply/arrange 소요를 조사하고 결과를 보고한다.

## 크기 변경 좌표 (4판)
자동 크기 변경 직전 채팅 사각형을 B, 새 표시 크기를 (w,h)라 하면 화면 제한 전 후보는 아래 배치에서 (B.minX, B.maxY-h, w, h), 위 배치에서 (B.minX, B.minY, w, h)다. 배치 방향은 크기 변경 직전의 방향을 사용하며 이 연산 때문에 바꾸지 않는다. 이후 기존 화면 제한을 채팅에만 적용한다. 직접 경계를 끄는 리사이즈는 이 자동 크기 변경 공식과 구분한다. 현재 펫 쪽 가장자리의 화면 좌표를 유지하므로 헤더 이동 이후에도 펫 좌표에서 다시 헤더를 산출하지 않는다.

## 직접 리사이즈 설계 정정 (5판)
4판에서 모든 직접 경계의 반대쪽 고정을 기존 동작이라고 기술한 것은 설계 오류다. PetLayout.resized와 AT-DI-11, logs/resize-contract-probe.log의 기준판 관측(오른쪽 +40: minX 386→346, width 428→508)을 근거로 좌우 중심 유지 계약을 보존한다. 화면 끝 및 trailing 웹 칸 때문에 비대칭으로 제한되는 기존 분기도 보존한다. 펫과 분리된 배치에서는 현재 채팅 콘텐츠 중심을 기준으로 계산하여 펫 위치에서 채팅을 다시 정렬하지 않는다. 세로 near/far는 반대쪽 경계 고정, 대각선은 축별 규칙을 적용한다. 자동 크기 변경의 minX·펫 쪽 가장자리 고정은 4판 그대로이며 직접 리사이즈와 구분한다.

## 겹침 방지 보완 (6판)
[확인] constrainedBubble은 화면 경계만 입력받아 펫 영역을 알 수 없다. 초기 배치뿐 아니라 withDrawer/dragged/placePet의 재배치와 stepPlacement의 중간 표시가 이를 통과하거나 직접 사각형을 만들기 때문에 화면 아래쪽에서 채팅이 펫 내부로 밀릴 수 있다. 실물 사용자 보고 및 logs/manual-fixed-user-summary.json에 겹침 좌표가 확인됐다.

기존 PetLayout의 채팅 제한 책임을 확장하여 실제 펫 사각형을 입력받고 화면 가시 영역 안의 비겹침 채팅을 계산한다. 별도 창·충돌 감시 타이머·새 저장 원본은 만들지 않는다. 펫의 placementSprite(in:)를 보존해야 할 영역으로 삼고, 채팅 경계와 접할 수는 있으나 내부 교차는 허용하지 않는다. 기존 화면 여백 및 가능하면 기존 간격을 유지한다.
현재 요청 위치가 안전하면 그대로 유지한다. 안전하지 않으면 펫 위·아래·좌·우의 화면 내 후보 영역 중 선호 크기가 들어가는 것을 먼저 선택하고 현재 위치에서 이동이 작은 것을 우선한다. 선호 크기를 유지할 수 없으면 최소 채팅 크기를 만족하는 후보를 우선하고, 같은 조건에서는 표시 면적과 이동 거리로 안정적으로 선택한다. 한 후보 안에서 실제 표시 크기만 제한한다. 모든 후보가 최소 크기 미만이면 양의 크기가 가능한 최대 영역을 쓰고 기존 좁은 화면 처리를 따른다. 유효 비겹침 영역 자체가 없는 비현실적 화면은 펫을 강제 이동하거나 겹침으로 우회하지 말고 경계 처리와 시험 결과를 보고한다.

초기 개폐·헤더/펫 이동·서랍/웹·직접 리사이즈·자동 높이·화면 변경을 같은 계산으로 통합한다. 기존 center/고정 가장자리 규칙은 충돌 없는 범위에서 유지한다. 서랍 및 웹 폭은 최종 가용 폭에 맞게 기존 분배 규칙으로 다시 계산하여 음수 콘텐츠 폭을 만들지 않는다. bubbleBelow는 최종 배치에 맞춰 일관되게 유지한다.
애니메이션 목표만 안전하고 중간 프레임이 펫을 통과해서는 안 된다. 기존 모션의 중간 사각형도 같은 제약을 만족시킨다. 방향 전환 경로가 안전하지 않으면 해당 채팅 위치 전환을 즉시 적용할 수 있으나 펫 좌표를 보간/복원하지 않는다. 코드 상수만 검사하지 말고 최종 view→screen 사각형으로 확인한다.

## 사용자 배치 정정 (2026-11-24, 7판)
사용자 실물 확인에서 좌우 회피 배치는 의도와 다름이 확인됐다. 펫은 채팅 위쪽 가장자리에 있거나 채팅 아래에 있어야 한다. 기존 6판의 좌/우 회피 후보는 폐기한다. 펫의 화면 위치·사용자 크기·포인터 추종은 그대로 유지하고 채팅만 위/아래 중 가능한 공간으로 배치한다. 위아래 공간이 부족하면 채팅 표시 높이를 줄이며 저장 선호 높이는 유지한다. 이미 비중첩이어도 옆으로 배치된 사각형은 유효하지 않다. 펫 중심이 채팅 가로 범위 안에 있도록 채팅 가로 좌표도 제한한다. T6에는 옆 배치 거부, 양쪽 높이 부족 시 수직 축소, 실제 드래그/애니메이션 프레임의 수직 분리 단정을 추가한다. 별도 담당 재배정·재승인 없이 사용자의 직접 구현 지시를 계속 따른다.

7판의 위쪽 걸침은 펼친 채팅의 상단 헤더 20pt에만 허용한다. 이는 6판의 전체 사각형 무교차 조건을 대체하며 본문과의 교차는 계속 금지한다. 접힌 말풍선에는 걸침을 허용하지 않는다. 아래쪽 배치는 비중첩을 유지한다.
