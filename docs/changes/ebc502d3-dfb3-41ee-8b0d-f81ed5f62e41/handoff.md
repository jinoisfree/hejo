## 실행 전후 오염 검사 (3판, R6)
기준판·수정판의 수동 모드 모두 `app/Tests/settings_guard.py`와 `app/Tests/downloads_guard.py`를 snapshot/verify로 실행 전후 감싼다. trap으로 정상 종료·실패·중단에서도 verify를 수행하고 하나라도 실패하면 전체 검증을 실패로 기록한다. snapshot 파일은 임시 루트에만 두고 내용을 로그에 출력하거나 공개 증거로 복사하지 않는다. guard가 실패해도 사용자 파일을 자동 복원·삭제하지 않는다.

[확인한 검사 한계] settings_guard는 CLI 설정 일부의 메타데이터, downloads_guard는 다운로드 폴더 항목 이름만 비교한다. 모든 사용자 설정·기존 다운로드 파일 내용 변경을 검출한다고 보고하지 않는다. TASK-00에서 같은 메타데이터 방식으로 운영 hejo Application Support 및 이 시험이 접근할 수 있는 사용자 설정 파일의 존재/항목/크기/mtime/ctime 비교를 추가하고, 다운로드 기존 항목의 변경도 메타데이터로 검사한다. 내용은 읽지 않는다. 범위 밖 경로에 대한 쓰기 가능성이 남으면 수동 모드를 실행하지 않고 보고한다. 실행 중 사용자가 한 변경도 검사 실패로 남기며 원인을 구분한다.

현재 handoff의 예정 실행 명령은 다음 wrapper 안에서 실행하도록 구현한다(저장소 루트 기준; 아래도 미실행 절차다).

```sh
"${HEJO_PYTHON:-python3}" app/Tests/settings_guard.py snapshot "$pet_probe_root/settings-before.json"
"${HEJO_PYTHON:-python3}" app/Tests/downloads_guard.py snapshot "$pet_probe_root/downloads-before.json"
```

실행 뒤 또는 trap에서 각 명령의 `snapshot`을 `verify`로 바꿔 같은 경로로 검사한다. 테스트 전용 추가 메타데이터 검사도 같은 수명으로 실행한다. 각 종료 코드를 따로 기록하며 마지막 성공 명령으로 앞 실패를 가리지 않는다.
웹 fixture는 WebPane의 `persistent: false` 경로를 사용해 `WKWebsiteDataStore.nonPersistent()`를 쓰고, 생성된 웹 보기마다 비영속 여부를 검사한다. 로컬 가짜 문서만 사용하고 운영 웹 데이터 저장소·인증 자료에 접근하지 않는다.

## 재인계: V1 설계 정정 및 남은 구현
검토 대상 준비 커밋은 `b1e3a8ccb617b74044c116988c891cce324af7f5`이며 제품 기준은 최초 base_commit 그대로다. [verdict](verdict.md)의 V1은 설계/수락 명세 오류로 5판에서 정정했다. 좌우 기존 중심 유지·세로 반대쪽 고정을 보존하며 원래 사용자 요구나 승인 범위를 늘리지 않는다. 기존 승인으로 TASK-01·02를 계속한다. 기존 작업 공간·구현 담당을 유지한다.

현재 수동 모드는 `bash app/scripts/pet-position-manual.sh`를 실행하며 wrapper가 --probe-root 등 임시 경로와 보호 검사를 설정한다. 위 초기 계획의 직접 app-tests 예시는 준비 당시 기록으로, 현재 실행은 wrapper를 사용한다. --probe-duration은 시작 smoke만 의미한다. 실제 입력을 수행하지 않았으면 성공으로 기록하지 않는다.
실제 서랍/웹 표시 확인을 위해 현재 단순 PositionCanvas와 설치된 하위 뷰가 조작 결과를 표시하는지 확인하고, 필요한 테스트 fixture만 완성한다. 임시 로컬 문서·비영속 웹·무통신 경계 유지. 보호 검사의 정상 종료는 기존 증거 재사용, 실패·INT·TERM 종료 검증은 임시 대역을 이용해 실제 사용자 파일을 바꾸지 않고 수행한다.
