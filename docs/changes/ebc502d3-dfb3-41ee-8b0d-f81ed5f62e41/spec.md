## 목적·범위
사용자 요청: 채팅을 여닫아도 펫이 제자리에 있고, 열린 상태에서도 마우스로 잡은 위치를 따라 움직인다. 기존 AppKit 배치·입력 책임 안에서 수정한다. 채팅은 펫 근처를 선호하되 화면 안으로 독립 보정한다. 펫을 헤더 위에 강제로 붙이거나 채팅 때문에 축소하지 않는다.
운영 설치·게이트웨이·외부 메시지·통신·데이터 변경은 범위 밖이다.

## 요구·수락 기준
- REQ-PP-01 / AC-01 (정상·경계): 유효한 화면 위치의 펫을 기준으로 채팅 열기/닫기/재열기와 전환 도중 반전의 모든 배치 프레임에서 화면상 펫 사각형의 위치·크기가 유지된다. 화면 모서리, 위·아래, 큰 채팅, 할 일 칸·웹 칸 열린 상태도 같다. 웹 칸 자체의 열기/닫기, 웹 칸을 연 뒤 펫 또는 헤더를 이동하고 웹 칸을 닫는 경우도 마지막 펫 위치를 유지한다. 접힌 말풍선의 공간 부족은 말풍선만 보정한다. 애니메이션 포즈 자체의 픽셀 차이는 제외한다.
- REQ-PP-02 / AC-01 (정상): 드래그 판정 이후 매 입력마다 펫 화면 좌표 = 누를 때의 화면 좌표 + 누를 때부터의 포인터 이동량. 수평·수직·대각·방향 반전, 펼침·접힘·전환 도중 모두 동일하다. 놓을 때 튀거나 클릭으로 채팅을 토글하지 않는다. 기존 4pt 클릭/드래그 문턱은 유지한다.
- REQ-PP-02 / AC-02 (경계): 화면 가장자리에서는 펫 자체의 기존 화면 제한만 적용한다. 채팅 최소 높이·헤더·서랍 폭 때문에 펫 이동이 더 제한되거나 크기가 달라지지 않는다. 다른 화면 및 음수 원점 화면에서도 동일하다. 화면 제거 시 기존 안전 복귀는 유지한다.
- REQ-PP-03 / AC-01 (정상·경계): 채팅은 화면 가시 영역 안에 배치되고 필요하면 위치·표시 크기를 보정한다. 펫을 끄는 동작으로 저장된 채팅 선호 크기를 바꾸지 않는다. 할 일·웹 칸의 폭 배분과 사용 가능한 채팅 입력·접기·리사이즈는 유지한다. 헤더를 끌면 누를 때의 펫·채팅 화면 사각형에 같은 포인터 변위를 적용하고 각자 화면 제한만 받는다. 헤더에 펫을 다시 붙이지 않는다. 놓기·다음 배치 갱신에서도 채팅이 이전 위치로 되돌아가지 않는다. AT92의 헤더 이동 중 높이 유지·화면 넘기기와 AT-DI-13의 오른쪽 경계·서랍 유지 기대는 보존한다.
- REQ-PP-03 / AC-02 (회귀): 드래그 종료 뒤 저장·새 컨트롤러 복원 시 최종 펫 위치와 사용자 크기가 유지된다. 개폐·할 일 칸 폭 보정만으로 저장 좌표를 바꾸지 않는다. 펫 클릭, Escape, 닫기 버튼, 편집기 포커스, 투명 영역 클릭 통과가 유지된다.

## 기존 기준과의 차이
[확인] TestMain.swift의 PetCarrySmoke 기대값은 아래쪽 고정/드래그로 높이 변경을 요구한다. 새 REQ-PP-02·03으로 교체한다. FOUNDATION REQ-HF-36.AC-06의 위쪽 자리 기억·기존 끌기 동작 중 이 요구와 충돌하는 부분도 대체한다.
[제안] DRAWER-INLINE REQ-DI-03.AC-01·02의 펫 동반 이동/복귀만 폐기하고 창의 화면 안 보정은 유지한다. 열린 칸이 채팅 개폐·드래그 때 펫을 옮기는 같은 원인이므로 이 변경 범위에 포함한다. 첫 계획 승인 시 함께 승인된다. 과거 문서는 이력으로 보존하고 적용 뒤 현재 명세에서 대체 관계를 연결한다.

## 완료 조건
모든 AC의 자동 회귀 및 실제 AppKit 입력 증거, 빌드·프로젝트 시험·개인값 검사 통과, 별도 구현 보고에 대한 검토와 현재 명세 반영. 실환경 드래그 확인을 못 하면 미확인으로 남기며 완료로 판정하지 않는다. 푸시는 별도 화면 승인이다.

## 재배치 회귀 범위 (4판)
REQ-PP-03.AC-01의 헤더 이동 뒤 위치 보존은 fitOpenThread, toggleChatWidth, resetChatSize, 사이드바 폭 변경, screensChanged에도 적용한다. 자동 높이 맞춤·폭 전환·크기 초기화·사이드바 폭 변경에서는 현재 채팅의 왼쪽 가장자리와 펫 쪽 수평 가장자리를 고정한다. 아래 배치이면 현재 maxY(위 가장자리), 위 배치이면 현재 minY(아래 가장자리)를 고정하고 새 크기를 적용한다. 현재 가장자리를 유지하는 것이며 펫 위치에서 가장자리를 다시 계산하지 않는다. 화면 제한 및 펫과의 겹침 방지에 필요한 채팅 이동·표시 크기 보정만 허용하며 펫은 움직이지 않는다. 직접 좌우 경계 리사이즈는 기존 중심 유지와 화면 끝·웹 칸에 따른 비대칭 제한을 보존한다(AT-DI-11). 헤더 이동으로 펫과 채팅 중심이 달라진 뒤에는 현재 채팅 중심을 기준으로 하여 옛 펫 중심으로 복귀하지 않는다. 직접 세로 경계 리사이즈는 반대쪽 가장자리 고정을 유지한다. 대각선은 각 축 규칙을 함께 적용한다. 펫 기준으로 다시 가운데 정렬하거나 이전 헤더 위치로 복귀하지 않는다. 화면 제거·가시 영역 축소 시에는 현재 화면상의 위치에서 각각 안전 영역으로 복귀한다. 사용자 명시적 위치 초기화는 이 보존 규칙의 대상이 아니다.

## 사용자 실물 피드백 반영 (6판)
사용자가 수정판에서 드래그 추종은 정상이나 펫이 채팅 내부로 들어간다고 보고했다. 첨부 화면과 보존한 실제 입력 좌표가 근거다. 기존 겹침 허용은 폐기한다.
- REQ-PP-04 / AC-01: 개폐·펫/헤더 드래그·놓기·창 크기/자동 높이 변경·서랍/웹 칸 개폐·화면 변경 및 전환 표시 중, 채팅의 실제 표시 사각형과 펫의 placementSpriteBounds 영역은 겹치지 않는다. 투명 atlas 여백을 충돌 영역으로 취급하지 않는다.
- REQ-PP-04 / AC-02: 펫 좌표·사용자 크기는 개폐와 충돌 보정으로 바뀌지 않고 포인터를 그대로 따른다. 충돌은 채팅 위치/표시 크기만 조정하여 해결한다. 채팅 선호 크기를 덮어쓰지 않는다. 화면 안에 기존 크기를 유지할 자리가 있으면 불필요하게 줄이지 않는다.
- REQ-PP-04 / AC-03: 화면 내부의 비겹침 공간이 선호 크기보다 작으면 사용 가능한 영역에 표시 크기를 맞추되, 가능한 후보 중 최소 채팅 크기를 충족하는 공간을 우선한다. 스크롤·입력·접기 기능을 유지한다. 드래그 중 공간 확보를 위해 채팅이 옮겨질 수 있으나 펫을 헤더 위치로 끌어오거나 축소하지 않는다.
기존 REQ-PP-03의 헤더 동일 변위·고정 가장자리 기대는 화면 제한 또는 겹침 회피가 필요한 경우 채팅에 한해서 보정 예외를 적용한다. 펫 드래그 추종에는 예외를 추가하지 않는다. 관련 T1~T5의 공간 충분한 기존 기대는 유지한다.

## 사용자 배치 정정 (2026-11-24, 7판)
사용자 실물 확인에서 좌우 회피 배치는 의도와 다름이 확인됐다. 펫은 채팅 위쪽 가장자리에 있거나 채팅 아래에 있어야 한다. 기존 6판의 좌/우 회피 후보는 폐기한다. 펫의 화면 위치·사용자 크기·포인터 추종은 그대로 유지하고 채팅만 위/아래 중 가능한 공간으로 배치한다. 위아래 공간이 부족하면 채팅 표시 높이를 줄이며 저장 선호 높이는 유지한다. 이미 비중첩이어도 옆으로 배치된 사각형은 유효하지 않다. 펫 중심이 채팅 가로 범위 안에 있도록 채팅 가로 좌표도 제한한다. T6에는 옆 배치 거부, 양쪽 높이 부족 시 수직 축소, 실제 드래그/애니메이션 프레임의 수직 분리 단정을 추가한다. 별도 담당 재배정·재승인 없이 사용자의 직접 구현 지시를 계속 따른다.

7판의 위쪽 걸침은 펼친 채팅의 상단 헤더 20pt에만 허용한다. 이는 6판의 전체 사각형 무교차 조건을 대체하며 본문과의 교차는 계속 금지한다. 접힌 말풍선에는 걸침을 허용하지 않는다. 아래쪽 배치는 비중첩을 유지한다.
