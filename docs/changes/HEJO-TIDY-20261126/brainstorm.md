# HEJO-TIDY 브레인스토밍 결정 요약 (2026-11-26)

- **목적:** ① 대기 중인 공개 작업을 검토해 커밋하고 푸시한다. ② 업데이트 뒤 Mac에 이전판 hejo가 남지 않게 한다. ③ 공개판 전체 코드에서 쓰이지 않거나 중복된 코드를 정리한다. ④ HEJO-ALERT-SEEN 후속 과제 V-3(말풍선·섬 클릭 시험)과 V-4(제목 이중 공백)를 처리한다. ④는 브레인스토밍이 끝난 뒤 사용자가 추가했다.
- **순서(사용자 결정):** 푸시 → 업데이트 정리 → 코드 정리.
- **하는 것:**
  - 공개 대기 브랜치 통합·푸시. 개발 저장소의 미커밋 문서는 로컬에서만 커밋한다.
  - 앱의 이전판 사본 정리.
  - `get-hejo`가 설치 뒤 앱을 열면 앱의 정리가 돌게 한다.
  - 검증 설치 백업 절차 개정.
  - 공개판 코드 정리(동작 보존).
- **하지 않는 것:**
  - 개발 main을 공개판에 푸시하지 않는다(이력 무관).
  - 다른 번들 ID나 `/Applications`·`~/Applications` 밖의 파일은 건드리지 않는다.
  - 영구 삭제하지 않는다.
  - 코드 정리 중 동작은 바꾸지 않는다.
- **칸:** 정리는 관제 화면(hejo 앱) 칸이 맡는다. 그 칸의 수명이 "앱은 갱신 때 교체"이므로 이전판 처분은 이 칸의 책임이다. `get-hejo`는 정비 격납고 칸이다. 새 저장 위치·두 번째 원본은 만들지 않는다.
- **실측:**
  - [확인] Sparkle은 실행 중인 번들 자리만 교체한다.
  - [확인] `get-hejo`는 `/Applications/hejo.app`만 지우고 새로 넣는다.
  - [확인] 이 서버 Mac의 `/Applications`에 같은 번들 ID의 0.2.7(9) 사본 두 개가 있다: `hejo-typing-previous.app`, `hejo-connection-stuck-…-previous.app`. 현재판은 0.2.8(10)이다.
  - [확인] 사본의 출처는 검증 담당의 수동 설치 스크립트다(`docs/changes/f1c5ef47-…/impl-report.md:121`).
- **선행 조사:** 생략. Sparkle 2에는 다른 사본을 정리하는 기능이 없다는 학습 지식을 가설로만 쓴다. 내부 설치 위치 문제이고, 동작은 번들 ID·버전 비교와 휴지통 이동뿐이라 외부 도구가 필요 없다.
- **대안:**
  - 앱 + 설치 스크립트 + 절차를 함께 고친다. **선택.**
  - 설치 스크립트만 고친다. 기각: Sparkle로만 갱신하는 Mac에는 사본이 남는다.
  - 한 번만 손으로 정리한다. 기각: 같은 일이 되풀이된다.
- **가정:**
  - 사용자 결정: 범위, 순서, 정리 방식 "앱+설치스크립트+절차 모두", 코드 정리 범위 "공개판 전체".
  - 에이전트 제안: 휴지통 이동, 더 낮은 빌드 번호만 정리, `get-hejo`에 정리 로직을 따로 두지 않고 앱 실행으로 대신하기(설계 D-03).
- **열린 질문:** 맥북의 정확한 사본 목록. 릴리스 설치 뒤 사용자 확인(M-01)으로 대신한다.
- **위험도 1차:** 일반.
- **진행 방식:** 연합개발, 계획 검증 켬.
