# HEJO-THREAD-DONE 명세 — 완결 스레드의 초록 상태 막대

## 문제
사장이 버튼 대신 글로 고칠 점을 보내고 직원이 반영했다고 답해 끝난 스레드가 계속 빨강이다. 완결 판정이 승인 단어만 인정하고, 판정 색이 비면 화면이 첫 보고 제목의 🔴로 돌아가기 때문이다.

## 요구·수락 기준
REQ-TD-01: 사장이 직원 요청에 답한 뒤 직원이 그 스레드에 다시 답하면 그 스레드는 완결이다.

- AC-01 정상: 직원 요청(버튼·reply_state=asked·승인 요청 문장 중 하나)이 있고, 그 뒤 사장 글(승인 단어 여부 무관, 해당 요청 대상 또는 대상 없음)이 있고, 그 뒤 작성이 끝난 직원 글이 하나 이상 있으면 판정은 settled=true, 색 `#2EB67D`, 종 없음(nil), 알림·질문 목록 제외다. 첫 글 제목에 🔴가 있어도 카드 상태 막대는 초록이다.
- AC-02 경계: 완결 뒤 직원이 새 요청을 올리면 그 새 요청 기준으로 다시 판정한다(답 전이면 질문 대기 빨강).
- AC-03 경계: 사장 답 뒤의 직원 글이 작성 중(streaming)뿐이면 완결이 아니다. 생각 중 글은 기존대로 판정에서 뺀다.
- AC-04 경계: 대상 지정 답(answer_to)이 다른 요청을 가리켜 남은 요청이 답을 못 받았으면 그 요청은 기존대로 대기(빨강)다.
- AC-05 회귀: reply_state=closed는 초록, reply_state=answered이면서 사장 답 뒤 직원 글이 없으면 처리 중 노랑, 승인 단어 답 뒤 직원 글 전이면 기존 승인 초록, 버튼 노출·숨김 규칙은 그대로다.

REQ-TD-02: 요청이 있던 스레드는 보고 제목 표시 색으로 되돌아가지 않는다.

- AC-06 정상: 요청이 있고 판정 색이 없으면(예: 사장이 승인 단어가 아닌 답을 보냈고 직원 답 전) 작업 중이면 노랑, 아니면 상태 색 없음이다. 제목의 🔴❌🚨⛔ 등으로 빨강이 되지 않는다.
- AC-07 회귀: 요청이 없는 스레드(보고만 있는 스레드)는 기존대로 제목 첫 표시로 색을 정한다(🔴 빨강, ✅ 초록 등). 작업 중이면 기존대로 노랑이 우선한다.

## 기존 규칙과의 관계
HEJO-FOUNDATION spec REQ-HF-27.AC-03 상태 막대 줄의 "승인 뒤 직원이 답하면 초록"을 "사장이 답한 뒤 직원이 다시 답하면 초록"으로, 제목 표시 색 적용을 "요청이 없는 스레드"로 좁힌다. 사장이 직접 고른 ddots와의 차이다(2026-11-24).

## 수락 시험
기대값 원본은 위 AC와 사장 결정이다. 앱 swiftc 시험(가짜 저장소·가짜 명부)으로 실제 `ConversationModel`·`ThreadAssessment`와 카드가 쓰는 상태 색 계산을 실행한다.

| AT-TD-02 | 02 | AT-TD-01 뒤 직원이 버튼 asked 새 요청 | pending=새 요청, 카드 빨강 |
| AT-TD-03 | 03 | 사장 비승인 답 뒤 (a) 직원 streaming 글만 (b) 직원 생각 중 글만 | (a)(b) 모두 settled=false, 카드 빨강 아님 |
