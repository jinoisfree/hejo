# 브레인스토밍 결정 요약 — 완결된 스레드의 상태 막대

- 목적: 사장이 답하고 직원이 다시 답해 끝난 스레드의 왼쪽 상태 막대가 빨강으로 남지 않고 초록이 되게 한다.
- 하는 것: 스레드 상태 판정의 '완결' 조건 변경, 요청이 있던 스레드에서 제목 표시(🔴 등) 색을 쓰지 않음.
- 하지 않는 것: gate·직원 규칙·reply_state 기록 방식 변경, 새 저장 필드, 버튼 동작 변경.
- 칸·원본·쓰기 주체·수명: 앱(대화 화면)의 파생 상태. 원본은 기존 기록장 투영(`ThreadAssessment`)이고 새 저장은 없다. 쓰기 주체 없음(읽기 파생), 수명은 화면 계산 시점.
- 실측 [확인]: 신고 스레드는 직원 요청 글 2개(버튼 4개, reply_state=asked) → 사장 자유 글 1개(승인 단어 아님, answer_to 없음) → 직원 글 2개. 현재 판정은 pending 없음·working 없음·settled 없음·approved 없음이라 색이 비고, 화면이 첫 글 제목의 🔴로 되돌아가 빨강이 된다(`app/Sources/ConversationView.swift:969`, `app/Sources/ThreadTools.swift:88-111`).
- 선행 조사: 외부 도구·오픈소스 해당 없음(앱 내부 파생 규칙의 국소 수정). 기존 규칙 원본은 HEJO-FOUNDATION spec REQ-HF-27.AC-03 상태 막대 줄(ddots 기준).

| 대안 | 판단 |
|---|---|
| A. 사장 답 뒤 직원이 다시 답하면(작성 중 제외) 완결 → 초록, 요청 스레드는 제목 색 미사용 | 채택(사장 선택) |
| B. 승인 단어만 완결 유지, 빨강만 제거 | 기각: 의견으로 끝낸 스레드가 계속 미완결로 보임 |
| C. 직원(gate)이 closed 상태를 명시 기록 | 기각: 직원 규칙·gate까지 바꿔야 하고 기존 스레드는 그대로 빨강 |

- 가정: [사용자 결정] 완결 기준은 A. [에이전트 제안] 요청이 있던 스레드는 제목 표시 색으로 되돌아가지 않는다(답 뒤 직원 답 전 공백 구간에서 빨강 재발 방지). [에이전트 제안] 작성 중(streaming) 직원 글은 완결 근거가 아니다.
- ddots 동일 원칙과의 관계: 이번 완결 기준은 사장이 직접 고른 차이다(2026-11-24).
- 열린 질문: 없음.
- 위험도 1차: 일반(표시 상태·종·알림 목록이 같은 판정을 씀).
