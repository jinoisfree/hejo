# HEJO-JUMP-ONCE 명세

- 상태: 5판 · 적용(공개판 제품 커밋 `708a6dadf22f0840c4a07195e8f5647e856433ad`, 검증 완료 [verdict.md](verdict.md) 5회차; 검증 3회차 AT-JO-08·18 입력 보완, [plan-review.md](plan-review.md)) · 2026-11-26
- 작업 유형: 의미 변경(화면 동작) · 위험도: 일반 · 운영 모드: 교차 모델(+계획 검증)
- 결정 근거: [brainstorm.md](brainstorm.md). 기준 커밋: 착수 시 고정([handoff.md](handoff.md) 0절)

## 1. 문제
[확인] 기록 나눠 받기 모드에서 가운데 카드창의 카드를 누르면 대화 목록이 여러 번 나눠 움직이고, 카드창과 대화 목록 맨 위에 "갱신 중" 줄이 끼었다 빠지며 내용이 오르내린다(근거: brainstorm 실측).
[확인] 글 하나를 보내고 답을 받는 동안에도 카드창 맨 위 "대화 알림을 갱신 중이에요."가 16.7초 영상에서 반복해 나타났다 사라진다(2026-11-26 19:35 화면 기록, 2fps 표본 32장 중 약 10장, 눈으로 셈). 직원 답이 써지는 조각(`edit`, `final:false`)마다 앱이 서버 집계 전체를 다시 묻기 때문이다(`ConversationController.swift` `onHistoryFrame` → `HistoryCoordinator.liveChanged`, `ConversationModel.apply`의 `history.refreshing = true`).

## 2. 목표
한 번의 누름에 대화는 한 번 움직이고 멈춘다. 갱신 표시와 안내는 내용의 자리를 밀지 않는다. 카드창에 뜬 카드는 누르면 서버 응답을 기다리지 않고 움직인다(대상이 그 대화의 최근 쪽 안일 때). 직원 답이 써지는 동안에는 서버 집계 전체 갱신이 돌지 않는다.

## 3. 범위
- 안: 앱(`app/`)의 대화 목록 이동, 이동을 부르는 입구, 카드창·대화창의 갱신 표시와 안내 줄, 기록 불러오기 조정자의 미리 받기, 실시간 글 조각이 전체 갱신을 일으키는 조건, 그 시험.
- 밖: 문(gate)·허브·통신 규격·기록장 형식, 카드창 카드의 내용·정렬·개수, 선택이 바뀔 때 도는 전체 갱신의 구조, 맨 위 "이전 글 보기" 줄과 빈 목록 줄, 전량 수신 모드의 불러오기 동작, 새 버전 빌드·배포·설치.

## 4. 용어
- **이동 입구**: 사용자 동작 하나로 특정 대화·글로 데려가는 곳. E1 카드창 카드 클릭(`selectDrawerCard`), E2 알림 섬의 질문·작업 클릭(`activateIsland`), E3 말풍선·알림에서 열기(`openFromBubble`), E4 검색 결과 선택(`revealHistorySearch`), E5 방 알림 줄 클릭(`jumpNotice`).
- **대상**: 입구가 가리키는 글. 글 id가 없으면 그 스레드 카드.
- **목표 위치**: 대상의 가운데가 보이는 영역 가운데에 오는 스크롤 원점. 목록 처음·끝에서는 그 경계로 자른다(지금의 `scrollOrigin` 규칙 그대로).
- **대상 화면 거리**: 대상의 화면 좌표 y와, 목표 위치에 있을 때의 y 사이 거리. 1/60초마다 잰다.
- **되튐**: 한 번의 이동 안에서 대상 화면 거리가 0.5pt 넘게 커지는 것(HEJO-WAIT-JITTER와 같은 0.5pt 기준).
- **정착**: 대상 화면 거리가 1pt 이하가 되고 그 뒤 계속 1pt 이하인 첫 시점. [근거] 1pt는 화소 반올림분(HEJO-AUTOLOAD AC-08과 같음).
- **이동 시간 상한**: 0.30초. [근거] 기존 감속 이동 길이 0.24초(`WorkspaceEase`)에 프레임 여유 0.06초.
- **자동 이동**: 리더 입력 없이 앱이 일으킨 원점 변화. 한 번의 자동 이동은 원점이 0.5pt 넘게 움직이기 시작해 다시 멈출 때(연속 3표본 변화 ≤0.5pt)까지다. 방을 바꿀 때 새 방을 기존 진입 위치에 놓는 첫 배치는 이동으로 세지 않는다.
- **대조 궤적**: 같은 구성·같은 시작 원점에서 이동 요청 없이 같은 리더 입력만 같은 시각에 재생해 잰 원점 궤적. 리더가 만든 이동과 자동 이동을 가르는 기준이다.
- **준비됨**: 대상이 글이면, 대상 스레드의 원문과 대상 글 본문이 앱에 있고 대상 글이 그 스레드의 답글 구간 안에 있어 그릴 수 있는 상태. 대상이 스레드 카드(글 id 없는 입구: E2 작업, E3)이면, 그 스레드 요약이 앱에 있어 카드를 그릴 수 있는 상태.
- **답글 구간**: 스레드가 그리는 이어진 답글 묶음(`history.messagePageIDs`). 처음 받으면 최근 쪽이고, 글 지정 열기는 그 글 주변으로 바꾼다.
- **구간 밖 대상**: 대상 글이 그 스레드의 지금 답글 구간(없으면 최근 쪽)에 들지 않는 경우. 예: 답글 120개 스레드의 10번째 답글.
- **써지는 중 조각**: 기록장 실시간 프레임 중 `type == "edit"`이고 `final == false`인 것.
- **집계 요청**: 서버의 `context`·`overview`·`threads`·`notices`·`questions` 요청.
- **받는 범위(카드창)**: 카드창에서 보이는 카드와 그 위·아래로 보이는 높이 1배 안의 카드. HEJO-AUTOLOAD의 받는 범위와 같은 규칙.
- **내용 위치 변화**: 카드창 카드 또는 대화 목록에서 보이는 글의 창 좌표 틀 변화.

## 5. 요구와 수락 기준

### REQ-JO-01 한 번 이동
이동 입구에서 한 번의 사용자 동작은 대화 목록을 목표 위치로 한 번만 옮긴다.

- AC-01 (정상·준비됨·같은 방) Given 기록 모드, 대상이 준비됐고 지금 보이는 방에 있으며 목표 위치에서 300pt 이상 떨어져 있다. When E1로 누른다. Then 되튐 0회, 누른 뒤 0.30초 안에 정착, 정착 뒤 1.0초 동안(내용 변화가 없을 때) 원점 변화 ≤0.5pt.
- AC-02 (정상·준비 안 됨) Given 대상 글 본문이 앱에 없고 서버가 늦게 정상 응답한다. When E1로 누른다. Then 대상 글이 그려지기 전에는 자동 이동 0회(원점 변화 ≤0.5pt. 스레드 카드로도 먼저 가지 않는다), 대상 글이 그려진 뒤 대상 글로 가는 자동 이동이 정확히 1회이고 되튐 0회로 그려진 때부터 0.30초 안에 정착한다. 다른 방이면 새 방의 첫 배치(기존 진입 위치) 뒤 같은 판정을 한다.
- AC-03 (경계·이동 중 높이 변화) Given AC-01에서 이동 중 또는 정착 뒤 1초 안에 대상보다 위쪽 카드 높이가 바뀐다(자동 불러오기로 채워짐). Then 되튐 0회, 높이 변화가 끝난 뒤 대상 화면 거리 ≤1pt.
- AC-04 (실패·리더 입력 우선) (가) Given 이동 중. When 휠·클릭·방향키로 위치를 옮긴다(실제 이벤트 경로). Then 입력 시각부터 1.0초 동안 원점과 대조 궤적의 차이 ≤0.5pt. (나) Given 준비 안 된 대상을 눌러 본문을 기다리는 중. When 같은 입력을 하고 그 뒤 본문이 도착한다. Then 입력 시각부터 본문 도착 1.0초 뒤까지 원점과 대조 궤적의 차이 ≤0.5pt(이동 요청은 리더 입력으로 취소되어 다시 시작하지 않는다). 대조 궤적에는 본문 도착으로 생기는 기존 위치 유지 보정이 들어 있으므로 같은 본문 도착을 재생한다.
- AC-05 (경계·연속 누름) Given 첫 대상으로 이동 중. When 다른 카드를 누른다. Then 둘째 대상에 대해 되튐 0회로 정착하고, 첫 대상 때문에 늦게 도착한 본문·예약된 이동이 정착 뒤 원점을 0.5pt 넘게 움직이지 않는다.
- AC-06 (실패·대상 글 없음) Given 서버가 대상 글에 `target_missing`을 준다. When E1로 누른다. Then 실패가 확정되기 전에는 자동 이동 0회, 확정된 뒤 스레드 카드로 가는 자동 이동이 정확히 1회(되튐 0회, 0.30초 안 정착)이고, 실패 안내는 REQ-JO-03 규칙으로만 보인다. 스레드 카드도 없으면 자동 이동 0회.
- AC-07 (정상·다른 방) Given 대상이 준비됐고 다른 방에 있다. When E1로 누른다. Then 새 방이 그려진 첫 화면부터 대상 화면 거리 ≤1pt이며(방을 연 뒤의 감속 이동 없음), 그 뒤 방의 나머지 카드가 채워져도 대상 화면 거리 ≤1pt.
- AC-08 (정상·다른 입구) 글 id가 있는 입구 E2(질문)·E4·E5는 AC-01과 같은 판정을 하고, E4·E5는 준비 안 된 경우 AC-02 판정도 한다. 글 id가 없는 입구 E2(작업)·E3은 대상이 스레드 카드이며 AC-01과 같은 판정을 하고, E3은 준비 안 된 경우(카드를 그릴 요약이 아직 없음) 카드가 그려지기 전 자동 이동 0회·그려진 뒤 정확히 1회로 판정한다.
- AC-09 (경계·동작 줄이기) Given 시스템 "동작 줄이기"가 켜져 있다. When E1로 누른다. Then 원점 이동은 한 번의 배치로 끝난다(이동 횟수 1, 되튐 0회).
- AC-10 (보존·다른 호출자) 스레드 펼치기(`chooseThread`), 답글 보내기 뒤 위치, 방 진입 위치의 최종 위치는 기준본과 같다(±1pt).

### REQ-JO-02 누르면 바로(카드 대화 미리 받기, 최근 쪽만)
카드창이 보이는 동안 받는 범위(카드창) 카드의 대상 스레드를 사용자 동작 없이 최근 쪽까지 준비해 둔다. 구간 밖 대상은 미리 받지 않고 누른 뒤 받는다(사용자 결정 D-08).

- AC-01 (정상) Given 기록 모드, 카드창이 열려 있고 대화가 연결된 카드가 3장 이상이며 대상 스레드가 아직 없다. When 누르지 않고 불러오기가 끝날 때까지 기다린다. Then 받는 범위(카드창) 카드의 대상 스레드마다 원문과 답글 구간이 있고, 대상이 구간 안인 카드는 준비됨이다.
- AC-02 (정상·부작용 없음) Given AC-01과 그 전의 선택 스레드·펼친 스레드·안 읽음 숫자·알림 확인 상태·대화 목록 스크롤 위치·카드창 카드 목록, 이미 답글 구간이 있는 스레드들의 구간. When 미리 받기가 끝난다. Then 모두 그대로다. 이미 구간이 있던 스레드의 구간은 바뀌지 않고(구간 밖 대상이 있어도), 보이는 글의 화면 위치는 ±1pt 안이다.
- AC-03 (정상·바로 이동) Given AC-01이 끝났고 대상이 구간 안이다. When 서버의 모든 응답을 2초 늦춘 상태에서 같은 방 카드를 누른다. Then REQ-JO-01.AC-01을 만족한다(0.30초 안 정착).
- AC-04 (정상·다른 방도 바로) Given AC-01이 끝났고 대상이 구간 안이다. When 서버의 모든 응답을 2초 늦춘 상태에서 다른 방 카드를 누른다. Then 누른 뒤 0.30초 안에 REQ-JO-01.AC-07의 첫 화면이 그려진다.
- AC-05 (경계·범위 밖) Given 카드 30장과 받는 범위(카드창)에 10장 안팎만 드는 창. When 불러오기가 끝난다. Then 범위 밖 카드에 대한 미리 받기 요청은 0건이다. 카드창을 스크롤해 범위에 들어오면 그때 받는다. 카드창이 닫혀 있으면 미리 받기 요청은 0건이다.
- AC-06 (경계·중복 없음) Given 이미 준비됐거나 받는 중인 대상. When 카드창 갱신이 여러 번 돌거나 스크롤로 범위를 들락거린다. Then 같은 연결·같은 본문 판에서 그 대상의 미리 받기 요청은 한 번뿐이다.
- AC-07 (경계·메모리) 미리 받은 본문은 기존 상주 본문 한도(`HistoryResidentBudget`) 규칙을 그대로 따른다. 새 한도 값이 없다. 한도로 비워진 대상은 누르면 REQ-JO-01.AC-02로 동작한다.
- AC-08 (실패) Given 한 카드의 미리 받기에만 오류를 주는 서버. When 미리 받기가 돈다. Then 카드창·대화창에 그 실패 안내가 보이지 않고, 다른 카드는 준비되며, 실패한 카드는 누르거나 연결이 새로 맺어지기 전에는 다시 요청하지 않는다. 누르면 REQ-JO-01.AC-02 또는 AC-06으로 동작한다.
- AC-09 (경계·누른 뒤 갱신) Given 준비된 대상으로 이동해 정착했다. When 선택·읽음 변화로 갱신이 돈다. Then 갱신이 끝날 때까지 대상 글이 화면에서 사라지지 않고("불러오는 중"으로 돌아가지 않음) 대상 화면 거리 ≤1pt, 그 대상의 본문 재요청 0건.
- AC-10 (경계·구간 밖 대상) Given 카드 대상이 구간 밖이다(답글 120개 스레드의 10번째 답글, 그 스레드는 최근 쪽이 보이는 중). When 미리 받기가 끝나고 그 뒤 카드를 누른다. Then 누르기 전 그 대상에 대한 글 지정 열기 요청은 0건이고 그 스레드의 구간은 그대로다. 누른 뒤에는 REQ-JO-01.AC-02(그려지기 전 자동 이동 0회, 그려진 뒤 정확히 1회)를 만족한다.

### REQ-JO-03 갱신 표시와 안내가 자리를 밀지 않음
- AC-01 (정상·카드창) Given 카드창에 카드가 보인다. When 갱신이 시작되고 끝난다. Then 카드의 내용 위치 변화 ≤0.5pt. 갱신 중에는 카드창 제목 줄에 갱신 표시가 보이고 끝나면 사라진다.
- AC-02 (정상·대화 목록) Given 대화 목록에 글이 보인다. When 갱신이 시작되고 끝난다. Then 목록에 `history-status` 줄이 행으로 들어가지 않고, 보이는 글의 내용 위치 변화 ≤0.5pt. 갱신 중에는 대화창 제목 줄에 갱신 표시가 보이고 끝나면 사라진다.
- AC-03 (실패 안내) Given 기록 불러오기가 실패했다. Then "대화를 불러오지 못했어요"와 "다시 시도"가 대화창 아래쪽 고정 줄에 보이고, 나타나고 사라질 때 보이는 글의 내용 위치 변화 ≤0.5pt이며, "다시 시도"는 지금과 같게 동작한다.
- AC-04 (카드창 안내) 카드창의 글 안내(앱 갱신 필요, "마감을 읽지 못했어요…", "마감을 닫지 못했어요…")는 카드창 아래쪽 고정 줄에 보이고, 나타나고 사라질 때 카드의 내용 위치 변화 ≤0.5pt. 기존 되돌리기 줄과 함께 보일 수 있다.
- AC-05 (접근성) 갱신 표시는 접근성 이름 "대화 알림을 갱신 중이에요."(카드창), "대화를 갱신하고 있어요"(대화창)로 읽힌다.
- AC-06 (보존) 맨 위 "이전 글 보기" 줄, 빈 목록 줄, 왼쪽 방 목록의 집계 표시는 그대로다.

### REQ-JO-04 써지는 중에는 전체 갱신 안 함
직원 답이 써지는 조각은 화면의 글만 바꾸고 서버 집계 전체 갱신을 일으키지 않는다. 집계는 새 글, 끝 조각, 상태·삭제·방 프레임에서만 갱신한다(사용자 결정 D-10). 써지는 중에 서버 집계가 실제로 바뀌는 경우("생각 중…"이 본문으로 바뀌어 안 읽음·종·알림이 생김, 본문에 승인 요청이 들어가 질문이 생김)도 끝 조각 뒤 갱신까지 미룬다(사용자 결정 D-11, GAP-JO-02).

- AC-01 (정상) Given 기록 모드, 보이는 방에서 직원 답이 새 글 프레임 1개, 써지는 중 조각 30개(30ms 간격), 끝 조각(`final:true`) 1개로 온다. When 끝까지 관측한다. Then 새 글 프레임으로 시작된 갱신이 끝난 뒤부터 끝 조각이 도착하기 전까지 집계 요청 0건, 그 구간에서 카드창·대화창 갱신 표시가 꺼져 있다. 끝 조각 뒤 집계 갱신은 1회 이상 2회 이하다.
- AC-02 (정상·글은 실시간) 같은 입력에서 대화 목록의 답 글자는 조각마다 바뀐다(기준본과 같은 조각 수만큼 화면 글 변화).
- AC-03 (정상·결과 같음) 끝 조각 뒤 갱신이 끝나면 안 읽음 숫자·종·알림·질문·스레드 요약(제목·미리보기·`working`·`assessment`·기다리는 버튼 수)이 같은 입력을 기준본에 넣고 정착시킨 값과 같다. 써지는 중에 "생각 중…" → 본문, 본문 → 승인 요청 문구로 바뀐 경우를 포함한다.
- AC-04 (경계·다른 프레임은 그대로) 써지는 중에 새 글·상태(`state`)·삭제·방 프레임이 오면 집계 갱신이 돈다. 이어 붙은 프레임은 진행 중 갱신 뒤 한 번으로 모인다(기존 동작).
- AC-05 (경계·사이 값) 써지는 중 조각 구간에서 왼쪽 방 목록·카드창의 미리보기·순서와 안 읽음 숫자·종·알림·질문 표시는 직전 갱신 값을 유지한다(움직이지 않음). 끝 조각 뒤 갱신에서 맞춰진다.
- AC-06 (실패) 끝 조각이 오지 않고 연결이 끊겼다가 다시 맺어진다. Then 다시 맺을 때의 기존 갱신이 돌고 AC-03의 값으로 맞춰진다. 끝 조각 없이 연결이 유지되면 다음 갱신 사유(새 글·상태·삭제·방 프레임, 선택 변경, 다시 연결)가 올 때 맞춰진다.

### NFR
- NFR-JO-01 (원본 하나) 이동 입구가 목록을 옮기는 길은 하나다. 입구가 직접 부르는 이동과 본문 도착 뒤 이동이 따로 남지 않는다.
- NFR-JO-02 (회귀 없음) 기존 앱 시험과 기록 하네스(스크롤, 자동 불러오기, 기다림 흔들림, 알림 확인, 세 번 누름)가 기준본과 같은 결과다.
- NFR-JO-03 (개인값 없음) 개인값 검사 통과.

## 6. 미확정
- 갱신 표시는 작은 ↻로 확정(사용자 D-09). 정확한 자리와 아래쪽 안내 줄의 모양은 시안 그림(AT-JO-15)을 사용자가 보고 확정한다. 자리를 밀지 않는다는 기준(REQ-JO-03)은 확정이다.
