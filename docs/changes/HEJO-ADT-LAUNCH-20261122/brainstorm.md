# HEJO-ADT-LAUNCH 브레인스토밍 결정 요약

- 날짜: 2026-11-22. 진행 방식: 연합개발, 계획 검증 켜기(사장 선택).
- 근간: [ARCHITECTURE.md](../../ARCHITECTURE.md). 새 칸 없음.
- 계기: 직원 C가 hejo 대화에서 CCTV 확인 중 "ADT-EYE 프로그램을 켜 주면 다시 볼게"라고 답했다. 사장 지시: "직접 켜서 확인해야지, 내가 앱을 열어주는 게 아니라."

## 1. 목적

직원 C가 CCTV 확인 중 ADT-EYE가 꺼져 있으면 사장에게 켜 달라고 하지 않고 스스로 켜서 확인을 끝낸다.

## 2. 하는 것 · 하지 않는 것

하는 것:

- team-kit CCTV 팩: 켜기·다시 틀기 클릭 직전 원격 창(Windows App 세션 창)이 맨 앞이 아니면 원격 창을 한 번 더 앞으로 올리고 다시 확인한 뒤 클릭한다. 그래도 막히면 가린 앱 이름을 기록하고 그 이름으로 보고한다.
- team-kit CCTV 팩: 실패 보고·도구 설명에서 사장에게 켜기를 부탁하는 문장을 없애고, 무엇을 시도했고 무엇에 막혔는지만 말한다.
- hejo 앱: hejo가 비활성일 때 '에이전트 연결'·'연결' 창과 공용 옵션 창(`OptionWindows`)이 원격 화면 위에 남아 가리지 않게 한다.

하지 않는 것:

- 원격 재연결 승인 흐름, 다시 틀기 하루 한도, 지시서 값 변경. Hermes 본체, ddots, 실제 고객 메시지.

## 8. 열린 질문

- team-kit 부분을 어느 세션에서 할지: 운영 저장소 규칙은 Hermes 작업을 그 저장소의 Paseo 프로젝트에서 하라고 한다.

## 9. 위험도 1차 판단

일반. 두 저장소에 걸치고 운영 서버 화면에 실제 클릭을 보내는 코드다. 클릭 대상 확인을 느슨하게 하면 엉뚱한 창에 입력이 갈 수 있어 클릭 직전 검사는 약화하지 않는다.
