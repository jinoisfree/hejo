# 펫과 채팅 위치

- 채팅 개폐, 서랍·웹 칸 개폐, 채팅 크기 변경은 펫의 화면 좌표와 사용자 지정 크기를 바꾸지 않는다.
- 펫 드래그는 눌렀던 지점과 화면 포인터의 누적 이동량을 유지한다. 펫 자체의 화면 경계만 제한한다.
- 헤더 드래그는 펫과 채팅을 같은 이동량으로 옮긴다. 화면 경계나 펫과의 충돌이 있으면 채팅만 별도로 보정한다.
- 채팅 본문은 `PetLayout.placementSprite`의 영역과 겹치지 않는다. 펼친 채팅이 펫 아래에 있으면 위쪽 헤더 20pt에만 걸침을 허용한다. 펫은 채팅의 위쪽 가장자리 위 또는 채팅 아래에 있으며, 좌우로 따로 배치하지 않는다. 펫 중심이 채팅의 가로 범위 안에 있도록 채팅만 옮긴다. 화면 안의 안전한 위·아래 요청 위치는 유지하고, 충돌 시 위·아래 영역에서 크기를 유지할 수 있는 가장 가까운 위치를 우선한다. 불가능하면 최소 채팅 크기 충족, 표시 면적, 이동 거리 순으로 선택한다.
- 표시 크기 축소는 저장된 선호 크기를 바꾸지 않는다. 열린 서랍·웹 칸의 폭은 실제 표시 폭 안에서 나눈다. 펫이 화면 전체를 덮는 예외에서는 채팅을 겹쳐 그리지 않고 빈 영역으로 처리한다.
- 자동 높이 변경은 아래 배치에서 위 가장자리, 위 배치에서 아래 가장자리를 유지한다. 직접 좌우 리사이즈는 기존 중심 유지, 세로 리사이즈는 반대쪽 가장자리 유지다. 화면·충돌 제약은 채팅에만 우선한다.
- 애니메이션 중간 표시에도 같은 충돌 제한을 적용한다. 전환 모양을 위해 펫 좌표를 보정하지 않는다.

책임: AppKit `PetLayout`의 좌표 계산과 `PetController`의 표시 적용. 저장 형식과 외부 통신 계약은 변경하지 않는다. 회귀: `PetPositionTests` T1~T6, AT92, AT-DI-11/13.
