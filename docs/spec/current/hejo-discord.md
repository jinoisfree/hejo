# HEJO 디스코드 창의 현재 계약

근간은 [ARCHITECTURE](../../ARCHITECTURE.md) 3절(사장 금고·공용 창고)과 4절(디스코드 문)이다. 적용 제품 커밋은 공개 이력 `4f0c7b574e2751d3ba477f8c10a0cbe2d1489910`(공개 기준 `59589595bf769badfc7928ab1203f0b915cd3710` 위, 개발 이력 원본 `3b9da3d3007f62d4cbce8f4669691f4eb73fcc63`, 개발 통합 `91f6013bd71e782d20dfb0cbca51eaf2b3a184e4`). 가짜 디스코드 객체와 실제 Hermes `DiscordAdapter`(가짜 `discord` 모듈) 시험으로 검증한 소스 기준이며, 운영 적용과 실물 확인(REQ-HD-09)은 아직이다. 요구 원문과 수락 기준은 [spec](../../changes/HEJO-DISCORD-20261124/spec.md), 판정은 [verdict](../../changes/HEJO-DISCORD-20261124/verdict.md)다.

## 칸과 저장

| 다루는 것 | 칸 | 위치 | 쓰기 주체 |
|---|---|---|---|
| 짝(서버·사장 계정·짝 표지), 짝짓기 코드 해시 | 사장 금고 | `<HOME>/hejo/discord.json`(0600) | 문 |
| 켜짐 | 공용 창고 | `<HOME>/shared/hejo/discord/settings.json` | 문(앱 요청 때만) |
| 방 ↔ 포럼 채널, 분류 id | 공용 창고 | `<HOME>/shared/hejo/discord/channels.json` | 문 |
| 보낸 디스코드 글 ↔ hejo 글 | 공용 창고 | `<HOME>/shared/hejo/discord/sent.jsonl`(덧붙이기만) | 문 |
| 받은 디스코드 글 ↔ hejo 글 | 기록장 | 사장 글 행의 `client_msg_id` = `discord:{표지}:{채널}:{글 묶음}:{글}` | 문 |
| 봇 토큰 | 사장 금고 | 기본 프로필 `.env`(Hermes가 읽음, hejo는 읽지 않음) | 사장 |

웹후크 토큰은 문 프로세스 메모리에만 있다. 금고 밖에서는 서버 id 대신 짝 표지를 쓴다. 기록장 레코드 종류는 그대로다.

## 동작

- **REQ-HD-01 짝짓기:** 앱이 받은 1회용 코드(600초)를 짝지을 서버의 아무 채널에 쓰면 짝이 된다. 다시 짝지으면 새 표지로 대체하고 이전 채널 대응은 쓰지 않는다. 해제는 짝·코드를 지우고 켜짐을 끈다.
- **REQ-HD-02 설정과 상태:** 프레임 `discord`·`discord_pair`·`discord_unpair`·`discord_save`(앱→문), `discord_status`·`discord_code`(문→앱). 상태 필드 `platform_ready`·`paired`·`enabled`·`channel_problem`·`core_open`. `discord` 기능을 밝힌 연결에만 보낸다.
- **REQ-HD-03 채널 동기화:** 활성이면 분류 `hejo` 아래 쓸 수 있는 방마다 포럼 채널 하나. 방 이름 변경은 채널 이름 변경, 보관·삭제는 `hejo 보관` 분류로 옮김, 보관 해제는 되돌림. 방은 앱에서만 만든다. 실패는 `channel_problem`.
- **REQ-HD-04 수신:** 닫힘 운영(Hermes 디스코드 허용 사용자 없음, 봇 글 거부)이 전제다. 문은 봇에 붙인 독립 듣기 하나로 받고 글마다 닫힘을 확인하며, 열려 있으면 기록하지 않고 `core_open`을 알린다. 짝 서버·사장 계정이 방 채널에 쓴 새 포럼 글은 새 스레드, 글 묶음 안 답은 그 스레드의 사장 글(첨부 포함, 같은 글 id는 한 번). 방 채널이 아닌 곳의 글에는 안내만 보낸다.
- **REQ-HD-05 발신:** 직원 남은 글(정착 2초 뒤, 작성 중이면 기다림)과 디스코드가 아닌 경로의 사장 글을 방 채널의 글 묶음으로 채널 웹후크를 써서 보낸다. 표시 이름은 직원 이름 또는 `사장`, 멘션은 모두 해제. 대응 글 묶음이 없거나 사라졌으면 새 포럼 글(제목 = 첫 비어 있지 않은 줄 앞 100자). 웹후크가 사라지면 그 글은 실패로 끝나고 다음 글부터 웹후크를 다시 만든다. 2000자 초과는 나눠 보내고, 8 MiB 초과 첨부는 `📎` 줄로 남긴다. 실패는 로그(종류만)이며 재시도하지 않는다.
- **REQ-HD-06 작성 중:** 대응 글 묶음이 있는 스레드에서 직원 차례가 도는 동안 8초에 한 번 이하로 작성 중 표시를 요청한다.
- **REQ-HD-07 창 공존:** 디스코드 창은 자기에게서 온 사장 글만 되보내지 않는다(텔레그램 창은 HEJO-TELEGRAM-REMOVE에서 없앰).
- **REQ-HD-08 앱:** 설정 "연결과 동기화" 페이지에 디스코드 구역(상태, 연결 코드·남은 초, 켜기, 연결 해제, 준비 안내). `hello.features`는 `rooms`·`discord`. 앱은 연결(`welcome`)마다 디스코드 상태 조회를 1번 보낸다. AppKit.

## 알려진 한계

보관된 글 묶음이 웹후크 발신으로 다시 열리는지와 실제 파일 한도는 실물 확인 전이다. 디스코드에서 고치거나 지운 글, 서버가 꺼져 있던 동안의 글은 반영하지 않는다.
