# HEJO 대화 화면 갱신의 현재 계약

근간은 [ARCHITECTURE](../../ARCHITECTURE.md)이며 이 문서는 관제 화면(app)의 갱신 계약만 다룬다. 적용 제품 커밋: `221e84082a4230caca6b450cb3b2e0ee9d085ee8`. 2026-11-23 로컬 설치 앱까지 검증됐으며 원격 반영은 별도 확인 대상이다.

- 변경 프레임의 일반 receive 경로는 기존 동기 transaction 안에서 최종 상태 통지를 통합한다. 프레임 순서·저장 cursor·오류 의미·동기 캡처를 유지한다.
- notices·timeline·assessment·날짜·홈 정렬 키는 Model의 한 동기 렌더 범위에서 재사용한다. 상태 변경 시 무효화하고 범위 종료 시 폐기한다. 렌더 도중 변경도 반환 전 최종 상태에 반영한다. 별도 영구 원본이나 전역 지연을 추가하지 않는다.
- 직접방에서는 필요하지 않은 홈 정렬을 실행하지 않는다. 읽음·종·질문·초안·첨부 및 기존 정렬 의미를 보존한다.

근거: [변경 명세](../../changes/60f149af-b64e-4d3a-9e8e-a1c7d4ea1045/spec.md), [수락 시험](../../../tests/acceptance/HEJO-PERF.md), [검증 판정](../../changes/60f149af-b64e-4d3a-9e8e-a1c7d4ea1045/verdict.md). 고정 가짜 부하의 수치 예산과 실제 앱 관측은 이 변경의 검증 근거이며 모든 운영 부하의 지연 보장은 아니다.

## 입력 갱신 계약 — HEJO-TYPING

적용 개발 커밋 `404c8319979a947a43506b133257ed4d6e0ab419`. 입력 이벤트는 초안 저장과 입력 영역 표시만 갱신하며 대화 전체 refresh를 호출하지 않는다. 전송 가능 조건은 선택 대상·연결 상태·공백 제거 후 텍스트 또는 첨부 유무의 공통 계산을 쓴다. 수신 갱신 경로는 유지한다. 자동완성 적용 중 발생하는 입력 알림은 초안에 반영하되 자동완성을 재진입시키지 않는다. 한국어 조합·커서·undo·멘션과 수신 중 입력 계약을 보존한다.

근거: [입력 명세](../../changes/HEJO-TYPING-20261123/spec.md), [수락 시험](../../../tests/acceptance/HEJO-TYPING.md), [최종 자체 점검](../../changes/26405dfc-f5c9-4243-ab07-fa756b3c00bb/verdict.md). 격리 창의 실제 한국어 입력을 사용자가 정상 확인했고 승인된 설치를 완료했다. 원격 반영은 별도 승인/확인이 필요하다.

## 재연결 기록 수신 계약 — HEJO-RECONNECT

적용 제품 커밋 `a420b634428bf33dc4c97c081b5693a3de491bfc`. GateClient는 welcome·`sync_done`의 `head_seq`와 누락을 알린 seq로 서버의 기록 끝(head)을 연결 동안만 기억하고 저장하지 않는다. 연결 시작·끊김·중지·인증 거절 때 버린다. head가 없거나 정수가 아니면 받을 기록이 없는 것으로 본다. 받을 기록이 남은 동안 기록 프레임(seq가 있는 프레임)은 지금처럼 순서대로 적용·저장하되 화면 통지만 보류한다. 보류한 통지는 head 도달 프레임, `sync_done`, seq 없는 프레임이나 다른 즉시 통지, 기존 0.5초 주기 점검 중 먼저 오는 때에 최신 상태로 한 번 전달한다. 일시정지 해제 때 쌓인 프레임은 한 묶음으로 적용하고 통지는 한 번이다. 받을 기록이 없는 평상시 프레임의 반환 전 통지 1회, 프레임 순서·저장 커서·캐시 형식·오류 의미는 그대로다.

근거: [변경 명세](../../changes/HEJO-RECONNECT-20261124/spec.md), [수락 시험](../../../tests/acceptance/HEJO-RECONNECT.md), [검증 판정](../../changes/HEJO-RECONNECT-20261124/verdict.md). 고정 가짜 부하(밀린 300건)에서 처리 시간이 약 20.9초에서 0.6초로, 화면 통지가 303회에서 4회로 줄었다. 실제 앱은 사용자가 재연결 체감으로 확인했으며 운영 부하 전체의 지연 보장은 아니다.

## 파생값 재사용 계약 — HEJO-SMOOTH

적용 제품 커밋 `e745466bc9772819626ee80cbefc442b02322da4`(대응 개발 커밋 `fc756976ff5e52ed7498fcfd8231a37f05fdc59f`). 2026-11-25 로컬 설치 앱에서 사용자가 확인했고 공개 main `27e0e95`에 반영됐다.

- 입력이 같으면 결과가 같은 순수 파생값은 그 값을 소유한 자리에서 입력이 바뀔 때까지 다음 그리기에도 유지한다. 대상은 글 본문 표시, 본문 높이, 스레드 판정, 달력 버튼, 생각 중 판정, 시각 표시, 날짜 파싱, 회원 상태 병합 결과다. 이 항목이 위 첫 절의 "범위 종료 시 폐기"보다 우선한다.
- 재사용은 입력을 값으로 비교한 뒤에만 하거나, 입력을 바꾸는 유일한 쓰기 지점에서 무효화한다. 값마다 개수 상한이 있고 삭제된 글·스레드의 항목은 버린다. 저장하지 않으며 두 번째 원본이 아니다.
- 현재 시각에 의존하는 값(알림 목록 등)은 기존대로 한 동기 렌더 범위에서만 재사용한다. 스레드 판정은 지속 값 위에 렌더 범위 기억을 함께 둔다.
- 접힌 창을 여는 알림 이동은 전환 스냅샷 전에 목적지 스레드를 최종 위치에 놓는다. 전환 중에는 이 동작 때문에 전체 다시 그리기나 스크롤 애니메이션을 시작하지 않는다. 이미 열린 창에서의 이동은 기존 스크롤 애니메이션을 유지한다.
- 계산을 나중으로 미루거나 갱신 횟수를 줄이거나 보이는 부분만 계산하는 방식은 쓰지 않는다. 시험 전용 계수·관측은 `HEJO_PERF_TESTING` 조건부 컴파일 안에만 둔다.

근거: [변경 명세](../../changes/HEJO-SMOOTH-20261124/spec.md), [설계](../../changes/HEJO-SMOOTH-20261124/design.md), [수락 시험](../../../tests/acceptance/HEJO-SMOOTH.md), [검증 판정](../../changes/HEJO-SMOOTH-20261124/verdict.md). 고정 가짜 부하(8방×100스레드×4글, 글 길이 200·800·3,000자)에서 동작 한 번의 주 스레드 점유 중앙값이 약 0.62~0.93초에서 0.03~0.06초로 줄었다(처음 보는 방 전환은 약 0.36초). 모든 운영 부하의 지연 보장은 아니다.

## 제한 조회 모드의 표시 계산

홈 스레드 순서는 서버가 반환한 순서를 사용한다. 방·스레드의 전체 읽지 않은 수, 질문·알림, 스레드 판정은 같은 history context의 요약에서 읽는다. 이 값을 얻기 위해 앱에서 전체 본문을 다시 내려받거나 현재 로딩된 본문으로 재계산하지 않는다. 집계가 도착하기 전과 갱신 중인 상태는 화면에서 구별한다.

날짜 파싱, 회원 상태 병합, 현재 표시할 글의 서식·측정·달력 버튼은 입력이 같은 동안 재사용한다. 본문 퇴거는 메시지 삭제와 구분하며, 과거 구간을 다시 열면 인증된 조회 결과로 복원한다. 셀 측정 캐시는 본문의 수명을 늘리지 않는다. 로컬 전체 계산 횟수에 관한 기존 회귀는 구 앱 참조 구성에서 확인하고, 제한 조회의 회귀는 인증된 작은 fixture에서 본문 한 건과 전체 집계가 공존하는 상태를 확인한다.

## 첫 방문·창 전환 계약 — HEJO-SMOOTH2

적용 공개 제품 커밋: 일정 버튼 `abc4ba0`, 화면 주기 전환 `15861e2`(대응 개발 커밋 `01d08769acdfb800bd0a6b54beacb6df18bf014f`, `0c60efaa8d305fd789b4c896d0907e12721b2776`). 2026-11-25 로컬 설치 앱에서 사용자가 확인했다.

- 카드의 일정 버튼은 `CalendarMatch.related` 결과만으로 만든다. 일정 목록이 비면 계산 없이 빈 결과다. 링크 찾기는 알림 말풍선 경로에만 있다. 위 'HEJO-SMOOTH' 절의 입력·상한·무효화는 그대로다.
- 대화 창을 여닫는 전환의 단계는 화면 주기 신호로 진행한다(macOS 14 이상 화면의 display link, macOS 13은 CoreVideo, 화면이 없거나 실패하면 1/60초 Timer로 대신). 진행률은 경과 시간으로 계산하고 모양·총 길이·동작 줄이기 경로는 바꾸지 않는다. 새 전환·드래그·화면 변경·해제 때 앞선 구동을 멈추고, 대체된 구동의 늦은 신호는 무시한다. 전환 중 판정은 이 구동 객체의 존재로 한다.

근거: [변경 명세](../../changes/HEJO-SMOOTH2-20261125/spec.md), [검증 판정](../../changes/HEJO-SMOOTH2-20261125/verdict.md). 고정 가짜 부하에서 처음 보는 방 전환이 약 0.34초에서 0.19초로, 실제 화면의 전환 최장 단계 간격 중앙값이 약 77ms에서 43ms로 줄었다. macOS 13 경로와 다중 화면 이동은 실물 미검증이다.
