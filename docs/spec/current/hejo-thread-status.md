# HEJO 스레드 상태 막대의 현재 계약

근간은 [ARCHITECTURE](../../ARCHITECTURE.md)의 관제 화면이다. 적용 제품 커밋은 공개 이력 `872ab0e1c0da7d2377d868f40e2ce2562387998f`(개발 이력 원본 `f1cb67d3dfbd74f7479566db5b6cb5c6da53b065`, 제품 patch-id 동일). 가짜 자료의 실제 앱 모델·AppKit 카드 조립에서 검증한 소스 기준이며 운영 설치·원격 반영을 뜻하지 않는다.

상태는 문 `gate/history_queries.py`의 `assess` 한 곳에서 파생한다. 문이 스레드 요약의 `assessment`·`notice`·`waitingButtonIDs`로 보내고, 앱의 카드 상태 막대·종·알림 목록·답 버튼이 같은 결과를 쓴다. 앱 `ThreadAssessment.assess`는 옛 기준본 빌드(`HEJO_LEGACY_REFERENCE` 등)의 비교 자료다. 새 저장 필드는 없다(HEJO-RESULT-DONE에서 원본 위치 정정).

- **REQ-TD-01 / AC-01~05:** 직원 요청(버튼·reply_state=asked·승인 요청 문장)에 사장이 답한 뒤(승인 단어 여부 무관, 해당 요청 대상 또는 대상 없음) 작성이 끝난 직원 글이 있으면 완결이다: 초록 `#2EB67D`, 종 없음, 알림·질문 목록 제외. 작성 중(streaming)·생각 중 글은 근거가 아니다. 완결 뒤 새 요청은 그 요청 기준으로 다시 판정하고, 대상 지정 답이 남긴 요청은 대기(빨강)다. closed 초록, answered 처리 중 노랑, 승인 단어 직후 초록, 버튼 노출 규칙은 유지한다.
- **REQ-TD-02 / AC-06~07:** 요청이 있던 스레드는 보고 제목 표시(🔴 등) 색으로 되돌아가지 않는다. 판정 색이 없으면 작업 중 노랑, 아니면 색 없음이다. 요청 없는 보고만 제목 첫 표시로 색을 정하고(🔴❌🚨⛔ 빨강 `#E01E5A`, 🟡🟠⚠ 노랑 `#ECB22E`, 🟢✅☑✔ 초록 `#2EB67D`, 🔵ℹ📌 파랑 `#1D9BD1`), 작업 중이면 노랑이 우선한다.

이 계약은 HEJO-FOUNDATION spec REQ-HF-27.AC-03 상태 막대 줄의 완결·제목 색 규칙을 대체한다(사장이 고른 ddots와의 차이, 2026-11-24). 근거와 검증 범위는 [판정서](../../changes/HEJO-THREAD-DONE-20261124/verdict.md)를 참조한다.

## 가운데 창 알림 확인과 카드 제목 (HEJO-ALERT-SEEN)

적용 제품 커밋은 공개 이력 `b1fc6c49c33eee7ff1b5778adf13b67da992c08a`. 가짜 기록장·대역 문과 실제 앱 하네스(기록 나눠 받기 모드)로 검증한 소스 기준이며 서버 문 설치·앱 배포를 뜻하지 않는다. 근거와 검증 범위는 [판정서](../../changes/HEJO-ALERT-SEEN-20261125/verdict.md) 3차.

- **REQ-AS-01:** 사장이 직접 고른 스레드(가운데 창 카드 클릭·Enter·화살표, 채팅 스레드 클릭, "답글" 버튼, 말풍선·섬, 검색 결과, 스레드 링크, "의견" 버튼)가 알림(답이 필요 없는 직원 소식)으로 울리면 확인 처리되어 가운데 창에서 빠진다. 앱이 방에 들어갈 때 자동으로 잡은 답글 대상은 확인하지 않는다. 답 요청(질문) 카드는 선택으로 빠지지 않고 답해야 빠진다. 울리는 알림을 직접 고르면 읽음 요청은 `notice` 한 건이며 이것이 `thread:`·`bell:`을 함께 쓴다. 울리지 않는 스레드는 지금처럼 `thread` 읽음 한 건이다. 실패하면 아무 키도 바뀌지 않고 카드가 남으며, 다시 고르면 다시 요청한다. 기록 조정자는 선택·입력이 바뀌어도 지금 의도 세대의 읽음 요청은 남기고 옛 세대 요청만 버린다(새 세션이면 전부 버림). 창을 숨길 때만 의도 세대를 올린다.
- **REQ-AS-02:** 알림·답 요청 카드 제목(문 notice `preview`)은 글의 첫 비어 있지 않은 줄이다. 그 줄이 멘션만으로 이뤄져 있으면 다음 비어 있지 않은 줄을 " · "로 이어 붙이고, 길이는 300 글자 묶음에서 자른다. 스레드 요약의 `title`·`preview`·`rootPreview`와 섬 질문 미리보기(24)는 바뀌지 않는다.

이 절은 [HEJO-TODO-DRAWER](../../changes/HEJO-TODO-DRAWER-20261120/spec.md) AT-TD-39·[HEJO-UI-CLEAN](../../changes/HEJO-UI-CLEAN-20261123/spec.md) REQ-UC-03 AC-07의 "알림 카드는 열면 사라짐"을 출시 경로에서 성립하게 하고 그 범위를 사장 직접 선택으로 정한다.

## 가운데 창 카드 ✓ 띠 (HEJO-CARD-DONE)

적용 제품 커밋은 공개 이력 `bd38bc47f3c7b58b3a14c4df3d0b1fd23e2e0b07`(답 요청·마감)과 `2172446addadc9a34a592ac8d30c6203f6acb0a3`(알림)이다. 가짜 문과 실제 앱 하네스(기록 모드)로 검증한 소스 기준이며, 앱 배포를 뜻하지 않는다. 근거는 [판정서](../../changes/HEJO-CARD-DONE-20261126/verdict.md) 3회.

- **REQ-CD-01·05:** 카드에 마우스를 올리면 종결할 수 있는 카드 오른쪽 끝에 카드 높이, 폭 44pt의 초록 띠와 흰 ✓가 나온다. 띠가 있는 동안 시간 글자는 숨기고 상태 줄은 띠 앞에서 말줄임한다. 종결할 수 있는 카드는 세 가지다: 답 요청(대화 키·글 id가 있고 보낼 수 있음), 마감(참조 있음), 알림(대화 키 있음). VoiceOver 동작 이름은 각각 `확인 보내기`·`완료로 닫기`·`읽음으로 표시`다.
- **REQ-CD-02:** 띠를 누르면 대화로 이동하지 않는다. 답 요청은 카드를 바로 숨기고 `‘제목’ 확인 보냄 · 되돌리기` 줄을 띄운 뒤, 5초가 지나면 그 스레드에 사장 일반 글 `확인`을 `send` 1건으로 보낸다. 직원 버튼은 누르지 않는다(`click` 0건). 마감은 우클릭 "완료로 닫기"와 같다. 되돌리기 줄은 마감 닫기와 같이 쓰는 하나다. 다른 것을 누르면 기다리던 것을 바로 실행하고, 앱이 끝나면 기다리던 것은 보내지 않는다. 알림은 되돌리기 없이 즉시 REQ-AS-01과 같은 `notice` 읽음 요청을 보낸다. 같은 키의 요청이 진행 중이면 합친다.
- **REQ-CD-03:** "확인" 글의 결과는 그 글의 `client_msg_id`로 정한다.
  - ① 즉시 실패, ② 문 `error(ref)` 거절(기록 모드가 아닌 경로에서는 재연결 `sync_done` 미확인 포함): 카드가 다시 보이고 경고 `확인을 보내지 못했어요. 다시 해 주세요.`가 뜬다.
  - ③ 기록 모드에서 쓰기를 시작한 뒤 결과를 모름: 숨긴다. 75초가 지나면 띠 없이 보인다.
  - ④ 접수: 답 요청 목록에서 빠질 때까지 숨기며, 최대 75초다.
  - 어느 경우에도 자동 재전송은 없다.
- **REQ-CD-04:** "확인" 뒤 직원이 답하면 REQ-TD-01에 따라 완결(초록)이 된다. 판정 코드는 바뀌지 않았다.

REQ-AS-01의 "답 요청 카드는 답해야 빠진다"는 그대로다. 답 요청 ✓는 실제 답(`확인`)을 보내는 방법이다.

## 결과 알림과 답 버튼 (HEJO-RESULT-DONE)

적용 제품 커밋은 공개 이력 `2595200`(문·안내판·앱)과 `740f3af7f27fb213a98c683066268ccc35b9834f`(앱 0.2.10)이다. 운영 문 줄 `c2b292d3adb051fe08156e63b6b1057bd1f5cc7d`가 서버에 설치됐다(2026-11-27). 앱 0.2.10 배포와 사장 실물 관측은 남아 있다. 근거는 [판정서](../../changes/HEJO-RESULT-DONE-20261127/verdict.md).

- **REQ-RD-01:** 결과 알림은 직원 글이면서 버튼 라벨이 가공 없이 이 순서 그대로 [`확인`, `되돌리기`]인 글이다. 사장 답이 없는 결과 알림은 답을 기다리는 요청이 아니다. 스레드의 마지막 요청성 글이 답 없는 결과 알림이고 앞에 답 없는 진짜 질문이 없으면 완결(초록)이다. 이때 답 요청·알림 카드와 종은 없다. 앞에 답 없는 질문이 있으면 그 질문이 대기(빨강)로 남는다. 역순·접두·공백 라벨과 다른 버튼 조합은 REQ-TD-01 그대로다. 결과 알림에 사장이 답한 뒤에도 REQ-TD-01 그대로다.
- **REQ-RD-02:** 섬 질문 목록은 `asked`인 직원 글 가운데 결과 알림을 넣지 않는다.
- **REQ-RD-03:** 문 스레드 요약은 답 버튼을 보여 줄 글 id 목록 `waitingButtonIDs`(seq 순, 안내판 선택 필드)를 보내고 `waitingButtonCount`는 그 길이다. 목록은 기존 규칙(답 없는 버튼 글이 둘 이상이면 모두, 아니면 대기 요청) ∪ 답 없는 결과 알림이다. 앱은 이력 모드에서 이 목록의 글에 답 버튼을 그리며, 누름 가능 여부는 `ReplyButtonPolicy` 그대로다. 필드가 없는 옛 문에서는 버튼을 그리지 않는다.
