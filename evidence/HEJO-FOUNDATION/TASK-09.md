# TASK-09 운영 설치·실물 확인 기록 (2026-11-15)

사장 지시("재시작해", "바로 진행하고 마지막 단계까지")로 운영 공항에서 진행했다. 직원 id·경로·메시지 원문 같은 개인값은 추적하지 않는 `.build/task09-*` 로그에만 있다.

## 완료한 것

1. **재시작 ①**
   - team-kit 답장 버튼과 캐시 auto를 로드했다.
   - Slack 6과 iMessage가 재연결됐고, 오류 로그 새 줄은 0이다.
2. **설치기 결함 수정과 설치**
   - **결함:** ruamel로 파일 전체를 왕복하면 운영 설정이 수백 줄 다시 써졌다.
     - 따옴표가 빠져서 YAML 1.1로 읽는 Hermes에서 값의 뜻이 바뀔 수 있었다(예: `"off"` → false).
   - **수정:** 설치기는 이제 hejo 줄만 고친다. Hermes의 reader로 다시 읽어 hejo 키 밖 차이가 0일 때만 쓴다.
   - **설치 결과:** 운영 설정 6개에 hejo 줄만 더해졌다(빈 `gateway: {}` 한 줄만 블록으로 바뀜). `--check`는 0이다.
3. **재시작 ②:** "Gateway running with 13 platform(s)"이다.
   - hejo 6개(기본 1 리스너 + 보조 5 전달자), Slack 6, iMessage 1
   - 리스너는 `127.0.0.1:47820` 하나다.
4. **실물 대화 (AT-31 일부, 루프백)**
   - 시험 기기를 페어링했다. welcome의 직원 수는 6이다.
   - 기본 직원에게 5회 보냈다. 작성 중 표시는 0.01초 안에 왔고, 답 완료까지는 1.5~2.7초였다(짧은 답 기준).
   - 같은 출입증으로 다시 접속해 `since`에서 다시 받았다. 11프레임이 순서대로 왔다.
   - 시험 기기는 끝에 취소했다(활성 기기 0).
5. **첨부:** 업로드 200 → 직원이 파일을 읽고 그 안의 단어로 답했다.
   - 다운로드 200, 바이트 일치
   - 출입증 없이 받으면 401
6. **보조 프로필 전달자:** 보조 직원 1명에게 보냈고 실제 답이 왔다. 다시 받기도 순서대로 왔다.
7. **되돌림:** 설치 전 운영 설정 사본에 설치하면 지금 운영 파일과 바이트가 같다. 그 사본을 제거하면 6개 모두 원본과 바이트가 같다(`.build/task09-uninstall-dryrun.log`).
   - 운영 상태에서 제거→재시작은 하지 않았다. Slack이 두 번 더 끊기는 것을 피했다.
