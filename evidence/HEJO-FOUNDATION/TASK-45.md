# TASK-45 — 옆 창과 시험 다운로드 격리

필요/도달 증거 수준: 2/2. 운영 앱 전체 비교가 아니라 원본 WebPane 함수·SwiftUI 제어와 제품 AppKit 웹 칸의 조립 비교다. 원본 WebPane·WebAddress·WebPicture·WebTabBlank는 수정하지 않고 주변 앱 타입만 대역으로 제공해 분리 실행했다. 제품은 실제 가짜 문에 연결한 최종 앱 시험 실행 파일의 WebKit·펫 패널이다.

- 같은 로컬 합성 페이지, 720×1000pt 웹 칸, 탭 하나, 기본 글씨 크기와 라이트/다크 상태다. 두 그림 모두 주소 표시는 `http://localhost/page`로 고정한다. 실제 탐색은 각각의 루프백 서버이며 검색 사이트에는 접속하지 않는다.
- WebKit의 별도 프로세스 그림은 `takeSnapshot`으로 얻어 실제 페이지 프레임에 합성했다. 제어 줄의 투명한 바탕은 같은 테마의 windowBackgroundColor 위에 내보냈다. 원본 SwiftUI 바깥 환경의 colorScheme도 해당 테마로 지정했다. 제어의 글꼴·기준선·그림 크기는 AppKit/SwiftUI 렌더링 차이가 있을 수 있으며 픽셀 동일 비교를 주장하지 않는다.
- 원본 캡처의 주변 대역은 글씨 상수(원본 ChatMetrics.auxiliaryFont=11), 배치 타입·움직임 검사 값·성능 기록 접점이다. WebPane의 탭/주소/도구 줄·페이지 구현은 그대로다.

움직임/동작은 앱 시험이 실제 패널을 열고 중간 폭·WebKit 생성 지연·720pt 기본 폭·끌기/초기화·기존 대화 크기 보존·흐린 그림 닫기·30초 내 재사용·동작 줄이기를 단언한다. 별도 원격 페이지나 운영 앱을 실행하지 않았다.

원본의 첫 탐색 실패 경계는 [분리 실행 결과](task45-original-failure.json)에 남겼다. 이 경우 `tab.url`이 nil이므로 원래 밖에서 열기 제어가 목적지 없이 비활성이며 칸은 열린 채로 남는다. 오류 안내와 제어 자체는 유지한다. 실패한 요청 주소를 별도로 보관해 밖에서 열게 하는 변경은 하지 않았다(26판 코드 우선). 이 해석은 계획 담당 검토 대상이다.

실제 서버·두 Mac·임의 웹 사이트 로그인·시스템 브라우저 실행·물리 한글 입력기·VoiceOver 실사용은 미검증이다. 시험에서 밖에서 열기는 URL만 기록하며 앱을 실행하지 않는다. 운영 다운로드 폴더는 이름 목록만 비교하고 내용은 읽지 않는다.

직접 표시 대조: 두 테마에서 탭·도구 줄 순서·문구·페이지·가로/세로 크기와 바탕 전환을 확인했다. 제품의 주소칸 시작은 원본보다 약 20pt 오른쪽이며 글자 기준선은 약 5pt 위다(AppKit 버튼/필드 배치). 페이지의 왼쪽 선은 제품에서 1pt를 차지하고 원본은 겹쳐 그린다. 이 차이를 숨기거나 픽셀 일치로 판정하지 않는다. 최종 검사에서 PNG 4개 모두 720×1000·불투명이며 페이지가 제어 줄 아래에 있음을 검사했다.
