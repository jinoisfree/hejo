# TASK-25 스레드 카드·작업 제어 화면 증거

가짜 직원·가짜 글·고정 시각을 넣은 독립 시험 창이다. 운영 앱·명부·설정·게이트웨이는 실행하지 않았다. 필요한/도달한 인계 증거 수준은 2다.

| 파일 | 실제 확인 범위 |
|---|---|
| [ddots 카드](task25-ddots-card.png) | 원본 NativeThreadCard와 SlackLayout을 가짜 상태로 실행한 참조 창 |
| [hejo 카드](task25-hejo-card.png) | 같은 상태를 기존 AppKit 카드 렌더러에 넣은 창: 질문 빨강 막대·종·세 얼굴·접힌 답·표·아래 다섯 버튼 |
| [hejo 날짜·표](task25-hejo-dates-table.png) | 실제 ConversationView 조립: 날짜 행·셀별 좌우 정렬·첨부·작업 중 줄·제어 버튼 |
| [hejo 제어 뒤](task25-controls.png) | 가짜 루프백 WS에서 중지·되돌리기·분기·삭제를 거친 뒤 새 스레드가 남은 화면 |

원본/이식 카드의 배치 영역은 각각 640×273pt, 캡처는 각각 664×273px이다. RGBA로 비교한 181,272개 픽셀 중 186개가 다르다. 제목·본문·세 얼굴·종·표·접힌 답·버튼 위치를 눈으로 함께 확인했다. 두 카드 캡처는 같은 밝은 외관을 강제했고 MessageFormat/ChatStyle 등 이미 이식된 유지 의존과 가짜 사진 공급자를 함께 사용했다. 원본 앱 전체를 독립 실행한 비교나 픽셀 완전 일치의 증거로 확대하지 않는다.

날짜·표 캡처는 연결하지 않은 단위 시험 상태라 연결 오류와 비활성 버튼이 보인다. 제어 캡처는 실제 루프백 가짜 문을 사용하며 운영 문·실제 Hermes 답·도구 부작용은 없다. 카드 아래 버튼 동작·4초/6초 시간·종 병합·캐시 소거·체크리스트는 해당 자동 시험과 함께 판단한다. OS의 콜드 URL 실행, 두 Mac, 운영 문 재시작, 실제 도구 중지와 사용자 눈 확인은 비설계자 검토·TASK-23에 남는다.

재현 도우미·로그는 미추적 `.build/task25/reference_capture.py`, `reference-capture.json`, `pixel-comparison.json`, `capture-ui.log`, `capture-network.log`에 있다. 원본 파일은 읽기만 했고 SwiftUI 참조 호스트는 제품에 포함하지 않았다.
