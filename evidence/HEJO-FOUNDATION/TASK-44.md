# TASK-44 다운로드 파일 비교

필요/도달 증거 수준: 2/2. 새 제품 화면이 없는 파일 입출력 변경이라 화면 캡처 대신, 같은 입력으로 실행한 원본/제품의 이름·파일 본문 결과를 비교했다. 실제 다운로드 폴더나 Finder는 사용하지 않았다.

- 원본: ddots `SlackFiles.swift`의 `SlackFileStore` 전체를 읽기 전용 원본에서 분리 컴파일했다. 같은 날짜·임시 다운로드 폴더·가짜 파일 이름/ID/본문을 썼다.
- 제품: 실제 `GateHTTP.swift`의 `DownloadFileStore`를 분리 컴파일했다. 원본과 받은 파일 두 개·보낸 사본 재사용/번호·폴더 안 파일 보존·이름 정리·UTF-8 길이 제한 결과가 같다. 원본의 200MB 한도는 이식하지 않고 hejo 50MiB를 유지했다.
- 날짜 비교 실행은 UTC로 고정했다. 실제 앱은 원본처럼 Mac 현지 시간으로 `yyyy-MM-dd HHmm`을 만든다. 파일 ID에서는 원본처럼 ASCII 영숫자만 이름에 남긴다. 같은 이름 다른 ID의 받은 파일은 별개로 저장되고 보낸 다른 본문은 ` 2` 번호를 받는다.
- 실제 GateClient·Controller·GateHTTP를 쓰는 별도 루프백 시험에서 같은 파일 동시 누름·연속 재열기가 HTTP 한 번으로 끝남, 다른 ID 분리, 다른 직원 범위 거절, 쓰기 불가 폴더에서 원문 안내와 캐시 열기, 송신 확인 뒤 사본 보관, 거절된 송신 사본 없음도 확인한다. 전부 임시 홈/다운로드 폴더이며 실제 서버·Slack 호출은 없다.
- 다운로드 저장 실패 뒤 캐시로 여는 것은 이번 직접 지시다. 원본 안내 `파일을 저장하지 못했어요. …`를 쓰며 사본 실패가 성공한 송신을 뒤집지 않는 원문 동작은 유지했다.

[원본·제품 실행 결과](task44-files.json)에는 같은 상태의 파일 이름과 합성 본문 바이트(base64), 재사용 결과를 담았다. 절대 경로·계정·출입증은 없다. 이 자료는 파일 저장 함수와 테스트 입력에 한정하며 운영 앱 전체 비교를 주장하지 않는다.

명령·원본 지문은 `.build/task44/reference.py`, `reference-inputs.json`, `reference.json`, mutation.json에 있다. 실제 HTTP/WS·전체 검사·반복·개인값 결과는 `impl-report.md`의 TASK-44와 `.build/task44/final-verification.json`을 따른다. 실제 서버·두 Mac·사용자 다운로드 폴더 실물은 운영 수락에 남는다.
