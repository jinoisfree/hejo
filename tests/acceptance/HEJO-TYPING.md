# HEJO-TYPING 수락 시험 v2

원본: [spec](../../docs/changes/HEJO-TYPING-20261123/spec.md). 명세 작성/자동 코드 미작성/실행 미실행/독립 검토 미실행. 자동 시험은 구현 담당이 app/Tests에 작성하되 기대값을 바꾸지 않는다. 모든 데이터는 임시 HERMES_HOME/LocalStore와 가짜 명부. 실메시지 전송 금지.

- AT-HT-01 (AC-01): 실제 ConversationView를 창에 붙이고 홈/직접방/단체방 각각에서 문자 추가·삭제·붙여넣기를 수행한다. 별도 수신/타이머 작업을 구분해 입력 이벤트가 대화 카드/사이드바 전체 갱신을 유발하지 않음을 계측한다. 같은 높이에서는 전체 레이아웃 무효화도 입력에서 추가하지 않는다. 멘션 입력/삭제에 받는 사람 표시가 즉시 바뀌고 초안은 입력과 같다. 수정 전 홈에서는 전체 갱신 호출을 실패로 기록한다. 직접방/단체방은 기준에서도 통과할 수 있으며 실패를 강요하지 않는다. 세 종류의 지연을 따로 기록하고 홈 외 지연 원인은 별도로 보고한다.
- AT-HT-02 (AC-02): 한글 marked text 생성→조합 수정→확정, 중간 커서 삽입, 범위 선택 교체, undo/redo, 서식과 일반 텍스트 붙여넣기, 여러 줄 높이 변화, 멘션 자동완성, 명시 받는 사람 선택/해제, 첨부만 있는 초안, 공백 초안, 연결 불가 상태를 검사한다. 버튼 기대값은 선택 대상 있음 AND canSend AND (공백/줄바꿈 제거 후 본문 있음 OR 첨부 있음)이다. 빈 본문·공백만·줄바꿈만/첨부 유무/선택 유무/연결 유무를 교차하여 입력 직후와 전체 갱신 후 결과가 같음을 검사한다. 이는 기존 실제 공백 전송 거부를 보존하며 버튼 불일치만 수정한다. 편집 중 selection·undo가 외부 복원으로 초기화되지 않는다. 방/새 글/답글 왕복 시 초안을 보존한다. 실제 한국어 입력기로 연속 입력도 관측한다.
- AT-HT-03 (AC-03): 입력 중 가짜 수신의 message/edit/delete/typing 및 연결 변화, 방/스레드 전환을 끼워 넣는다. 메시지/수신자/버튼/초안/선택을 검증한다. 새 갱신 경로가 실제 변경을 막지 않는다. ComposerTests, ComposerTargetTests 및 관련 기존 앱 회귀를 함께 실행한다.
- AT-HT-04 (AC-04): 가짜 방 8개×스레드 100개×글 4개, 동일 창 크기·빌드 옵션·시각·글 순서에서 홈/직접방/단체방 입력을 측정한다. warm-up 제외 5회, 각 회 동일 문자 시퀀스. 이벤트 제출→처리 시작의 큐 대기와 처리 완료까지의 지연을 구분해 기록하고 각각 중앙값 ≤0.25초·최대 ≤0.5초를 만족한다. 전후 모든 표본·소스 커밋·환경을 기록한다. 타이머/스트리밍 유무를 분리하고 고정 입력을 줄이거나 결과를 누락하지 않는다. 실제 AppKit 창의 한글 연속 입력과 메시지 목록 위치 안정성도 확인한다. OS 입력 실험이 불가능하면 미실행으로 반환하고 자동 호출 시험으로 대체 완료하지 않는다.

빌드 bash app/scripts/build.sh, 회귀 bash scripts/test.sh, 개인값 python3 scripts/scan_private.py를 실행하고 로그를 남긴다. 운영 비밀을 읽는 설정은 사용하지 않고 검사 입력이 필요하면 가짜 값으로 격리한다. 기존 시험 실패는 기준 동일 조건과 비교하여 구별하고 임의 완화하지 않는다.
