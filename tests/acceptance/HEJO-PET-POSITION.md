# HEJO-PET-POSITION 수락 시험
원본 요구: [spec](../../docs/changes/ebc502d3-dfb3-41ee-8b0d-f81ed5f62e41/spec.md).
상태: 명세 작성, 자동 코드 미작성, 실행·독립 검토 미실행. 임시 HERMES_HOME·임시 LocalStore·가짜 명부만 사용한다.

| 시험 | AC | 입력·관측·합격 기준 |
|---|---|---|
| T1 | REQ-PP-01.AC-01 | 중앙·네 모서리에서 열기/닫기/재열기/중간 반전. 일반·동작 줄이기, 서랍/웹 각각 및 동시 열림. 전환 프레임마다 globalSprite/실제 view 화면 환산 사각형이 시작과 같다. 저장 좌표도 불변 |
| T2 | REQ-PP-02.AC-01 | 실제 PetView mouseDown→여러 mouseDragged→mouseUp 경로. 안쪽에서 포인터 (+60,+40), (-30,-50), 방향 반전. 매 입력의 표시 펫 좌표가 시작+변위이며 크기는 불변. 열린/닫힌/전환 중 각각 검사, 놓아도 토글·튐 없음 |
| T3 | REQ-PP-02.AC-02 | 펫 자체 경계를 넘어 위·아래·좌·우로 이동 및 돌아오기, 크기 다른 화면과 음수 원점 화면 이동·화면 제거. 채팅 최소 높이나 폭과 무관하게 펫 자체 경계만 제한하고 화면 제거 때 안전 복귀 |
| T4 | REQ-PP-03.AC-01 | 큰 채팅·서랍/웹·좁은 화면에서 드래그. 채팅 가시 영역 포함·선호 크기 불변·음수 크기 없음. 헤더 이동·가장자리 크기 변경·편집기·닫기 조작 유지. 펫 자동 재부착 없음 |
| T5 | REQ-PP-03.AC-02 | 드래그 종료→임시 저장소로 새 컨트롤러 복원. 최종 좌표/사용자 크기 일치, 개폐·서랍 보정으로 저장 좌표 변경 없음. 클릭 문턱/포커스/Escape/접기/투명 영역 클릭 통과 회귀 |

자동 비교는 CGFloat 오차용 0.01pt 이내(시각 오차 허용치가 아닌 연산 비교 기준). 내부 헬퍼 결과만 보지 않고 표시 사각형과 입력 경로까지 검사한다. 기존 carried-height 및 drawer 동반 이동 기대값은 승인된 새 요구로 대체하며 관련 없는 검사는 유지한다.
실환경: 격리된 실행 앱에서 실제 포인터로 개폐·상하좌우/대각/역방향 드래그·놓기·화면 가장자리·채팅 입력을 확인한다. 가능하면 다중 화면도 확인하고 없으면 자동 증거와 미실행 범위를 구분한다. 개인 정보가 없는 관측 기록/녹화와 대상 커밋을 남긴다. 앱 실행·손 입력 확인 없이 스크린샷만으로 드래그 합격 처리하지 않는다.

## 2판 검토 보완
- T1: 웹 칸 자체 개폐 및 웹을 연 채 펫/헤더 이동 후 웹 닫기를 추가한다. 마지막 펫 위치·크기 불변. 낮은 화면에서 접힌 말풍선 표시·갱신에도 펫 불변.
- T4: 헤더를 끌 때 펫과 채팅 각각 시작 사각형+포인터 변위, 각각의 화면 제한을 기대값으로 삼는다. 놓은 직후와 다음 배치 tick·서랍/웹 개폐 후에도 위치가 되돌아가지 않아야 한다. AT92 높이 유지·화면 넘기기 및 AT-DI-13 오른쪽 경계/서랍 유지 검사를 유지한다.
- T2·T4 실환경: 제품 수정 전에 기준 커밋 재현 결과를 기록하고 수정판과 같은 조건으로 비교한다. 좌표 오류와 이벤트/그리기 지연을 구분한다. 수동 격리 모드 준비·실행은 [handoff](../../docs/changes/ebc502d3-dfb3-41ee-8b0d-f81ed5f62e41/handoff.md)의 절차를 따른다. 모드는 아직 미구현이며 실환경 증거는 미실행이다.

## 3판 검토 보완
- T4: 헤더 이동 종료 뒤 fitOpenThread(늘림/해제), toggleChatWidth(왕복), resetChatSize, 사이드바 폭 변경을 각각 수행한다. 화면 내부에서는 현재 채팅 minX 및 펫 쪽 가장자리(아래 배치 maxY, 위 배치 minY) 유지와 의도한 크기 변경만 허용하고, 넘칠 때는 화면 제한에 필요한 이동만 허용한다. 펫 재부착/이전 위치 복귀 금지. screensChanged는 화면 불변·축소·제거를 나누어 현재 위치 보존 또는 개별 안전 보정을 확인한다.
- 수동 시험 실행 전후 기존 settings_guard/downloads_guard와 보완 메타데이터 검사가 모두 통과해야 한다. 실패·중단 시에도 검사하고 로그에는 내용·개인 경로·항목 이름을 남기지 않는다. guard의 제한을 명시한다. 웹 fixture의 비영속 데이터 저장소를 생성 시 확인한다. 상세는 handoff의 실행 전후 오염 검사 절과 4판 보완을 따른다.

## 4판 검토 보완
- T4 자동 크기 변경: 아래/위 배치 각각에서 높이 증가·감소 전후의 maxY/minY 및 minX를 검사한다(오차 0.01pt). 헤더 이동 후의 현재 가장자리가 기준이다. 화면 내부 사례는 그 좌표가 그대로이며 펫 사각형도 그대로다. 경계 사례는 design의 후보 사각형에 화면 보정만 적용한 결과와 비교한다. 직접 좌우 드래그의 기존 중심 유지·화면 끝/웹 칸 제한(AT-DI-11)과 세로 드래그의 반대쪽 고정 회귀를 별도로 유지한다.
- 수동 모드의 모든 보호 검사 명령은 snapshot/verify/trap 모두 `${HEJO_PYTHON:-python3}` 선택을 따른다.

## 5판 설계 오류 정정
직접 좌우 리사이즈에서 모든 경우 반대쪽을 고정한다는 기대를 철회한다. 기준판 AT-DI-11의 minX 386/width 428 → 오른쪽 +40 → minX 346/width 508을 유지한다. 펫과 채팅 중심이 다른 상태에서는 현재 채팅 중심 유지와 펫 불변을 확인한다. 세로 반대쪽 고정·대각선 축별 조합, 화면 끝·웹 칸에 의한 기존 제한도 검사한다. 사용자 목표는 그대로이며 범위 밖 좌우 리사이즈 의미 변경을 제거하는 정정이다.

## 6판 T6 — 실제 발견된 겹침 회귀 (REQ-PP-04.AC-01~03)
- logs/manual-fixed-user-summary.json의 실제 겹침 사례를 개인값 없는 숫자 fixture로 사용한다. 현재 구현에서 비겹침 단정 실패를 확인하고 수정 뒤 통과해야 한다.
- 화면 중앙/아래/위/네 모서리, 큰 선호 채팅, 서랍·웹, 음수 원점 화면에서 개폐와 펫/헤더 이동을 검사한다. 실제 표시 채팅과 placementSprite 영역의 교차 면적은 0이어야 한다. 부동소수 비교 오차 외 교차 허용치를 두지 않는다.
- 각 입력/전환 프레임에서 펫 좌표=기존 화면 제한을 적용한 포인터 이동 목표, 크기 불변, 채팅은 화면 내·비겹침을 함께 검사한다. 드래그 종료 뒤 튐 없음. 채팅이 충돌 회피로 이동해도 펫 추종을 깨지 않는다.
- 공간이 충분하면 선호 크기 유지, 부족하면 표시 크기만 변경되고 저장 선호 크기는 불변. 최종 서랍/웹/본문 폭은 음수가 아니며 입력·접기 가능. 자동 높이/직접 경계 변경의 기존 고정 기준은 충돌 없는 경우 유지한다.
- 동일 시나리오를 수정된 격리 시험 창에서 사용자가 재확인한다. 이전 “드래그 잘된다” 관측은 acf168c 대상 부분 증거이며 겹침 수정의 합격으로 승계하지 않는다.

## 7판 사용자 배치 정정
T6: 펫이 채팅 옆에 놓이는 배치를 실패로 판정한다. 펫은 채팅 상단에 걸치거나 채팅 아래에 있어야 하며 펫 중심은 채팅 가로 범위 안에 있어야 한다. 공간 부족 시 채팅 높이만 줄이고 선호 높이와 펫 좌표는 유지한다. 펼친 채팅 상단 20pt 헤더에만 걸침을 허용하고, 나머지 본문은 펫 영역과 교차하지 않는다. 접힌 말풍선과 채팅 위 배치는 기존 비중첩을 유지한다. 실제 view 좌표로 개폐·펫/헤더 드래그·애니메이션·서랍/웹 개폐마다 검사한다. 기존 6판의 좌우 후보 및 전체 사각형 무교차 조건은 이 조항으로 대체한다.
