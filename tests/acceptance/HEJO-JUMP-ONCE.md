# HEJO-JUMP-ONCE 수락 시험

- 5판(spec 5판과 짝, 검증 3회차 AT-JO-08·18 입력 보완) · 상태: 명세 확정 / 코드 작성(`app/Tests/HistoryAutoloadFixture.py`·`HistoryAutoloadHarness.swift`·`HistoryJumpInputHarness.swift`·`HistoryJumpStatusHarness.swift`, 기대값 소유는 기획설계) / 실행: 검증 담당 직접 실행 36개 통과(`708a6da`) / 독립 검토: 검증 5회차 완료
- 가짜 방·가짜 글만 쓴다. 증거 수준: 공통 5절 2(앱 시험 하네스와 가짜 서버). 실제 설치 앱 확인은 릴리스 작업.
- 관측(제품 내부 값을 기대값으로 쓰지 않는다)
  - 대화 목록 스크롤 원점과 대상 글의 화면 좌표 틀을 1/60초마다 잰다(시험이 시계를 민다).
  - 카드창 카드와 대화 목록 글의 창 좌표 틀.
  - 가짜 서버가 받은 요청 기록(종류, 대상 스레드, 글 id, 시각)과 응답 지연 조절.
- 독립 계산: 목표 위치 = 대상 틀의 가운데 − 보이는 높이/2 를 0~(문서 높이 − 보이는 높이)로 자른 값. 시험이 관측한 틀로 직접 계산한다.
- **가운데 대상(4판, 5판 보완):** 한 번 이동을 판정하는 시험(AT-JO-01·03·04·05·08·09·12)의 대상은 목표 위치가 경계로 잘리지 않아야 한다. 대상이 글이면 스레드 카드 가운데로 잰 목표와 대상 글 가운데로 잰 목표가 모두 0보다 300pt 이상 크고 최대값보다 300pt 이상 작으며, 두 목표가 서로 50pt 이상 다른 글을 고른다. 대상이 스레드 카드(글 id 없는 입구 E2 작업·E3)이면 카드 목표만 같은 경계 조건을 지킨다. 목록 처음·끝(경계로 잘리는 대상)은 AT-JO-01b로 따로 본다.
- **표본 시작(4판):** 원점 표본은 누름 이벤트를 처리하기 직전 원점을 첫 표본으로 둔다. 누름 전에 진행 중이던 갱신은 응답을 다 받은 뒤 누른다(진행 중 갱신과 겹치는 경우는 AT-JO-14가 본다).
- 자동 이동 횟수: 원점 표본에서 0.5pt 넘게 움직이기 시작해 연속 3표본 변화 ≤0.5pt로 멈출 때까지를 1회로 센다. 리더 입력이 없는 시험에서만 센다.
- 대조 궤적: 리더 입력이 있는 시험은 같은 구성·같은 시작 원점에서 이동 요청 없이 같은 입력(과 같은 서버 응답 시각)을 재생한 실행을 따로 돌려 원점 궤적을 얻고, 본 실행과 같은 시각끼리 뺀다. 본 실행의 시작 원점은 입력 직전 원점으로 맞춘다.
- 판정 용어(되튐, 정착, 자동 이동, 대조 궤적, 이동 시간 상한 0.30초, 허용 0.5pt·1pt)는 spec 4절.
- **기준본 실행:** 시험을 제품 수정 전에 먼저 써서 착수 커밋에서 돌리고 "기준본 기대"와 맞는지 로그로 남긴다. "실패"로 적힌 시험이 기준본에서 통과하거나 "통과"로 적힌 시험이 실패하면 제품을 고치지 말고 멈추고 보고한다. "기록"은 값만 남긴다.
