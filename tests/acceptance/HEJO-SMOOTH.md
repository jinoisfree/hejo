# HEJO-SMOOTH 수락 시험 명세

원본 요구: [spec](../../docs/changes/HEJO-SMOOTH-20261124/spec.md).
상태: 명세 v5. 개발 기준에서 AT-SM-01~08·10 실행·판정 완료(5회 검토). AT-SM-05·06·09의 판정 기준은 spec v5의 조정을 따른다(아래 v5 절). 공개 기준 재실행과 AT-SM-09는 미실행. v3 이후 추가분은 계획 검증 담당의 재검토를 받지 않았다.
모든 자동 시험은 임시 HERMES_HOME·LocalStore와 가짜 명부·기록만 쓴다. 운영 기록·개인값을 fixture로 복사하지 않는다. 실제 메시지를 보내지 않는다.
기대값과 예산의 소유는 기획설계다. 구현자는 이 명세를 app/Tests의 코드로 옮기되 기대값·예산·입력 규모를 바꾸지 않는다.

## 공통 입력
- 현실 workload: 가짜 방 8개, 방당 스레드 100개, 스레드당 글 4개. 글 길이는 200자·800자·3,000자를 스레드 번호 순서로 고정 반복하고, 목록·코드·링크·체크 표시가 든 글을 섞는다. 내용은 합성 문장이다. 규모는 재현용이며 운영 자료량 추정이 아니다.
- 실제 `ConversationView`를 840×760 창에 붙인다. 시각·프레임 순서를 고정한다.
- 기존 동결 workload(`workload-frames.json`)와 그 기대값은 바꾸지 않는다. 새 workload의 결과는 별도 파일에 남긴다.
- 계수기는 `HEJO_PERF_TESTING` 조건부 컴파일의 시험 전용이다. 본문 꾸미기와 높이 계산을 글 식별자별로 센다.

## AT-SM-01 안 바뀐 글 재사용 (AC-01, 자동)
1. 방 하나를 열고 한 번 그린 뒤 계수기를 0으로 한다.
2. 같은 상태에서 다시 그린다. 기대: 꾸미기 0, 높이 계산 0.
3. 답글 3개 이상인 스레드를 선택해 펼친다. 기대: 새로 보이게 된 답글만 각 1회 이하. 다른 스레드의 글은 0.
4. 같은 스레드를 접는다. 기대: 꾸미기 0, 높이 계산 0.
5. 새 글 전환을 한다. 기대: 꾸미기 0, 높이 계산 0.
6. 다른 스레드를 선택한다. 기대: 3과 같은 규칙.
기대값 근거: 화면에 보이는 글의 내용이 바뀌지 않았다는 사실(독립 근거, 구현 방식과 무관).

## AT-SM-02 낡은 값 금지 (AC-02, 자동)
대조 기준은 같은 모델 상태에서 새로 만든 View(재사용 값이 빈 상태)다. 아래 변화 각각을 적용한 뒤, 계속 쓰던 View와 새 View의 모든 카드에서 글 문자열·글자 속성·카드 높이·글 위치를 비교한다. 전부 같아야 한다.
- 글 편집, 스트리밍 진행 3단계와 완료, 글 삭제, 보내는 중에서 보냄으로 전환.
- 긴 답글 펼치기와 접기, 체크 표시 전환, 검색 강조 켜기·끄기·검색어 변경.
- 밝은 테마와 어두운 테마 전환, 글자 크기 변경, 말풍선 모양 설정 변경(`ChatAppearance.revision` 증가).
- 창 폭 840에서 600, 다시 840.
- 발신자 색이 바뀌는 명부 변경.
- 같은 글 식별자에 다른 내용이 오는 경우, 방 A에서 B로 갔다가 A로 복귀.
- 경계: 빈 방, 글 1개 방, 보이는 범위 50개를 넘겨 이전 글 보기 뒤.
- 상한: 8개 방을 모두 순회한 뒤 재사용 값 개수가 선언된 상한 이하.
실패 뒤 상태: 불일치가 하나라도 있으면 불합격이며 어떤 변화·어떤 글에서 달랐는지 출력한다.

## AT-SM-03 답변 수신 (AC-03, 자동)
1. 한 스레드의 글 하나에 스트리밍 편집 프레임을 4개 순서대로 넣는다(마지막은 완료).
2. 프레임마다, 그리고 그 사이 표시 타이머로 생기는 다시 그리기마다 계수한다. 기대: 꾸미기·높이 계산은 흘러나오는 글에서만 발생. 다른 글 0.
3. 표시된 글자 단계의 순서와 완료 뒤 최종 글이 기준 빌드의 관측과 같다.
4. 따라가기: 맨 아래를 보던 화면에서 시작한다. 목록의 시계를 주입하고 따라가기 단계를 시험이 직접 진행시킨다(기존 `app/Tests/ScrollTests.swift` 방식). 같은 프레임·같은 시각 순서에서 단계별 스크롤 위치가 기준 관측과 1pt 미만 차이여야 한다. 따라가기가 끝난 뒤(완료 프레임 이후 정착 시점) 바닥과의 거리가 1pt 미만이어야 한다. 중간 단계에서 바닥과 정확히 일치할 것을 요구하지 않는다. 기존 동작이 단계적으로 따라가기 때문이다.
기준 관측은 제품 수정 전 TASK-01에서 같은 입력으로 동결한다. 수정 구현으로 다시 만들지 않는다.

## AT-SM-04 창 전환 (AC-04, 자동)
실제 `PetController`와 대화 View를 연결한다.
- 정상: 접힌 상태에서 화면 밖 위쪽에 있는 스레드의 알림을 연다. 기대: (가) 전환 시작 전 전체 다시 그리기 1회 이하, (나) 스냅샷 시점에 그 스레드 카드가 보이는 영역 안의 최종 위치, (다) 전환 시작부터 종료까지 이 동작이 일으킨 전체 다시 그리기 0회와 스크롤 애니메이션 시작 0회, (라) 종료 뒤 위치가 기준 동작의 최종 위치와 1pt 미만 차이로 같다.
- 경계: 다른 방의 스레드, 홈의 스레드, 맨 아래 스레드, 보이는 범위 밖(50개 이전) 스레드.
- 경계: 전환 도중 새 글이 수신되면 그 수신은 기존대로 화면에 반영된다(다 조건의 예외로 계수에서 구분).
- 유지: 이미 열린 창에서 같은 이동을 하면 기존 스크롤 애니메이션이 시작된다.
- 유지: 애니메이션 줄이기 설정에서는 기존대로 즉시 배치된다.
1pt 미만은 기존 스크롤 시험(`app/Tests/ScrollTests.swift`)이 쓰는 위치 허용 오차다.

## AT-SM-05 동작 지연 예산 (AC-05, 자동 계측)
현실 workload에서 준비 실행 1회를 버리고 5회 측정한다. 각 동작의 호출 직전부터 동기 처리가 끝나고 `layoutSubtreeIfNeeded`가 반환할 때까지의 주 스레드 시간을 잰다.

| 동작 | 합격선 |
|---|---|
| 스레드 선택(펼침 포함) | 5회 중앙값 ≤0.050초, 최대 ≤0.100초 |
| 답글 더미 펼치기·접기 | 같음 |
| 새 글 전환 | 같음 |
| 방 전환(이미 한 번 본 방으로) | 같음 |
| 방 전환(처음 보는 방으로) | 수정 후 5회 중앙값 ≤ 수정 전 기준 5회의 최대값 |
| 스트리밍 편집 프레임 1개 수신에서 화면 반영까지 | 5회 중앙값 ≤0.050초, 최대 ≤0.100초 |
| 알림 이동 준비(전환 전 대화 갱신 묶음) | 5회 중앙값 ≤0.050초, 최대 ≤0.100초 |

- 제품 수정 전 같은 머신·같은 최적화 옵션으로 기준값을 먼저 기록한다. 결과 파일에 workload 해시, 원시 5회, 중앙값, 최대, 실행 커밋을 남긴다.
- 음수·누락 표본은 무효다. 미달 시 값을 완화하거나 입력을 줄이지 않고 병목을 보고한다.
- 처음 보는 방 전환에 절대 예산을 두지 않는 이유: 그 방의 글은 실제로 처음 꾸며야 하며 이 작업의 범위(안 바뀐 글 재사용)로 줄일 수 없다. spec AC-05가 이 구분과 악화 금지 기준을 정한다. 비교 상한을 기준의 최대값으로 둔 것은 임의 비율 없이 같은 조건의 측정 흔들림만 허용하기 위해서다.
- "이미 한 번 본 방"은 같은 실행에서 한 번 열어 그린 뒤 다른 방으로 갔다가 돌아오는 경우다. "처음 보는 방"은 측정 실행마다 새 View에서 한 번도 열지 않은 방이다.
- 이 계측은 화면에 표시하지 않은 AppKit 측정이다. 설치 앱 체감의 측정이 아니다.

## AT-SM-06 전환 프레임 간격 (AC-06, 자동 계측)
애니메이션을 켠 상태로 실제 run loop에서 접힌 창을 여는 알림 클릭 전환을 5회 실행한다. 준비 실행 1회는 버린다. 전환 시작 시각(전환 타이머 등록 시점), 전환 단계가 불린 모든 시각, 전환 종료 시각을 기록한다.

각 실행의 합격 조건(모두 충족):
- 전환 시작부터 첫 단계까지의 간격 ≤0.050초.
- 연속한 단계 사이 간격이 모두 ≤0.050초.
- 전환 종료가 기록되고, 시작부터 종료까지 ≤0.350초.
- 단계 수 6 이상.

불합격 처리: 위 조건 미충족, 시작 뒤 1초 안에 종료가 기록되지 않음, 시각 기록 누락, 간격을 계산할 수 없는 표본. 이런 표본을 무효로 버리거나 다시 실행해 대체하지 않는다. 5회 모두 합격해야 한다.

근거: 전환 길이는 0.30초다. 전환 진행률은 시작 뒤 경과 시간으로 계산되므로, 첫 단계가 늦으면 한 번에 끝나 버리고 그것이 가장 나쁜 끊김이다. 그래서 시작부터 첫 단계까지를 간격에 포함한다. 간격 상한 0.050초로 0.30초를 채우는 최소 단계 수가 6이고, 마지막 간격을 더한 종료 상한이 0.350초다.

기준값을 수정 전에 같은 방법으로 기록한다. 기준이 이미 불합격이면 그 값을 그대로 남긴다.

## AT-SM-07 스크롤 (AC-07, 자동 계측)
현실 workload의 방에서 맨 아래부터 맨 위까지 60pt씩 스크롤하며 걸음마다 표시 갱신까지의 주 스레드 시간을 잰다. 합격선: 수정 후 5회 전체 걸음의 중앙값 ≤0.0167초, 최대 ≤0.050초. 기준값(중앙값 0.00002초, 최대 0.0102초)이 이미 합격선 안이므로 스크롤 전용 수정은 없다. 이 계측은 창을 표시하지 않아 픽셀 그리기 비용을 담지 못한다. 체감은 AT-SM-09로 판단한다.

## AT-SM-08 기존 의미 보존 (AC-08, 자동)
`bash scripts/test.sh` 전체가 종료 0이다. 성능 의미 동결(58단계), 입력 계약 시험, 스크롤 시험, 세 번 누르기 시험이 기대값 변경 없이 통과한다. 기준에서 이미 실패하던 항목이 있으면 수정 전 실행 기록으로 구분해 보고한다.

## AT-SM-09 실제 창 관측 (AC-09, 수동)
임시 홈과 현실 workload를 연결한 실제 제품 View를 보이는 창으로 띄운다. 소켓·운영 연결·전송 없음. 스레드 선택, 새 글 쓰기, 알림 이동, 답변 수신 재생, 방 전환, 스크롤을 각 10회 반복해 멈춤·튐·늦게 따라오는 스크롤 유무를 기록한다. 구현자가 관측할 수 없는 항목은 실행 방법을 준비해 보고하고, 사용자 확인 요청은 기획설계가 한다.

## AT-SM-10 글에서 뽑는 값 재사용 (AC-10, 자동)
대조 기준은 같은 프레임 순서를 처음부터 새로 넣어 만든 모델과 화면(재사용 값이 빈 상태)이다. 시각은 주입한다.

1. 계수: 한 번 그린 뒤 같은 상태에서 다시 그린다. 기대: 스레드 판정 계산 0회, 달력 버튼 계산 0회. 한 스레드에 글 하나를 추가하면 그 스레드의 판정만 1회, 그 글의 달력 계산만 1회.
2. 대조: 아래 변화를 하나씩 순서대로 적용하고, 변화마다 계속 쓰던 쪽과 새로 만든 쪽을 비교한다. 비교 대상은 사이드바 행의 순서·배지·종·질문 표시, 방별 알림의 식별자·순서·개수, 스레드별 판정 결과 전체, 글별 달력 버튼, 서랍의 처리할 일 수다. 전부 같아야 한다.
   - 글 추가, 편집(스트리밍 중간과 완료), 삭제.
   - 답글 상태 변화, 버튼이 있는 글과 버튼 누름, 체크 목록, 승인 요청 문구가 든 글.
   - 확인 표시 전환, 읽음, 음소거, 방 보관, 명부 변경.
   - 회원 상태(v4): 전송 대기 중인 로컬 변경, 전송 확인, 원격 상태 수신, 계정 전환. 각 변화 뒤 상태 조회 결과(값·읽음 위치·확인 여부)가 새로 만든 쪽과 같아야 한다.
   - 달력 일정 추가·삭제·변경.
   - 시각 경과: 알림 발생 전, 24시간 직전, 정각, 직후.
   - 다시 연결 뒤 기록 다시 받기, 중복 프레임.
   - 경계: 빈 방, 삭제로 비게 된 스레드, 같은 글 식별자에 다른 내용.
3. 상한: 8개 방을 순회하고 스레드 100개를 삭제한 뒤 재사용 값 개수가 선언된 상한 이하이고 삭제된 스레드의 항목이 남지 않는다.
4. 구현자가 같은 원칙으로 추가한 재사용 값은 모두 이 대조의 비교 대상에 넣는다.

기대값 근거: 새로 만든 쪽은 재사용 없이 계산한 결과다(독립 기준). 기존 의미 동결 58단계(AT-SM-08)도 함께 통과해야 한다. 불일치가 하나라도 있으면 불합격이며 어떤 변화·어떤 방·어떤 스레드에서 달랐는지 출력한다.

## v5 조정 (2026-11-24, 사용자 결정)
- AT-SM-05: "방 전환(이미 한 번 본 방으로)"의 합격선을 "수정 후 5회 중앙값 ≤ 수정 전 기준 5회의 최대값"으로 바꾼다. 다른 행은 그대로다.
- AT-SM-06: 각 실행의 프레임 간격 조건은 그대로 기록한다. 합격 판정은 "5회 모두 전환 전 다시 그리기 1회 이하·전환 중 다시 그리기 0·스크롤 시작 0·즉시 배치"와 "프레임 간격 조건을 채운 실행 수가 수정 전 기준의 실행 수 이상"이다. 표본을 버리거나 대체하지 않는 규칙은 유지한다.

- 공개 기준 재검증에서는 "수정 전 기준"을 공개 tip에서 같은 workload로 잰 값으로 한다.
