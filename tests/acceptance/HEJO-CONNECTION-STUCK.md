# 연결 단계 멈춤 수락 시험

원본: [spec](../../docs/changes/f1c5ef47-8a5d-4479-871d-c48580bfdfdb/spec.md). 명세 작성 / 코드 미작성 / 미실행 / 계획 검증 2회차 v2 APPROVED 후 권고 반영 v3 재검증 대기.
가짜 직원 alpha, 임시 HERMES_HOME, 가짜 send 응답만 사용한다. 실제 서버·메시지·재시작은 사용하지 않는다.

|---|---|---|---|
| AT-CS-01 | AC-01 | app_connect에 waiting + next.kind=gateway_restart + 안내 반환. 별도로 일반 입력 단계 반환 | 재시작 단계 버튼은 다시 시작, 저장 안내 없음. 일반 입력의 필수값 검증·저장 버튼 유지 |
| AT-CS-02 | AC-02 | 실제 AppKit 입력창에서 재시작 누름, 인증 성공 대역, 실제 확인창 취소. 일반 창/떠 있는 대화창 둘 다 | 확인창과 레벨 25 대화창을 의도적으로 겹쳐 배치한다. 확인 버튼 영역이 가시 화면 안에 있고 다른 앱 내 높은 레벨 창에 가려지지 않음(창 순서·프레임 교집합·가짜 자료 스크린샷 기록). 확인창이 키 입력 대상이며 실제 마우스 클릭 이벤트로 취소 버튼을 눌러 완료됨. endSheet 직접 호출·performClick만으로 대체 금지. 취소 후 busy 해제·입력창 조작 가능·재개 프레임 0. 일반 레벨에서도 동일 확인 |
| AT-CS-03a | AC-03 | committed 뒤 수락, 제어 가능한 send를 보류해 응답 지연 상태 관찰 후 pending(job)→done 반환 | 재개 1회·values는 resume만. 실제 대기 중 진행 표시·닫기 가능, job을 받은 뒤 해당 job 조회만 수행, 성공 결과 표시 |
| AT-CS-03b | AC-03 | 입력창의 committed 후 resume 경로와 입력창 없는 게이트웨이 줄의 직접 gateway_restart 경로 각각에서 수락 뒤 send 무응답, 시험용 짧은 제한 시간을 주입해 실제 요청 timeout 처리 실행. 두 경로 각각 전송 후 연결 끊김도 실행 | job 미확보 시 job_status(latest) 조회로 전환. 재시작 재시도 안내 없음·각 시나리오의 재시작 부작용 요청 합계 1회(직접 실행은 gateway_restart 1회, resume 경로는 재개 1회). 직접 실행에 resume·저장값을 추가하지 않음. 입력창이 없으면 연결창 notice에서 진행·결과 확인 가능. 조회 연결 회복 뒤 pending→done 표시. latest 결과는 최근 결과로 표현하며 현재 요청 성공으로 단정하지 않음 |
| AT-CS-03c | AC-03 | 조회 응답을 failed/refused/partial/unknown/timeout/UNKNOWN_JOB 각각 반환, 별도로 조회 실패 지속·조회 기한 종료 | 해당 결과 또는 확인 불가 표시·닫기 가능·읽기 전용 재확인만 허용. 새 재시작 프레임 없음. 동의 만료·다시 연결 안내 없음. 즉시 BUSY 거절은 미실행 안내와 입력 조작 복구 |
| AT-CS-03d | AC-03·04 | 원래 응답을 보류→timeout→latest 조회 중 창 닫기·선택 변경·재열기·늦은 원래 pending 응답 전달 | 요청 시점 대상/알려진 job 유지, 부작용 재전송 없음, 닫은 입력창 재표시 없음, 복구 조회 경로 중복 없음. 재열기 결과 표시가 최초 추적과 동일 계약을 따름 |
| AT-CS-04 | AC-04 | 입력·확인·응답 대기 각각에서 허용되는 닫기 동작, 이후 다시 열기; 지연 응답 전달 | 숨은 확인창·미해결 확인 대기 없음. 메뉴·연결창 반응, 늦은 응답이 닫은 입력창을 다시 열지 않음. 이미 보낸 작업은 취소됐다고 표시하지 않음 |

구현 회귀 시험 위치: app/Tests/ConnectionsTests.swift. 실행 증거·원인 기록은 작업 impl-report.md, 검토는 verdict.md. 기존 HC·CM·FF 연결 시험을 함께 확인한다.

무응답·지연 대역은 인증/확인/전송 단계별로 진입·해제 시점을 기록한다. 제품 제한 시간·서버 코드는 바꾸지 않는다. 가짜 응답 통합은 증거 수준 2이며 실제 운영 원인 확정으로 보고하지 않는다. AppKit 가시성·클릭 검증은 실제 GUI 세션에서 수행하고 조작할 수 없으면 미실행으로 보고한다.

## 기존 회귀 기대값 정합성 — V-CS-02
AT-HC-26 구현 시험의 내부 확인 중 부모 normal 단언은 AT-CS-02와 같은 가시성 기준으로 교체한다. preferredLevel=26 조건에서는 선호 높이 유지·확인 sheet 가시성·키 대상을 확인하고, 기존 sheet 존재·NSApp.modalWindow==nil·취소 continuation 완료는 유지한다. 시스템 재인증 중 normal 전환과 복원은 바꾸지 않는다. 원래 HEJO-CONNECTIONS 수락 명세의 sheet·앱 모달 금지 요구는 그대로이며 구현 시험의 잘못된 높이 기대값만 정정한다.
